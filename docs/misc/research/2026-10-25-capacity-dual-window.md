# 리서치 — "5시간 남은 양"과 "일주일 남은 양"을 한 화면에 함께 보여 주는 방법

**결론 한 줄:** 업계 표준은 같은 눈금 위에 막대 두 줄을 겹치지 않고 쌓는 것이다(위 = 5시간, 아래 = 일주일). 각 줄에는 "% + 리셋 시각"이 붙는다. 우리는 여기에 계정 단위 개수를 더하고 Codex는 일주일 한 줄만 둔다.

**구조**
1. 선행 사례 6개: 각 제품이 두 창(5시간·일주일)을 어떻게 그리는가
2. 후보 표현 5가지와 판정
3. 우리 화면에 가져온 것과 다르게 한 것 (요구 1a·1b·2 대응표)
4. 출처

읽기 안내: 결정만 보려면 §3만 읽으면 된다.

## 1. 선행 사례

1. **claude.ai 설정 → 사용량 (Anthropic 공식)**
   - 막대가 세로로 두 개 이상 쌓인다: "Current session"(5시간)과 "Weekly limits"(전체 모델, Fable 별도).
   - 각 막대에는 사용 %와 리셋까지 남은 시간이 붙는다.
   - 두 한도는 따로 걸린다. 세션에 여유가 있어도 주간 한도가 차면 못 쓴다.
2. **Claude Code `/usage`·`/status`, VS Code "Account & usage" 대화상자**: 위와 같다. 세션 막대와 주간 막대가 있고, 각 막대에 리셋까지 남은 시간이 붙는다.
3. **Codex CLI `/status` (OpenAI)**
   - 막대 두 줄: `5h limit: [████████████████████] 100% left (resets 14:51)` / `Weekly limit: [████████████░░░░░░░░] 61% left (resets 16:21 on 18 Feb)`.
   - **"남은 %"**로 표시하고, 주간에는 날짜를 붙인다.
4. **CodexBar (steipete, macOS 메뉴바)**
   - 아이콘 하나에 막대 두 개: 위 = 세션(5시간), 아래 = 주간(가는 선).
   - 펼치면 제공자별 타일에 사용량 막대와 리셋 카운트다운이 나온다.
   - 오래되었거나 오류가 난 데이터는 아이콘을 흐리게 한다.
5. **CodexBar (Gordon Beeming, Codex 전용)**
   - 메뉴바에는 두 % 중 **더 나쁜 쪽 하나**만 보인다.
   - 드롭다운에는 한도별 막대, 리셋 시각, "일정한 속도보다 빠른가"(pace) 표시가 있다.
   - 75%와 90%에서 색이 바뀐다.
6. **CodexBar-Win (Windows 트레이)**: 세션 한도, 주간 한도, 리셋 시각이 있고, 남은 정도에 따라 주황 → 호박색 → 빨강으로 바뀐다.

공통점:
- 두 창을 **같은 모양의 막대로 따로** 그린다. 위에 5시간, 아래에 일주일을 두는 순서까지 같다.
- 숫자는 %, 시간은 리셋 시각이나 카운트다운으로 보여 준다.
- 접힌(아이콘) 상태에서도 두 값을 나란히 보여 주거나, 더 나쁜 쪽 하나를 보여 준다.

차이점: 모두 **계정 1개**의 %다. 우리처럼 여러 계정을 묶은 풀을 "최대 플랜 계정 몇 개분"으로 세는 사례는 없다. 그래서 1a의 "몇 계정분"은 우리가 덧붙여야 한다.

## 2. 후보 표현과 판정

1. **막대 두 줄, 같은 눈금** (위 5시간, 아래 일주일, 각 줄에 `x / 총 계정 · %`): **채택.**
   - 선행 사례 전부와 같아서 학습 비용이 0이다.
   - 같은 단위(계정)와 같은 총량이므로 두 줄 길이를 바로 비교할 수 있다.
   - 우리 모델에서 지금 쓸 수 있는 양은 계정마다 min(5시간 남음, 일주일 남음)을 더한 값이다. 그래서 위 막대는 아래 막대보다 길 수 없다. 이 관계도 눈으로 보인다.
2. **겹친 막대** (일주일을 연하게 깔고 5시간을 진하게 겹침): 기각. 한 줄이라 작지만, 진한 부분과 연한 부분이 무엇인지 범례가 필요하다. 1차 v2에서 "알아볼 수 없다"는 판정을 받은 이유가 바로 이런 해석 비용이었다.
3. **동심원 링** (애플 워치 방식): 기각. 원호 길이 비교는 막대보다 부정확하다. 링 안에 "5.2 / 16.0 계정"을 넣을 자리도 없다.
4. **더 나쁜 쪽 하나만** (Beeming 방식): 기각. 요구 1b가 두 기준을 모두 보이라고 한다.
5. **숫자만** (`지금 5.2/16.0 33% · 주 5.7 36%`): **접힌 상태에만 채택.** 한 줄 칩으로 1a와 1b를 함께 충족한다. 폰에서는 개수를 줄이고 %만 남긴다(개수는 툴팁과 펼친 화면에 있다).

앞으로 들어올 양(요구 2):
- 선행 사례에는 "리셋 시각"만 있고 "얼마가 돌아오나"를 보여 주는 사례는 없다.
- v1 타임라인을 유지한다. 5시간 리셋은 청록 ●(라벨이 축 위), 일주일 리셋은 보라 ◆(라벨이 축 아래)로 둔다. **색과 모양과 위치 세 가지로 구분**하므로 색약이나 흑백에서도 갈린다.
- ● 색은 위 막대(5시간)와, ◆ 색은 아래 막대(일주일)와 같다.

## 3. 우리 화면에 가져온 것 — 요구 대응표

1. **1a: %와 몇 계정분을 한눈에**
   - 펼친 화면: 막대마다 `5.2 / 16.0 계정 33%`처럼 개수와 %를 한 줄에 둔다.
   - 접힌 칩: `Claude 지금 5.2/16.0 33% · 주 5.7 36%`.
2. **1b: 5시간 기준과 일주일 기준**
   - Claude: 막대 두 줄로 "5시간 · 지금 쓸 수 있음"과 "일주일 · 이번 주 남음"을 둔다.
   - **Codex: 일주일 막대 한 줄만** 둔다. 5시간 창이 없으므로 위 줄을 그리지 않는다.
   - 5시간 리셋이 와도 일주일 한도에 묶여 늘어나지 않으면, 5시간 줄 아래 문구가 "일주일 한도에 묶임 — 다음 일주일 리셋 때 +X계정"으로 바뀐다. 두 한도가 따로 걸린다는 선행 사례의 교훈을 화면에서 그대로 읽게 했다.
3. **2: 들어올 양, 5시간과 일주일 구분**: 타임라인 하나에 ●(5시간)과 ◆(일주일)을 둔다. 지금부터 24시간이 폭의 55%, 그다음 7일까지다.
4. **정직성** (선행 사례가 "오래된 데이터는 흐리게"를 쓰는 것과 같은 목적):
   - 흐린 한 줄로 `16/17 반영 · 차단 6 · 제외 1(보류) · 측정 4시간 전`을 보여 준다.
   - 하루 넘게 지난 측정은 경고색 `⚠ 측정 N일 전`으로 표시한다.
5. **Pace(속도) 표시는 넣지 않음**
   - 개인 한 계정에는 유용하지만, 풀 단위에서는 "누가 얼마나 빨리 쓰나"가 계정마다 다르다.
   - 넣으면 요소가 늘어 "알아볼 수 없다"로 되돌아간다. 다음 단계 후보로만 남긴다.
