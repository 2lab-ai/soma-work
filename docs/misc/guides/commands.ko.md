# soma-work 명령어

## 명령어

목적이 겹치지 않는 4개의 prefix family:

| Prefix | 범위 | 지속성 | 예시 |
|--------|------|--------|------|
| `/z <topic> …` | 기본 명령어 surface (필요 시 Block Kit UI) | 유저 전역 | `/z persona set linus` |
| `%<sub> …` | **현재 세션 전용** — 저장 없이 오버라이드 | 휘발성 (`new`/`renew` 시 초기화) | `%model opus` |
| `$<skill>` / `$<plugin>:<skill>` | **강제 스킬 발동** (`SKILL.md` 로드, `compact` 이상에서 RPG 배너 출력 — `minimal`에서는 게시하지 않음; 세션에 대화가 있으면 대시보드 작업 로그에 기록) | 메시지 단위 | `$z`, `$stv:new-task` |
| naked text | bare 명령 또는 채팅 / 워크플로우 디스패치 | n/a | `sessions`, `new`, `fix PR 123` |

**찾을 수 없는 스킬**: 메시지가 스킬 참조(와 그 `--플래그`)뿐이면 `❌ 스킬을 찾을 수 없습니다`로 답하고 멈춘다. 그보다 많은 말이 들어 있으면(`$plugin:skill`을 인용한 답장, 이 호스트에 없는 스킬 이야기) `⚠️` 안내만 남기고 메시지는 그대로 모델에 전달한다.

**대시보드 입력창 메뉴 (2026-11-04)**: 대시보드의 두 입력창(**새 작업**, 열린 세션의 입력창)에서 맨 앞에 `/`를 치면 그 자리에서 쓸 수 있는 명령어가 모두 나온다. 행마다 무엇을 하는지와 대표 예시(회색)가 붙는다. 새 작업에는 기존 세션 없이 쓸 수 있는 명령이 모두 나온다(`/compact`, `!`처럼 스레드의 세션에 작용하는 명령만 빠진다). 답만 하는 명령은 행에 그렇다고 표시되고, 답은 Slack 스레드에 올라가며 대시보드가 링크와 함께 알려 준다. 새 작업의 첫 메시지가 이런 명령이면 답만 하는 실행으로 처리된다. 새 스레드에서 답하고 작업 카드는 만들지 않는다. 어드민에게는 어드민 명령도 보인다. `%`는 세션 설정을, 단어 맨 앞의 `$`는 내가 쓸 수 있는 스킬을 모두 보여 준다. 스킬은 이름이 겹치지 않는 토큰(`$user:…` · `$local:…` · `$<plugin>:…`)으로 들어간다. 이어서 치면 목록이 좁혀지고, ↑↓로 고르고 Enter나 Tab으로 넣고 Esc로 닫는다. 목록은 `GET /api/dashboard/composer-menus`([`src/conversation/composer-menus.ts`](../../../src/conversation/composer-menus.ts))가 준다. 그 테스트가 명령 행의 예시를 실제 `CommandRouter`에 모두 통과시키므로, 봇이 채팅으로 받을 명령은 목록에 들어갈 수 없다. 메뉴 자체는 `@2lab.ai/ui` `<ui-composer>`의 `data.triggers`(0.27.0)다.

주요 `/z` 명령: `help` · `cwd` · `mcp` · `bypass` · `lang`(표시 언어 ko·en, 유저 단위·기본 한국어) · `epictasks`(에픽 만들기 허용 — 새 작업 창의 **에픽** 스위치, 유저 단위·기본 꺼짐·실험. 에픽은 계획 트리를 쓰고 자식마다 같은 채널에 스레드를 하나씩 만드는 Slack 스레드이고, 일하는 자식에게 보낸 지시는 그 자식의 대기열에서 기다린다. 스위치를 켜도 디스패처가 작업량을 태스크 하나 이하(약 10분)로 보면 에픽 대신 일반 작업으로 만들고 스레드에 그 이유를 남긴다. 판정이 없거나 실패하면 에픽으로 만든다) · `persona` · `model` · `verbosity` · `session` · `new`/`renew` · `close` · `restore` · `context`/`compact` · `link` · `onboarding` · `admin` · `cct` · `auth` · `marketplace` · `plugin` · `skill` · `report`

문맥 되돌리기: `rollback`(또는 `롤백`)은 내 입력 목록을 보여주고, `rollback <번호>`는 그 입력 *직전*으로 모델의 대화 문맥을 되돌립니다(파일은 그대로, 다음 턴부터 적용). `rollback goal`은 같은 이유로 멈춘 goal이 처음 실패한 지점으로 되돌립니다(그 사이 한 일이 없을 때만). `rollback cancel`로 취소, `rollback redo`(`롤백 다시`)는 다음 지시를 보내기 전까지 마지막 되돌리기를 한 단계씩 취소합니다. 대시보드에서는 디테일 카드의 **⏪ 되돌리기 모드**를 켜면 채팅의 지시마다, 작업 로그의 지시·응답·툴 카드마다 되돌리기 버튼이 붙습니다. 지시 전으로 되돌리면 그 지시가 입력창에 다시 들어갑니다(**↪︎ Redo**로 취소). 스펙: [`docs/current/spec/context-rollback.md`](../../../docs/current/spec/context-rollback.md)

- 출력 수준(`/z verbosity`, 세션 한정 `%verbosity`): `minimal` · `compact` · `detail` · `verbose`. 기본값은 `minimal`이다 — 스레드에는 task list(메인 에이전트의 것 — 서브에이전트의 목록은 대시보드의 그 서브에이전트 항목에 있다), 질문/승인, 최종 답변, 오류만 남고, 모델의 실시간 작업 설명·도구 호출·압축 공지·스킬 발동 배너(`$skill`·autoskill 포함)는 대시보드 작업 로그로 간다.

- Fable 5.2(`claude-fable-5-2`, 구독 엔드포인트가 Claude Code 2.1.284를 `claude_code_version_too_old`로 거부하며 Anthropic은 2.1.321 이상을 요구)·Fable 5.1·Opus 5.5(`claude-opus-5-5`, Claude Code 2.1.280 이상 필요) 지원을 위해 SDK를 `0.3.321`(네이티브 Claude Code `2.1.321`)로 고정한다. 스트리밍 턴은 `CLAUDE_CODE_ENABLE_TASKS=false`와 `MCP_CONNECTION_NONBLOCKING=0`을 강제하여 기존 Slack TodoWrite 스냅샷 처리와 첫 턴 MCP 초기화를 유지한다. 이 호환성 설정은 stream-options builder가 관리하며 운영자 설정으로 덮어쓰지 않는다.
- 모델 별칭 `fable`·`fable[1m]`·`fable-5-2`·`fable-5-2[1m]`은 최신 Fable인 `claude-fable-5-2[1m]`을 선택한다(2026-11-10부터). 1M 컨텍스트와 750k 자동 압축 기본값을 유지하며, 버전을 지정한 `fable-5-1`·`fable-5-1[1m]`은 `claude-fable-5-1[1m]`을, `fable-5`는 기존 `claude-fable-5[1m]`을 그대로 선택한다.
- 모델 별칭 `terra`·`terra[1m]`은 `gpt-6.1-terra[1m]`(1M 컨텍스트, 600k 자동 압축 기본값)을 선택한다(2026-11-10부터). bare 리터럴 `gpt-6.1-terra`는 500k 컨텍스트에 450k, `gpt-5.6-terra`는 리터럴 id로 계속 선택할 수 있다.
- 모델 별칭 `opus`·`opus[1m]`·`opus-5-5`는 `claude-opus-5-5[1m]`(1M 컨텍스트, 750k 자동 압축 기본값)을 선택한다. 버전을 지정한 `opus-5`/`opus-5[1m]`은 기존 Opus 5 id를 그대로 선택한다.
- naked `cron`/`schedule`(크론/스케줄): 잡별 모델/출력 대상 드롭다운 + 삭제 버튼이 달린 인터랙티브 카드로 목록·수정. 텍스트 명령도 지원 — `cron model <name> <default|opus|fable|fast|모델>` (default = 만든 사람의 현재 모델, opus/fable = 실행 시점의 최신 opus/fable, fast = 실행 시점에 만든 사람 모델의 sonnet급 — Claude·Codex·Grok 모델이면 각각 `sonnet`·`terra`·`grok`(medium effort)) · `cron target <name> <channel|dm|thread>` · `cron delete <name>`; admin은 전체 유저 잡을 owner와 함께 보고 `<@owner>` 후행 인자 또는 카드에서 직접 타인 잡을 수정. 커맨드로 라우팅되므로 autogoal이 삼키지 않음.
- **대시보드의 크론 실행**: 크론 발동이 만든 세션은 `Direct (skipDispatch)`가 아니라 잡 이름으로 시작한다. 이 제목은 임시 제목이라 첫 명확한 제목(턴 요약·연결된 이슈/PR)이 오면 교체되고, 카드는 새 제목을 페이드인한다. 카드 머리 왼쪽에 **CRON** 뱃지가 붙고, 보드 칸 위의 **CRON 레인**에 들어간다 — 잡마다 타일 1개(스케줄 문장, cron은 UTC 기준·다음 실행·최근 실행 막대 ✓성공 ✗실패 ●실행 중 ▲응답 필요 ◌세션 없음)와 그 잡의 최신 실행 카드. **지난 실행**을 누르면 잡의 보관된 실행(잡당 최근 20회)을 세션·작업 로그·대화 기록·Slack 스레드와 연결해 보여 주는 서랍이 열린다(`GET /api/dashboard/cron`). 기존 세션에 주입된 크론 실행은 그 세션을 레인으로 옮기지 않는다. default 모드 실행은 잡의 세션에서 돈다 — 잡에 스레드가 있으면 그 스레드의 세션, 없으면 그 잡의 이전 실행이 연 세션이다. 그 세션이 깨어 있으면 거기서 돌고(일하는 중이면 끝날 때까지 기다린다), 없으면 새 스레드를 연다. 같은 채널에 있는 오너의 다른 세션에는 절대 들어가지 않고, 기다린 실행은 기다리던 그 세션에서 돈다. 출력 `thread`(와 `dm`)는 프롬프트 글만 올린다 — 아무것도 그 글을 실행하지 않고 세션도 열리지 않는다(지금 실행 전후로 서랍이 그렇게 말하고, 실행 기록 줄은 글이 올라간 스레드로 이어진다). 스레드 답글 잡의 출력을 `channel`로 바꾸면 스레드가 그대로 남아, 그 뒤로 프롬프트가 그 스레드 세션에서 실행된다(대시보드 편집, `cron target`, 크론 카드, `cron_update` 모두 같다. `cron_update`의 `clear_threadTs`는 스레드를 지운다).
- **대시보드 LLM 가용량 (2026-10-25)**: 통계 줄과 Agent inbox 사이에 섹션이 있다(`GET /api/dashboard/capacity`, llmux 조회 30초 캐시·페이지 60초 재조회). 섹션은 모든 창에서 접힌 채로 시작하고, 펼치기 선택은 기기에 저장된다. 미니멀과 어드밴스드 두 모드 모두에 보인다(2026-11-10). 접힌 칩은 구독 프로바이더마다 주간 창을 합계 대비 계정과 %로 보여 준다(`Claude 주 5.6/16.0 35%`). 840px 미만에서는 칩 줄이 감긴다. 가장 오래된 측정이 하루를 넘었거나 계정의 80% 미만만 반영된 칩에는 경고가 붙는다(`Codex 주 2.37/2.4 99% ⚠ 5일 전 · 3/5 반영`). 2026-11부터 5시간 창을 주는 프로바이더가 없어 막대는 하나다. [`docs/misc/research/2026-10-25-capacity-dual-window.md`](../../../docs/misc/research/2026-10-25-capacity-dual-window.md)의 5시간 막대는 없어졌고, 예전 llmux가 보내는 `five_hour`는 읽지 않는다. 펼치면 프로바이더마다 단순한 카드 하나가 나온다(Claude·Codex, API 키 풀은 플랜 단위가 없어 제외). 카드 구성은 다음과 같다. **막대 한 줄**: `일주일 · 이번 주 남음`을 `x / 합계 계정 · %`로 보여 주고, "다음 +1.0계정 · 1시간 23분 후" 한 줄을 붙인다(얼마나·언제만 쓴다. 계정 이름은 툴팁에 있다). 계정 카드는 지금(주간 잔여, 차단 중이면 0)과 주를 보여 준다. 폰에서는 막대가 카드 폭 전체를 쓴다. "계정"은 티어 가중치(x20 = 1, x5 = ¼, $500 = 1, $200 = 0.4)에 잔여를 곱한 정규화 추정이고 토큰 수가 아니다. %는 실제 비율로 계산해 가득일 때만 100%로 표시하고, 합계로 반올림되는 수는 소수 둘째 자리까지 보인다(`2.37 / 2.4 · 99%`). **흐린 공개 줄 한 줄**: 0이 아닌 것만 보여 준다(`16/17 반영(차단 6 포함) · 제외 1(보류) · 측정 4시간 전`). **타임라인 하나**: 지금→24h(폭 55%)→7d 축에서 ◆는 일주일 막대가 늘어나는 것이고 막대와 같은 색이다. 겹치는 라벨은 하나로 합친다. 계정별 리셋을 시간순으로 재생해 계산한다(차단 해제 먼저, 그다음 주간 리셋). llmux 0.2.26부터는 계정별 플랜을 llmux가 직접 알려 준다(Claude `rate_limit_tier` = `default_claude_max_20x` 등, Codex `plan_type` = `pro`($200)·`promax`($500)). 그래서 설정 없이 티어가 잡힌다. 우선순위는 `SOMA_LLMUX_ACCOUNT_TIERS` → llmux가 알려 준 플랜 → 기본값이다. `SOMA_LLMUX_ACCOUNT_TIERS`(`group:name=tier`, 예: `claude:ai7=x20,claude:ai12=x5`)는 기본값(Codex `ai1`·`ai2` = Pro $200, `ai5`·`ai6` = Pro $500) 위에 덮인다. llmux의 `max`만으로 x5/x20을 추측하지 않는다. 매핑이 없는 **Claude** 계정은 Max x20으로 세고 그렇다고 밝힌다(카드 `티어 미지정 15(x20 가정)`, 접힌 칩 `⚠ x20 가정 15`). 그래서 매핑이 없는 호스트도 풀을 보여 준다(2026-10-26). 매핑이 없는 Codex 계정은 합계에서 뺀다(`제외 1(티어 미지정)`). 스펙: [`.prd/12-cron-lane-and-llm-capacity-spec.md`](../../../.prd/12-cron-lane-and-llm-capacity-spec.md)
- **배포 후 QA**: 호스트에 `post-deploy` 스킬을 제공하는 환경 플러그인(`acme-env` 같은)을 설치하면, deploy 워크플로우가 7단계로 배포가 확인된 repo마다 배포 세션 안에서 배포 후 QA를 돈다(설정: [docs/runbook/add-new-deploy.md](../../../docs/runbook/add-new-deploy.md) §8.5). `qa=max`는 실제 QA가 보는 범위(커버리지 매트릭스)로 이슈마다 케이스를 먼저 계획하고, 케이스마다 사전 조건(계정·테스트 데이터·쓰기 권한·설정)을 확인한다. 하나라도 부족하면 어떤 케이스도 돌리기 전에 미충족 표를 올리고 요청자에게 한 번 묻는다. 선택지는 제공하기, 없이 진행하기(그 케이스는 blocked로 남고 PASS가 될 수 없음), 이슈 건너뛰기다. 답이 올 때까지 실행은 `deployed, QA incomplete: waiting for precondition confirmation`으로 끝난다. `$autoz`로 요청한 배포는 자동화가 보내므로 답할 사람이 없다. 그래서 워크플로우가 `waive=autoz`를 넘기고, 그 요청을 "없이 진행" 답으로 보아 같은 실행 안에서 열린 사전 조건을 모두 waived로 기록하고 묻지 않고 QA를 계속한다. waived 케이스는 blocked로 남고 PASS가 될 수 없으며, 리포트에 `waived by $autoz`로 표시된다. `$autoz`가 없으면 지금처럼 묻고 기다린다. 리포트는 사전 조건을 맨 앞에 보여 준다.
- **환경 스킬은 어드민 승인**: 배포 때 설치된 환경 플러그인의 스킬은 어드민(`ADMIN_USERS`)은 바로, 그 밖의 사람은 어드민이 허용했을 때만 돈다. 어드민이 아닌 사람의 `$plugin:skill`이나 모델의 `Skill` 호출은 멈추고, 어드민 전원에게 버튼(수락 = 그 스레드만, 거절, 이 스킬 항상, 그 스킬이 속한 환경 `dev2` 전체 항상 — 환경 스킬과 그 환경 서버 도구 전부)이 붙은 DM이 간다. 허용되면 요청한 턴을 다시 보내 이어서 실행한다(자세히: [docs/runbook/add-new-deploy.md](../../../docs/runbook/add-new-deploy.md) §8.5).
- **환경 유저는 샌드박스 없는 어드민**: 환경 유저는 server-tools 항목의 `envUser`(`env:acme-dev2`)다. 어드민이고, 그 세션은 어느 호스트에서나 샌드박스 없이 돈다. 배포·QA 스킬은 환경 유저의 개인 스킬로 두고, 다른 사람은 이미 있는 두 흐름으로 부른다. `$acme-dev2:deploy-dev2`(환경 이름에서 `env:`를 뺀 것)는 다른 유저의 스킬과 같다. 대시보드 입력창의 `$` 메뉴도 이 스킬들을 환경 이름(`acme-dev2`) 묶음으로 보여준다 — 허락이 없으면 설명 대신 "관리자 승인 필요". 허락이 없으면 어드민 전원에게 DM 카드가 간다 — 수락(1회 — 그 스레드의 그 메시지에만), 거절, 이 스킬 항상, `acme-dev2` 환경 전체 항상(그 오너의 모든 스킬). 카드에는 실행될 메시지가 보인다. 허락이 있으면 그 메시지는 요청자 세션에서 돌지 않는다. 크론 실행 요청이 잡 오너 권한으로 도는 것처럼, 같은 채널의 새 스레드에서 환경 유저로 돈다. 요청자 스레드에는 링크와 결과가 온다. 그 세션은 스킬 호출과, `$`를 모두 무력화한 인용으로만 요청자 글을 받는다. 그래서 요청자 글은 거기서 명령으로 읽히지 않고 다른 스킬로 풀리지도 않는다. 한 메시지는 환경 스킬 하나만(다른 스킬과 함께 부르지 않는다), 2,000자까지(카드에 전부 보이게) 부르고, 환경 스킬은 메시지에서 직접 불러야 한다(다른 스킬 안에서는 안 된다). 환경 스킬 본문은 어드민 말고는 보거나 복사하지 못한다. 환경 유저의 스레드에서는 어드민이 묻지 않고 말할 수 있고, 다른 사람의 말은 어드민에게 묻는다. 환경 유저가 오너인 크론은 스케줄대로 환경 유저로 돈다. 허용 목록에 없는 사람의 `cron run <이름>`은 어드민에게 DM으로 묻고, 어드민이 승인하면 환경 유저로 실행된다. `acme-dev2`라는 이름은 어떤 Slack 표시 이름보다 먼저 `env:acme-dev2`로 풀린다.
- **작업 큐 — dev2 배포는 한 번에 하나**: 어떤 작업은 봇의 모든 유저를 통틀어 동시에 N개까지만 돈다. 기본 큐는 dev2 배포를 줄 세운다. `… -> deploy/dev2` 배포가 하나 진행 중이면 두 번째 배포는 시작하지 않는다. 요청자에게는 누가 배포 중인지(스레드 링크, 몇 분째인지)와 버튼 두 개 — **현재 배포가 끝나면 배포**, **취소** — 를 담은 카드가 간다. 취소를 누르거나 10분 안에 고르지 않으면 요청은 끝나고, 그 요청 때문에 만든 세션은 닫힌다. 대기를 고른 요청은 자리가 나면 자기 스레드에서 스스로 시작하고, 평소처럼 배포 확인을 묻는다. 자리는 배포 세션의 턴이 끝날 때, 세션이 닫힐 때, 배포가 자기 질문에 10분 동안 답을 못 받을 때 난다. 그 스레드에서 나중에 답하면 다시 큐를 거친다. 호스트는 모델이 돌기 전에 트리거 문장에서 대상 브랜치를 읽고(`dev2`와 `deploy/dev2`는 같은 대상), 배포 세션은 이후 턴에도 그 큐에 묶인다. 큐는 `config.json#workQueues`로 정한다. 키가 없으면 dev2 큐가 적용되고, `[]`면 큐를 모두 끈다. 항목마다 `id`, `label`, `workflow`, `targets`, 선택 `repos`, `concurrency`, `askTimeoutMinutes`, `holderIdleMinutes`를 쓴다. 큐는 봇 메모리에 있어서, 봇 프로세스 하나의 모든 유저를 덮지만 다른 봇 설치나 손으로 한 머지는 막지 못한다.
- **작업 카드 링크 누락 리포트**: 매일 `SOMA_LINK_LEAK_REPORT_HOUR`(`REPORT_TIMEZONE` 기준)에 호스트가 GitHub App이 지난 24시간 동안 연 PR·이슈(배포 PR 제외)를 모아, 살아 있는 카드와 보관된 카드의 링크 전부와 대조한다. 어느 카드에도 없는 것, 다른 세션의 카드에 붙은 것(만든 세션은 그 PR을 만든 쓰기에서 안다), 누락 없는 날이 며칠 이어졌는지를 올린다. 경보는 기준 주간이 지난 뒤, 그 주의 중앙값을 넘을 때만 낸다. `SOMA_LINK_LEAK_REPORT_CHANNEL`을 설정하면 매일 게시가 켜지고, `report leaks`는 GitHub App이 설정돼 있으면 언제든 지금 수치를 스레드에 보여 준다.
- **배포 릴리즈노트**: 배포가 끝나면 deploy 워크플로우가 `local:release-notes`로 노트를 쓰고 repo마다 `release_notes` 디렉티브를 하나 낸다. 호스트는 채널 루트에 짧은 헤더(`repo target · 버전` + TL;DR 최대 3줄)를, 그 스레드에 전문을 잘림 없이 나눠 올린다. 채널은 운영자가 호스트 `.env`의 `SOMA_RELEASE_NOTES_CHANNELS`로 정한다(예: `acme/app@deploy/dev2=C0DEV2CHAN1,*=session`). `owner/repo@branch` 또는 `branch`가 정확히 맞으면 그 채널, `*=session`이면 매핑 안 된 배포는 배포 세션 채널, `*`가 없으면 매핑 안 된 배포는 배포 스레드에만 남는다. 설정하지 않으면 예전처럼 배포 세션 채널이다. 게시가 실패해도 다른 채널 루트로 옮기지 않고 경고와 함께 배포 스레드에 남긴다.
- **llmux 세이브 모드 (관리자, 상단바)**: 상단바의 **세이브** 칩으로 llmux 세이브 모드를 켠다. 정한 시각까지 llmux는 그 전에 주간 한도가 리셋되는 계정만 쓰고, 나머지는 일시정지처럼 쉬게 해서 다음 주 토큰을 아껴 둔다(예: 금요일에 월요일 15:00로 설정). 칩은 `세이브 끔` 또는 `세이브 ~ <시각>`으로 상태를 보여 주고, 누르면 시각(기본값: 다음 월요일 15:00)과 켜기·끄기가 있는 창이 열린다. 그 시각이 되면 저절로 꺼진다. 쓸 수 있는 계정을 다 쓰면 그 시각까지 요청이 거절된다. 칩은 관리자에게만 보이고, 바꾸려면 수명 주기 정책처럼 관리자 모드(또는 viewer 토큰)가 필요하다. 쉬는 계정은 가용량 카드에 "세이브 모드"로 표시된다. API: `PUT /api/dashboard/llmux-save-mode` `{ until: <epoch 초> | null }` → llmux `POST /llmux/save-mode`. 세이브 모드가 있는 llmux가 필요하다(이전 llmux에서는 칩이 숨는다).
- naked `key` (= `auth key`): 자기 전용 llmux 클라이언트 키 + 로컬 Claude Code(`ANTHROPIC_BASE_URL`/`ANTHROPIC_API_KEY`)와 Codex(`OPENAI_BASE_URL`/`OPENAI_API_KEY`) 실행법을 DM으로 받음. 같은 유저는 항상 같은 키 — 봇 사용량과 로컬 사용량이 한 테넌트로 계측된다. 모든 유저 사용 가능(자기 키이므로), 시크릿은 DM으로만 전달.
  Codex 안내는 안내된 서버 주소의 `/v1`과 같은 테넌트 키를 사용한다. `codex --model … -c …` 명령 전체를 복사해야 기존 ChatGPT 로그인이나 다른 provider 설정이 있어도 명시한 Responses provider가 환경변수의 키를 사용한다. 환경변수는 현재 터미널에 적용되며, Codex 설정 파일과 로그인 정보는 덮어쓰지 않는다. 다음 llmux 세션도 같은 명령으로 시작한다. [Codex 게이트웨이 인증 문서](https://learn.chatgpt.com/docs/enterprise/connect-to-a-gateway).
- `auth`(= `/z auth`) **용량 오버뷰**: llmux 모드에서 `auth` 카드는 admin 포함 모두에게 **읽기 전용 용량 오버뷰**가 기본이다. Claude → Codex → Grok 순 그룹화(그 외 그룹은 알파벳순, 그룹 안은 스케줄러 선택 순서); 그룹 합계는 7d(및 `7d-fable` 등 scoped weekly) 잔여 비율을 **정규화된 계정분**(계정 1개 100% = 1, 플랜 가중치 없음)으로 합산 — llmux status 계약에는 utilization 비율과 리셋 시각만 있고 토큰 분모가 없으므로 토큰 잔고를 표시하거나 암시하지 않는다(누적 토큰은 소비량으로만 표기); 리셋은 Slack 로컬 절대 시각 + 남은 시간으로 표시하고 다음 리셋의 창·계정·회복 %p를 예고(추가 사용이 없을 때만 유효); 미제공·만료·범위 밖 값은 0%/100%가 아니라 "미제공"으로 표시, scoped 창은 공통 한도와 분리, cold/null 값은 합계에서 제외하고 측정 커버리지(n/m)를 표기; 5시간 창은 2026-11부터 어느 프로바이더도 주지 않으므로 카드에 `5h` 줄·합계·리셋이 없다(예전 llmux가 보내는 `five_hour`는 읽지 않음); Grok/API-key는 구독 창이 없어 잔여량·리셋 미제공으로 표시하고 소비량만 보여 준다; Codex 수동 리셋 카운터(보유/현재 적용 가능)는 읽기 전용 표시(자동 사용 없음); 관리 컨트롤(모드 전환·설정·추가·삭제·계정 전환)은 [어드민 모드] 버튼 **명시 클릭**으로만 열리고 위조/스테일 admin 클릭은 서버에서 readonly로 강등; 큰 풀은 고정 페이지 크기로 페이지네이션되어 모든 계정에 도달 가능하며 Refresh/페이징은 현재 보기와 페이지를 유지한다. 레거시 CCT를 `auth` 안에 표시할 때도 페이지를 나누며, 변경 버튼과 모달 제출 후 같은 auth 보기로 돌아온다. 별도 `cct` 명령은 기존 동작을 유지한다. 상세: [README.md의 Auth capacity overview](commands.md#auth-capacity-overview) · 스펙/업스트림 검증: [`.prd/07-auth-capacity-spec.md`](../../../.prd/07-auth-capacity-spec.md)
- **llmux SDK 인증 격리**: llmux 모드에서 soma-work는 Claude Agent SDK의 Messages 경로를 사용하며, 모델 카탈로그의 Codex 백엔드 모델도 이 경로로 실행한다. SDK 호출마다 선택한 llmux URL과 키를 함께 전달한다. 테넌트 lease가 있으면 개인 키를 쓰고, lease가 없는 보조 호출 등은 기존 공유 키로 폴백한다. 부모 환경의 OAuth·Bearer 인증, 다른 프로바이더 선택 플래그, 인증용 커스텀 헤더는 이 선택을 덮어쓰지 못하며 그 외 커스텀 헤더는 유지된다. [SDK 인증 계약](../../../docs/current/spec/llmux-sdk-auth.md)을 참고한다.
- 메시지 명령 `autocompact`(메시지 맨 앞에 `/`를 붙인 `/autocompact`도 같은 파서로 허용; 별도 등록된 Slack slash command는 아님): **세션 스코프** auto-compact 토큰 임계값. 인자 없이 호출하면 현재 유효값과 출처를 보여주고, `800k`/`800K`/`0.8M`/`800000`/bare `800`(천 단위로 해석)으로 설정하며, `reset`으로 모델 기본값으로 되돌린다 — 세션에 저장되어 재시작에도 유지. 우선순위(높은 게 이김): 세션 오버라이드 → 모델 기본값(`fable`(`claude-fable-5-2[1m]`)/`opus` 1M 프로파일 750k·750k, bare `gpt-5.6-sol` 340k, 리터럴 `gpt-5.6-sol[1m]` 1M 프로파일 600k, `astra`/`gpt-6`/`gpt6` 및 `gpt-6-astra[1m]` 1M 프로파일 600k, bare 리터럴 `gpt-6-astra`는 272k 컨텍스트에 240k, `sol`/`sol[1m]`/`gpt-6.1` 및 `gpt-6.1-sol[1m]` 1M 프로파일 600k, bare 리터럴 `gpt-6.1-sol`은 272k 컨텍스트에 240k, `terra`/`terra[1m]` 및 `gpt-6.1-terra[1m]` 1M 프로파일 600k, bare 리터럴 `gpt-6.1-terra`는 500k 컨텍스트에 450k, `sonnet`/`sonnet[1m]`(`claude-sonnet-5-5[1m]`)·`haiku`/`haiku[1m]`(`claude-haiku-5-5[1m]`) 1M 프로파일 750k, `luna`/`luna[1m]`(`gpt-6-luna[1m]`) 1M 프로파일 600k(bare 리터럴 `gpt-6-luna`는 272k에 240k), `grok-4.7`(대표 grok, 2026-11-10부터)·`grok-4.6` 450k, bare `claude-opus-5`는 기본값 없이 레거시 퍼센트로 폴백) → 레거시 유저 퍼센트(현재 모델 컨텍스트 윈도우 기준 환산). `grok-4.7[1m]`·`grok-4.6[1m]`은 실재하지 않는 모델이라 항상 `use grok-4.7`·`use grok-4.6`으로 명시 거부된다. `/compact-threshold <percent>`는 **deprecated** 호환 어댑터 — 현재 모델 기준으로 퍼센트를 환산해 `/autocompact`와 같은 세션 토큰 슬롯에 쓰고, 변환 성공 시 옛 유저 전역 퍼센트 저장값을 지운다; 모델의 안전 최대치를 넘는 변환은 조용히 clamp하지 않고 명시적으로 실패한다. 자동 compact는 harness의 임계값 체커가 유일한 트리거이며, SDK 자체의 native autocompact는 모든 해석된 모델 프로파일에서 꺼져 있다. 체커는 턴이 끝날 때만이 아니라 턴의 API 호출이 들어올 때마다 돈다. 턴 도중 임계값을 넘으면 그 턴을 멈추고 대화를 압축한 뒤 작업을 자동으로 이어 간다(goal 세션은 goal 루프가 이어 감). 이미 임계값을 넘은 상태로 시작한 턴은 멈추지 않고 다음 턴에 압축한다. 재시작 뒤에는 저장된 컨텍스트가 임계값 이상인 세션이 다음 턴 전에 압축한다. 모델별 정확한 기본값 표는 [README.md의 Auto-compact thresholds 섹션](commands.md#auto-compact-thresholds-autocompact--compact-threshold)을 참고하세요.
- 모든 `gpt-…[1m]` 프로파일은 앞으로 추가되는 지원 모델까지 Sol과 같은 1M 윈도우, SDK 차단선 977k, 자동 압축 600k를 적용한다. 모델별 임계값을 따로 등록할 필요가 없다. 지원하지 않는 모델 변형을 생성하거나 명시적으로 선택한 bare 모델 ID를 바꾸지는 않으며, 세션 오버라이드는 계속 우선한다.
- 제공자가 compact 요청을 거절하면 실패 안내에 인증정보를 가린 오류 상세를 표시한다. Slack 표시 길이를 넘으면 생략 사실을 알리며, 서버 로그에는 가림 처리한 전체 원인을 남긴다. 실패 안내는 압축 성공을 뜻하지 않는다.
