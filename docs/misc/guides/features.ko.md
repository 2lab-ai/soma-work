# soma-work 기능과 아키텍처

## soma-work란?

Slack 워크스페이스의 모든 대화를 AI 코딩 세션으로 전환하는 멀티테넌트 봇입니다. DM을 보내거나, 채널에서 멘션하거나, 스레드에서 대화하면 — 봇이 코드를 읽고, PR을 리뷰하고, Jira 이슈를 정리하고, 컨텍스트를 유지한 채 솔루션을 작성합니다.

```
You:   이 PR 리뷰해줘 https://github.com/org/repo/pull/42
Bot:   [diff 분석, 소스 코드 읽기, 라인별 리뷰 코멘트 작성]

You:   PROJ-1234 이슈 요약해줘
Bot:   [Jira 이슈 조회, 관련 PR/코드 분석, 경영진 보고용 요약 생성]

You:   이 함수 성능 개선해줘 [파일 첨부]
Bot:   [업로드된 코드 분석, 병목 지점 식별, 최적화된 버전 제안]
```

## zworkflow 플러그인

soma-work가 기본으로 싣는 Claude Code 플러그인 `zworkflow`는 [`src/local/`](../../../src/local/)에 있습니다.
내 Claude Code에서는 `/plugin marketplace add 2lab-ai/soma-work`와 `/plugin install zworkflow@soma-work`로
설치합니다. 설치·업데이트·훅, 그리고 플러그인 없이 `using-intentfirst`·`using-ssot` 스킬만 복사하는 경로는
[zworkflow 플러그인 README](../../../src/local/README.ko.md)에 있습니다.

zworkflow는 어디서든 쓸 수 있게 유지하는 것이 원칙입니다. 세션 작업 카드 호출(`GET_SESSION` / `UPDATE_SESSION`)과
NEEDS YOU 후속 작업은 두 번째 플러그인 `local`([`src/local-harness/`](../../../src/local-harness/))에 있고, soma-work만
기본으로 싣고 마켓플레이스에는 올리지 않습니다. zworkflow에 남은 다른 soma-work 전용 호출(`ASK_USER_QUESTION`,
`CONTINUE_SESSION`, cron)은 #860에서 옮깁니다. 그중 `local:auto-es`가 soma-work 안의 Executive Summary입니다:
`zworkflow:es`로 문서를 쓰고 작업 카드를 맞추며, 턴 종료 요약도 이 스킬의 턴 종료 규칙으로 돕니다.

## ✨ 주요 기능

### 🔀 워크플로우 자동 분류

사용자 입력을 분류하여 최적의 워크플로우로 자동 라우팅합니다 — 수동 선택 불필요.

| 워크플로우 | 트리거 | 동작 |
|-----------|--------|------|
| **PR Review** | GitHub PR URL | 코드 리뷰 + 인라인 코멘트 |
| **PR Fix & Update** | `수정해줘` + PR URL | 수정 구현 → 커밋 → 푸시 |
| **PR Docs** | `문서화` + PR URL | Confluence 문서 생성 |
| **Jira Planning** | Jira 이슈 + `계획` | 태스크 분해 & 작업 분할 |
| **Jira Summary** | Jira 이슈 + `요약` | 경영진 보고서 생성 |
| **Jira Brainstorming** | Jira 이슈 + `브레인스토밍` | 아이디어 발산 & 종합 |
| **Jira → PR** | Jira 이슈 + `PR 만들어줘` | 이슈에서 PR 자동 생성 |
| **Deploy** | 배포 관련 요청 | 배포 워크플로우 오케스트레이션 |
| **Onboarding** | 신규 유저 / `onboarding` | 인터랙티브 가이드 셋업 |
| **Default** | 기타 모든 입력 | 범용 코딩 어시스턴트 |

세션 핸드오프 전용 entrypoint(`z-plan-to-work`, `z-epic-update`)도 있습니다 (#695) — free-text 분류가 아니라 `CONTINUE_SESSION` 핸드오프로 진입합니다. Source of truth: [`somalib/model-commands/session-types.ts`](../../../somalib/model-commands/session-types.ts)의 `WorkflowType`, [`src/dispatch-service.ts`](../../../src/dispatch-service.ts)의 `VALID_WORKFLOWS`; 프롬프트 파일은 [`src/prompt/workflows/`](../../../src/prompt/workflows/).

### 🎭 천재 페르소나

봇의 성격과 사고방식을 전환합니다. 각 페르소나는 문제 해결에 고유한 접근법을 제공합니다.

```
/z persona set einstein    → 제1원리 물리학적 사고
/z persona set linus       → 무자비한 코드 리뷰
/z persona set feynman     → "간단히 설명 못하면 이해 못한 것"
/z persona set vonneumann  → 수학적 정밀함
```

사용 가능: `default` · `linus` · `buddha` · `davinci` · `einstein` · `elon` · `feynman` · `jesus` · `newton` · `turing` · `vonneumann` — source of truth: [`src/persona/`](../../../src/persona/)

### 🔌 MCP 도구 생태계

MCP 호환 서버(stdio/SSE/HTTP)를 연결하여 Claude의 능력을 무한히 확장합니다. 호출 통계와 예상 소요 시간을 내장 추적합니다.

### 🔐 인터랙티브 권한

Slack 네이티브 버튼/폼 UX로 권한 승인, 선택지, 세션 관리를 처리합니다. 신뢰된 사용자를 위한 바이패스 모드 지원.
**다른 사람의 지시는 소유자의 승인을 기다립니다.** 세션 소유자가 아닌 사람이 소유자의 작업 스레드에 지시를 보내면(슬랙 답글, 대시보드 메시지, 대기열의 메모, 슬랙 없는 태스크의 지시나 답) 실행하지 않습니다. 스레드에 기다리는 중이라고 알리고, 소유자에게 권한 요청처럼 슬랙 DM과 대시보드 카드(NEEDS YOU)로 묻습니다. 소유자는 어느 쪽에서든 답할 수 있고, 한쪽에서 답하면 양쪽이 함께 끝납니다: **✅ 승인**은 보류된 지시를 이번만 실행, **🔁 이 세션에서 항상 승인**은 실행하고 이 세션에서는 그 사람에게 다시 묻지 않음, **⭐ 이 사람의 지시 항상 승인**은 실행하고 그 사람을 소유자의 항상 승인 목록에 추가, **🚫 거절**은 지시를 버리고 스레드에 알립니다. 승인된 지시는 쓴 사람의 권한으로 실행됩니다. 예외 하나: 관리자가 보낸 맨 `!`는 지시가 아니라 중지라서 바로 작업을 멈춥니다. 항상 승인 목록은 **⚙ 설정 → 권한 → 항상 승인하는 사람**에 있고 거기서 뺄 수 있습니다(추가는 승인 요청에서만). 요청은 24시간 기다리고, 같은 사람의 지시는 같은 요청에 모입니다. 저장: `DATA_DIR/instruction-approvals.json` (`src/instruction-approval.ts`).

**소스 스레드에 남긴 지시는 보낸 사람이 승인하면 새 작업으로 시작합니다.** 스레드 중간에서 멘션하면 작업은 새 작업 스레드로 옮겨 가고, 멘션이 있던 스레드가 그 작업의 소스 스레드가 됩니다. 소스 스레드에서 봇을 다시 멘션하면 그 스레드에서 시작된 모든 작업 스레드의 상태를 답합니다. 멘션에 지시가 있으면 봇이 지시를 보낸 사람에게 DM으로 묻습니다: **새 작업으로 진행**을 누르면 같은 채널에 새 작업 스레드 헤더를 올려(대시보드에서 시작한 작업과 같은 방식) 그 지시만의 작업 스레드를 만들고, 같은 소스 스레드에 연결하며, 소스 스레드에 그 링크를 남깁니다. **취소**를 누르면 실행하지 않습니다. 파일을 첨부한 멘션(파일만 있는 멘션 포함)도 똑같이 묻고, 첨부 파일은 지시와 함께 넘어갑니다. 답하기 전에는 아무것도 실행하지 않고, 지시를 보낸 사람만 답할 수 있습니다. 소스 스레드 하나에 작업 스레드가 여러 개 있을 수 있습니다. 각 작업 스레드는 턴이 Executive Summary와 함께 끝나면 결과(TL;DR, 이슈와 PR, 작업 스레드 링크)를 소스 스레드에 보고합니다. 작업 스레드마다 카드 한 장이고, 이후 결과는 그 카드를 갱신합니다. 사용자 답을 기다리며 끝난 턴은 보고하지 않고, TL;DR에 ⚠️ 줄이 있으면 완료 대신 확인 필요로 표시합니다. 코드: `src/slack/source-thread-new-task.ts`, `packages/slack/src/source-thread-summary.ts`.
어느 모드에서든 비관리자 세션은 샌드박스 셸이 쓸 수 있는 곳에만 파일을 씁니다: 네이티브 `Write` / `Edit` / `NotebookEdit` 도구, 새 git worktree, 작업 디렉터리 전환(worktree로, 또는 서브에이전트의)도 Bash처럼 작업 디렉터리와 사용자 전용 임시 디렉터리로 묶이고, `Artifact`는 자기 스크래치패드에만 저장합니다(`out_dir`는 거부). 세션이 그 디렉터리로 가는 길에 심볼릭 링크를 만들어도 경계는 옮겨지지 않고(링크를 치울 때까지 네이티브 쓰기가 멈춥니다), 한 디렉터리의 두 표기(`/tmp`와 `/private/tmp`)는 같은 곳으로 봅니다.

**관리자도 샌드박스 안에서 실행됩니다** (#1210). 관리자 세션은 관리자 프로필로 돕니다: 모든 네트워크 도메인, `localhost`, gh의 TLS 검사, 임시 디렉터리 쓰기. 홈의 패키지 캐시는 읽기만 됩니다(봇이 거기서 MCP 서버를 띄웁니다). 샌드박스 안에서 설치할 때는 그 명령의 캐시를 사용자 임시 디렉터리로 직접 지정합니다(`npm install --cache /tmp/<사용자 ID>/npm`, pnpm `--store-dir`, `PIP_CACHE_DIR`, `UV_CACHE_DIR`, `GOCACHE`도 같은 식). 관리자의 네이티브 `Write` / `Edit`도 셸과 같은 디렉터리로 묶입니다. `sandbox off`는 호스트 운영자가 `.env`에 `SOMA_SANDBOX_OFF_ALLOWED=true`를 둔 호스트에서만 효과가 있고, 그 밖에서는 명령이 이유를 답하고 세션은 샌드박스로 돕니다. 어떤 세션도(관리자 포함) 배포 디렉터리, 그 data 디렉터리, 홈의 시작 파일(LaunchAgents, 셸 rc, `.ssh`, git·CLI 설정)을 쓰지 못하고, 사람·호스트의 자격 파일(`~/.ssh`, `~/.config/gh`, `~/.aws` …)을 읽지 못합니다 — 봇 자신의 짧은 수명 GitHub App 토큰은 git·gh가 push에 쓰므로 읽힙니다. Bash `ssh`는 모두에게 막혀 있고, 관리자는 server-tools의 `ssh_exec` 도구로 호스트 명령을 실행합니다 — 샌드박스 밖에서 봇 자신의 키를 씁니다.

### 📎 파일 분석

이미지(JPG/PNG/GIF/WebP), 텍스트, 코드 파일을 Slack에서 직접 업로드 가능. 파일당 50MB 제한.

### 🆕 대시보드에서 작업 시작

대시보드의 **New task** 버튼(PC는 상단 바·`Ctrl+N` 단축키(Mac은 `⌃N`), 휴대폰은 아래 탭 바 가운데의 + 버튼)으로 작성 창을 엽니다. 모델과 effort를 한 모델 메뉴에서(모델마다 창·자동 압축 지점·비용과 그 모델이 실행하는 effort 단계만; 옆에 공유 풀 잔여량 배터리), Slack 채널, 작업 단위 `autogoal`·`autoz` 토글, 지시문, 첨부(파일·붙여넣은 스크린샷·휴대폰 카메라·음성 녹음)를 정하면, 고른 채널의 새 스레드에 내 메시지로 작업이 시작되어 진행이 Slack에 그대로 보입니다. 지시문은 12,000자까지입니다. 붙여넣은 글 때문에 이 한도를 넘게 되면 그 글은 입력창에 들어가지 않고 텍스트 파일(`pasted-text-<날짜>-<시각>.txt`)로 첨부되고, 세션은 그 파일을 끝까지 읽습니다. 채널 목록은 내가 속한 repo 매핑 채널과 맨 위의 `#workspace`(repo에 매핑되지 않은 일반 채널 — 여러 repo를 건드리거나 repo 없는 작업용, `#workspace · 모든 repo · 일반 작업`으로 표시)이고, 기본값은 마지막으로 명령을 내린 채널입니다. 관리자(`ADMIN_USERS`)에게는 봇에 `channels:manage` 권한이 있을 때 **＋ 새 repo 채널 만들기**가 함께 보입니다. GitHub repo(`owner/name` 또는 github.com 주소)를 쓰면 `workspace-<repo>` 이름(고칠 수 있음)의 새 공개 채널에서 작업이 시작됩니다. 봇에 `groups:write`가 있으면 비공개로도 만들 수 있습니다. 봇이 채널을 만들고, 채널 설명에 `https://github.com/<repo>`를 적고(이것이 채널과 repo를 잇습니다), 나를 초대한 뒤 그 채널에 작업을 올립니다. 봇이 GitHub에서 읽을 수 없는 repo는 거절하고, 이미 채널이 있는 repo는 새로 만들지 않고 그 채널에 올립니다. `autoz`를 켜면 지시 끝에 `$autoz`가 붙습니다. 음성 녹음 마이크 옆에 받아쓰기(연필) 버튼이 있습니다: 말하는 동안 브라우저 내장 음성 인식기가 입력창에 글자로 적고, 고쳐서 텍스트로 보냅니다. 브라우저가 할 수 있으면 기기 안에서 처리합니다(iPhone·Mac Safari, 한국어가 설치된 데스크톱 Chrome). 갤럭시(Chrome·Samsung Internet)에서는 휴대폰의 음성 인식(Google 음성 인식 앱)을 씁니다. 이런 환경에서는 새 작업 창이 받아쓰기가 켜진 채로 열리고, 키보드로 치면 꺼지고 타이핑이 이어집니다. 한국어가 없는 데스크톱 Chrome에서는 꺼진 채로 열리고, 처음 누르면 바로 받아쓰며 상태 줄에 음성이 브라우저의 음성 서비스로 간다고 알립니다. 인식이 실패하면 빨간 오류 줄에 이유를 보여 줍니다. 갤럭시에서는 무엇을 켜야 하는지(‘Google 음성 인식 및 합성’ 앱, 브라우저의 마이크 권한) 알려 주고, 마이크를 아예 열지 못하는 인식기도 알려 줍니다. 글자 없이 세 번 연속 끝나면 멈추고, 소리는 들렸던 경우에는 계속 그러면 무엇을 해 볼지 상태 줄에 알려 줍니다. 세션 패널 입력창에도 같은 받아쓰기가 있습니다. 인식기가 없는 브라우저(Firefox, iPhone 홈 화면 웹 앱)는 음성 녹음만 있습니다. **설정 › 받아쓰기**에서 이 기기의 엔진을 고릅니다. 고른 값은 이 브라우저에만 저장되고 서버에는 저장되지 않습니다. 같은 탭에 이 기기의 음성 인식 정보(브라우저·OS, 처리 위치, 언어별 Chrome 기기용 모델과 내려받기, 마이크 권한, WebGPU)가 나오고, **말해서 시험**은 8초 동안 듣고 첫 글자까지 걸린 시간을 알려 줍니다. **서버 위스퍼**를 고르면 마이크 소리가 서버의 Whisper(large-v3-turbo, Apple Silicon에서는 GPU를 쓰는 mlx-whisper)로 흘러가고, 0.5초마다 글자가 늘어나며 두 번 연속 같은 결과와 쉼마다 확정됩니다. Google 음성 서비스를 거치지 않아 삼성 인터넷·Safari·Firefox에서도 같게 동작합니다. 서버에는 A2T 워커(`services/a2t/requirements.txt`)가 필요합니다. **브라우저 위스퍼**를 고르면 Whisper가 브라우저 안에서 돌고(Web Worker의 transformers.js, WebGPU가 있으면 WebGPU, 없으면 WebAssembly), 음성이 기기 밖으로 나가지 않습니다. 모델 크기는 기기마다 고릅니다(작게 whisper-base · 보통 whisper-small, WebGPU 기본값 · 크게 whisper-large-v3-turbo). 처음 쓸 때 내려받으며 상태 줄에 진행률이 나오고, 이후에는 브라우저 캐시에서 씁니다. 두 위스퍼 엔진은 같은 스트림 정책으로 글자를 확정합니다. 조사: [`docs/misc/research/2026-11-01-on-device-dictation.md`](../../../docs/misc/research/2026-11-01-on-device-dictation.md). 작업 시작을 누르면 작성 창은 바로 닫히고 다음 작업을 위해 비워집니다. 보드에는 그 작업이 실행 중 맨 위에 '시작 중' 카드로 나타나고, 작업의 실제 카드가 오면 그 카드로 바뀝니다. 시작 알림의 카드 열기(또는 '시작 중' 카드 누르기)는 Slack이 아니라 보드의 그 카드를 상세 패널과 함께 엽니다 — 카드가 아직 없으면 오는 즉시 엽니다(스레드는 Slack에서 보기 링크). 한 페이지에서 연달아 시작한 작업은 앞 작업이 시작된 뒤 차례로 올라갑니다(서버는 유저당 한 번에 하나씩 받습니다. 같은 순간 다른 탭에서 시작한 작업은 거절되고, 실패한 작업처럼 돌아옵니다). 그동안 각 작업은 자기 '시작 중' 카드를 보여 줍니다. 시작하지 못한 작업은 보드에서 빠지고, 지시와 첨부가 이유와 함께 작성 창으로 돌아옵니다. 작성 창에 다른 지시가 있으면 덮어쓰지 않고, '응답 필요'에 '시작 실패' 카드로 남겨 두었다가 누르면 가져옵니다.

### ⏳ 한 사람당 한 번에 한 작업 (작업 큐)

요약: 관리자가 아닌 사람은 한 번에 작업 하나만 진행합니다. 작업이 진행 중일 때 보낸 요청은 그 사람의 대기큐에 들어가고, 진행 중인 작업이 끝나면 저절로 시작합니다. **먼저 진행**을 누르면 진행 중인 작업을 멈추고 이 요청을 먼저 하며, 멈춘 작업은 그 뒤에 이어서 합니다.

- **무엇을 진행 중으로 보나.** 작업은 스레드 하나입니다. 그 스레드의 턴이 도는 동안, 또는 골 루프가 다음 턴을 곧 시작하려는 동안 진행 중입니다. 내 답을 기다리는 작업, 배포·QA 레인에서 기다리는 작업은 세지 않습니다. 진행 중인 스레드에 보낸 메시지는 그 작업의 후속 지시이지 새 작업이 아닙니다.
- **한도.** 기본 1개, 관리자(`ADMIN_USERS`)는 무제한. 관리자는 **설정 › 작업 큐**에서 사람마다 정합니다. 사람마다 노브가 하나씩 있고 볼륨처럼 돌립니다(위·오른쪽으로 끌기, 휠, 화살표 키; Page Up/Down은 3칸, Home은 1, End는 ∞). 손을 떼면 저장되고, 새 한도로 시작할 수 있는 대기 작업은 바로 시작합니다. **기본값으로**를 누르면 돌려놓은 노브가 기본값으로 돌아갑니다. 같은 탭 맨 위 **작업 큐 — 한 번에 하나씩**에는 레인(`qa-dev2` · `deploy-dev2` …)마다 지금 진행·대기와 내역 표(줄 선 시각 → 진행 구간 → 끝)가 있어, 레인이 들어온 순서대로 한 번에 하나씩 처리한 기록을 봅니다.
- **Slack에서.** 대기하는 스레드에 메시지가 하나 올라옵니다. 진행 중인 작업과 그 스레드 링크, 그 작업이 끝나면 이 요청이 자동으로 시작된다는 것(대기 순번 포함), 버튼 둘입니다. **먼저 진행**은 가장 늦게 시작한 작업을 멈추고 이 요청을 바로 시작한 뒤, 멈춘 작업을 대기열 맨 앞에 둡니다. 멈춘 스레드에도 그렇게 알리고, 먼저 간 요청이 끝나면 멈춘 지점부터 이어서 합니다. 멈추는 중인 턴과 동시에 돌지 않도록, 요청은 대기열 맨 앞에서 기다렸다가 멈춘 턴이 완전히 끝나는 즉시 시작합니다(막 시작하는 중인 턴은 멈출 수 있게 되는 즉시 멈추고, 그 전에 작업이 스스로 끝나면 이어서 하지 않습니다). **대기 취소**는 요청을 대기열에서 뺍니다. 요청한 사람(또는 관리자)만 누를 수 있습니다. 차례가 오면 같은 메시지가 "시작했습니다"로 바뀝니다.
- **대시보드에서.** 기다리는 요청은 크론 칸 바로 밑 **작업 큐** 칸의 **개인별 큐** 탭에 있습니다. 사람마다 한도 · 진행 중인 작업 · 대기 중인 요청의 카드(대기 순서대로 — **대기중 · n번째**, 누구의 것인지(전체 사용자 보드에서는 세션 카드와 같은 이름 뱃지 — 한 사람은 한 색, 내 것은 링), 무엇을 기다리는지: 1번째는 진행 중인 작업이 끝나면 바로 시작하고, 2번째부터는 바로 앞 항목을 이름으로 보여 줍니다(`앞에 n개 먼저 — 바로 앞: …`)) · 내역(시작 · 취소 · 같은 작업 거절)이 나옵니다. 카드를 열면 **먼저 진행** / **대기 취소**가 있습니다. 대기 중인 스레드는 응답 필요 칸에 없고 "응답 필요" 숫자에도 세지 않습니다. 아직 세션이 없는 스레드(첫 메시지)의 요청도 카드가 있고, 제목을 누르면 Slack 스레드가 열립니다. 다른 탭 **작업 큐**에는 레인(`qa-dev2`, 한 번에 하나)이 있습니다: 진행 중인 작업, 그 레인에서 기다리는 카드(보드의 칸에서 옮겨 옴), 겹치지 않는 24시간 막대, 최근 내역. 관리자 모드의 관리자는 카드를 먼저 진행시키거나(**먼저 진행**) 대기에서 빼고(**대기에서 빼기**), 진행 중인 차례를 끝냅니다(**차례 끝내기**). 대기에서 빼기와 차례 끝내기는 무엇이 일어나는지 묻는 확인 창을 먼저 띄웁니다 — 차례를 끝내면 그 작업은 레인에서 빠지고 스레드에 안내가 가지만, 작업 세션 자체는 멈추지 않습니다.
- **같은 작업을 다시 시키면.** 요청의 작업 키(GitHub 이슈·PR 링크와 `owner/repo#123`, Jira 링크·키)가 모두 내 다른 스레드에서 진행 중이거나 대기 중이면 시작하지 않고 바로 알립니다 — 키마다 어느 스레드가 하고 있는지, 그리고 **그래도 시작**(30분 안, 한 번). 관리자에게도 적용되고, 크론·호스트 턴·같은 스레드의 후속 지시는 거절하지 않습니다. 진행 중인 작업의 키 = 그 요청들이 낸 키 + 작업 카드의 이슈·PR.
- **먼저 진행이 멈추지 않는 작업.** 배포·QA 레인을 잡은 작업이나 환경(env) 작업을 기다리는 작업은 멈추지 않습니다 — 배포가 반쯤 된 채로 남을 수 있어서입니다. 대신 그다음으로 늦게 시작한 작업을 멈추고, 진행 중인 작업이 전부 그런 작업이면 이유를 말하고 거절합니다(Slack·대시보드). 요청은 그 작업이 끝나면 시작합니다.
- **Slack 재전송.** 봇이 이벤트를 늦게 확인하면 Slack이 같은 이벤트를 다시 보냅니다(`retry_attempt`, 이유 `timeout`). 이미 줄에 있거나 30분 안에 줄에서 빠진 메시지의 사본은 새 요청이 아닙니다. 항목도 안내도 하나뿐입니다. 이 처리가 들어가기 전에 저장된 사본은 로드할 때 첫 항목으로 합칩니다.
- **한도 올리기.** 노브를 올리면 시작할 수 있는 작업이 바로 시작합니다. 자기 스레드가 아직 도는 항목은 건너뛰고, 빈 자리는 그다음 항목이 받습니다.
- **PR 알림과 종료한 스레드.** 그 사람의 다른 작업에 온 pr-watch CI·리뷰 알림은 요청으로 줄을 서지 않습니다. pr-watch가 빈 자리가 생길 때까지 들고 있다가 넘기고, 그사이 PR이 머지되거나 세션이 종료되면 버립니다. 스레드의 세션을 종료하면 그 스레드의 대기 항목도 줄에서 빠지고 안내가 바뀝니다.
- **잡아두지 않는 것.** 이미 진행 중인 작업을 호스트가 이어 가는 턴 — 골 루프의 다음 턴, 재시작 뒤 재개, 배포 레인 차례 알림, 에픽의 자식 — 은 새 작업이 아니라서 잡아두지 않습니다(대기 중인 스레드의 골 연속 턴은 버리고, 대기 항목이 작업을 이어 갑니다).
- **어디에 있나.** `src/user-task-queue/`. 게이트는 `SlackHandler.handleMessage`의 유휴 디스패치 지점에 있어 Slack·대시보드·크론이 모두 지납니다. 대기열은 `DATA_DIR/user-task-queue.json`, 한도는 `DATA_DIR/user-task-limits.json`(둘 다 원자적 저장, `.bak`). 재시작해도 대기열은 남습니다.

### 🧭 작업 계획 모드

새 작업 창의 입력창 오른쪽 아래, **작업 시작** 버튼 바로 왼쪽에 **작업 계획** 스위치가 있습니다(기본 꺼짐, 해/달 모양). 모든 새 작업에 있습니다(새 작업은 모두 고른 채널의 Slack 스레드입니다). 켜면 달이 뜨고 별이 나오며, 보내기 버튼이 밤 색으로 바뀌고 글자가 **계획 시작**으로 올라옵니다. 끄면 해와 **작업 시작**으로 돌아옵니다. 폭이 375px보다 좁은 폰에서는 보내기 버튼이 화살표만 보여 줍니다. 켜 두면 그 작업에는 autogoal과 autoz가 꺼지고, 작업은 바로 실행되지 않으며, 먼저 지시를 SSOT로 고정하고 의도를 정리해(INTENT-FIRST) 전체 계획을 세웁니다. 계획은 한 줄 결론과 의도 → 단계 지도 → 단계별 작업 → 작업마다의 디테일 순서로, 서버가 그린 HTML로 보입니다. 받아쓰기나 음성으로 내린 지시, 오래 걸리는 에픽처럼 잘못 읽히면 비싼 일을 실행 전에 확인하기 위한 것입니다.

- 계획은 디테일 카드 탭 줄의 첫 탭 **작업 계획**에 있고, 눈에 띄게 그려집니다(강조 색, 버전과 상태). 시작을 기다리는 계획이면 카드가 그 탭이 열린 채로 열립니다. 맨 위 상태 바에 **시작** · **취소**, 맨 아래 입력창 위에 **시작** · **취소** · **직접 입력**이 있고, 펼친 작업 카드에도 같은 세 버튼이 있습니다. 계획이 올라오면 작업 카드가 한 번 저절로 펼쳐집니다.
- **시작**은 보고 있던 버전만 시작합니다(그사이 새 버전이 왔으면 다시 보라고 알립니다). 시작하면 계획 전문이 지시로 들어가 작업이 이어집니다. **취소**는 계획을 닫고, 새 지시를 보내면 다시 계획합니다. **직접 입력**은 입력창으로 가며, 거기 보낸 말을 반영해 모델이 다음 버전의 계획을 올립니다.
- 시작 전에는 계획 도구만 붙고 에픽의 자식 만들기 도구는 붙지 않습니다. 전체 화면 보기: `/dashboard/plan/<세션 키>`.
- Slack 스레드 작업이면 계획이 올라올 때 스레드에 카드 링크가 담긴 안내가 옵니다. **시작**을 누르면 계획이 스레드에 내 다음 지시로, 따로 한 턴으로 들어갑니다. 아직 도는 턴이 있으면 그 뒤 대기열에서 기다립니다. 계획이 기다리는 동안 스레드에 쓴 말은 직접 입력입니다. `/compact`와 봇이 스스로 이어 가는 턴은 직접 입력이 아니어서, 계획은 그대로 기다립니다.
- 단순한 질문(선택지 2–4개, 짧은 이름 — 예/아니오, 시작/취소 같은 것)은 작업 카드에 선택지 버튼으로 나와 한 번 눌러 답합니다.
- 질문은 그 답이 막고 있는 작업(🚧), 걸린 것(⚖️), 되돌릴 수 있는지(⚠️ 되돌릴 수 없음 + 이유, 또는 ↩️ 되돌릴 수 있음)를 함께 보여 줄 수 있습니다. Slack 카드와 대시보드에 같은 줄이 같은 순서로 나옵니다(#1073). 대부분의 질문에는 이 줄이 없고 예전과 똑같이 보입니다. 이 줄이 있는 질문은 카드 면에서 한 번 눌러 답하지 않고, 카드를 펼쳐 줄을 본 뒤 답합니다. 스펙: [`docs/current/spec/12-ui-ask-user-question.md` §7.10](../../current/spec/12-ui-ask-user-question.md).
- **시작**하면 계획을 끝까지 마치는 goal도 함께 걸립니다. goal 루프가 계획이 끝날 때까지 턴을 이어 가고, 서비스가 재시작되면 다시 이어 갑니다. 직접 보낸 지시나 답은 이어가기 한도를 초기화합니다.

### 🙋 사용자 작업 (유저가 할 일)

에이전트가 스스로 할 수 없는 일 — 소유자만 할 수 있는 인증, 로그인, 에이전트가 닿지 않는 머신에서의 명령 — 을 시켜야 할 때는 답변 본문에 적지 않는다. 전용 도구(`user-action` MCP의 `instruct_user`)로 넘기고, 그 일은 따로 보인다: 스레드의 별도 Slack 카드, 그리고 대시보드 디테일 카드의 **사용자 할 일** 섹션(질문과 분리)이다. 이 섹션은 탭 줄의 마지막 탭 **사용자 작업** 안에 있어서, 누르면 보이고 다시 누르면 접힌다. 그 탭과 작업 카드 면에 기다리는 필수 작업 수가 표시된다.

- 모든 작업은 짧은 스크립트(최대 8줄·600자) + 실행할 머신, 에이전트가 못 하는 이유, 스크립트가 바꾸는 것, 성공하면 보이는 것으로 온다. 브라우저나 폰에서 하는 일도 명령에서 시작한다(예: 맥에서 `open 'https://…'`).
- 보여 주기 전에 스크립트는 에이전트가 자기 Bash 명령에 거는 것과 같은 점검을 거친다: 구문 검사(`bash -n`), 같은 위험 명령 규칙, 비가역 동작 판정, 그리고 sudo·네트워크 접속·파일 쓰기·내려받거나 감춘 코드 실행. 결과(✅ 통과 · ⚠️ 주의 · ⛔ 위험과 각 항목)가 스크립트 옆에 붙는다. 어느 필드든 비밀값이 든 것, 링크만 있는 것, 구문이 틀린 스크립트는 유저에게 가기 전에 거절된다. 스크립트는 POSIX 셸(bash·zsh·sh)이다.
- 실행한 뒤 Slack 카드나 대시보드 섹션의 **✅ 완료했어요** 또는 **❌ 안 됐어요**를 누른다. 카드의 버튼이 사라지고 대시보드가 갱신되며, 에이전트는 무엇을 눌렀는지 메시지로 받고 이어서 진행한다. 그 메시지가 에이전트에 닿지 못하면 작업은 다시 대기로 돌아가 한 번 더 누를 수 있다. 세션 소유자(또는 그 세션에 승인된 사람)만 누를 수 있다.
- 스펙: [`docs/current/spec/15-user-action.md`](../../current/spec/15-user-action.md).

### 📬 에이전트 우편함 (인스턴스끼리 메일)

인스턴스가 자기 [agent-mailbox](https://github.com/2lab-ai/agent-mailbox) 우편함을 읽는다. 다른 호스트의 에이전트끼리, 그리고 같은 호스트의 세션끼리 슬랙 없이 주소로 메일을 주고받는다. 호스트 프로세스가 로컬 우편함 서버를 롱폴로 확인한다(빈 함에는 모델이 돌지 않는다).

- **주소**: 인스턴스는 `<에이전트>:<호스트>:<인스턴스>`(예: `soma-work:host-b:dev`), 메일함 오너의 Slack 세션은 `…/<채널 소문자>-<threadTs>`. 그런 세션의 턴마다 에이전트 셸에 그 주소가 `MAILBOX_ADDRESS`로 들어가서, 그 세션에서 `mailbox send`로 보낸 메일은 그 세션이 보낸 것이 되고 답장도 그 세션으로 돌아온다. 다른 유저·환경 유저의 세션에는 주소가 없다.
- **세션 메일**(꼬리표 있음)은 그 세션이 비는 순간 호스트 턴이 된다. 잠든 세션은 자기 스레드에서 깨운다. 메일함 오너의 세션만 메일을 받는다: 이미 없어진 세션·남의 세션의 꼬리표, 3번 못 받거나 30분 바쁜 세션, 모르는 꼬리표는 메인 세션으로 가고 왜 왔는지 한 줄이 붙는다.
- **일반 메일**(꼬리표 없음, `/main`)은 인스턴스의 **메인 세션(대표 세션)**이 받는다. 아직 없거나 더 이상 턴을 못 받으면 설정한 채널(기본: 오너 DM)에 새 봇 스레드를 열어 메인 세션으로 삼는다. 어드민은 `GET/PUT/DELETE /api/mailbox/main-session`(Slack 로그인, 변경은 관리자 모드, 메일함 오너의 살아 있는 세션만)으로 보고 바꾼다. UI 연구: [`docs/misc/research/2026-11-20-mailbox-main-session-ui.md`](../research/2026-11-20-mailbox-main-session-ui.md).
- 메일 본문은 그대로 들어간다 — 명령·스킬 호출·유저 답으로 읽히지 않고, 메일이 아무 권한도 주지 않는다고 적혀 들어간다. 호스트가 턴을 받았을 때만 읽음 처리한다. 한 대화가 12번 턴을 열면 멈춘다(에이전트끼리 답장에 답장하는 것 방지).

```json
"mailbox": { "owner": "U0123ABC", "channel": "C0123ABC", "allowFrom": ["soma-work:*:*"] }
```

`client`(기본 `~/.config/agent-mailbox/client.json`, 우편함 CLI 자신의 설정)에 서버 URL·토큰·주소가 있다. `allowFrom`(필수)은 턴을 열 수 있는 보낸 사람, `cli`는 턴 안내문에 쓸 CLI, `intervalSeconds`(기본 15)는 바쁜 세션을 기다리는 간격. `mailbox` 키가 없으면 poller도 없다. 코드: `src/mailbox/`, `src/conversation/mailbox-routes.ts`.

### 📞 전화 걸고 받기 (server-tools)

에이전트가 server-tools 환경의 번호([한국AI통신](https://platform.koreaaitel.com/docs/getting-started), 구 ClawOps)로 전화를 걸고 받는다. 듣기는 음성 서비스의 받아쓰기, 생각은 soma-work의 모든 모델 호출과 같은 길(Agent SDK `query()` → llmux, 요청자의 키), 말하기는 음성 서비스의 스트리밍 합성(Drama 3, 기본 `cwon`)이다.

- **걸기**: `phone_call {server, to, title, purpose, scenario?, max_minutes?}`가 통화 ID를 바로 돌려주고 통화는 따로 진행된다. `phone_calls {server, call_id, wait_seconds}`로 상태 · 시간 · 전사를 읽는다(끝날 때까지 최대 300초 기다림). `phone_call`은 어드민 도구(또는 환경 허용이 연 도구)이고, 요청자가 있어야 하며 감사 원장에 전후로 남는다.
- **채팅 안에서**: 통화는 그 통화를 건 턴의 답 아래 카드로 뜬다 — 제목 · 번호 · 통화 시간 · 상태 · 마지막 몇 마디(상대 왼쪽, 에이전트 오른쪽), 통화 중에는 실시간. 누르면 통화 보기: **통화**(통화를 채팅처럼) · **작업**(통화 에이전트의 작업 기록 — 받은 지시, 받아쓰기, 모델 응답, 도구 호출, 음성 합성과 각각의 시간).
- **받기**: 그 번호로 온 전화는 환경의 수신 지시와 미리 합성한 인사로 받는다. 끝나면 회선 owner에게 슬랙 DM으로 요약과 `/dashboard?phoneCall=<id>` 링크를 보낸다.
- **번호당 한 통화**(통화 중 걸려 온 전화는 통화중). 회선은 MCP 서버가 아니라 데몬이 든다 — 플랫폼이 번호당 연결 하나만 둔다.
- **설정**: server-tools 환경에 `phone` 절, 키는 시크릿 저장소(`{"$secret": …}` — config.json에 직접 쓴 키는 무시된다). 전화만 있는 환경은 호스트 절이 없어도 된다. 예시는 영문 가이드와 [`.prd/31-phone-calls-architecture.md`](../../../.prd/31-phone-calls-architecture.md) §4.1.

스펙: [`.prd/30-phone-calls-spec.md`](../../../.prd/30-phone-calls-spec.md).

### 🗂️ 작업은 한 종류

모든 작업은 Slack 스레드입니다. 채널에서 시작하든 대시보드의 새 작업 창에서 시작하든 같고, 대시보드는 그 스레드를 보여 주는 화면입니다. 후속 대기열, `!` 스티어링, goal, 재시작 뒤 이어가기, 압축 같은 Slack 세션의 기능이 모든 작업에서 그대로 동작합니다. Slack 없는 별도의 대시보드 작업은 없어졌습니다(#855). 저장돼 있던 것은 봇이 세션을 불러올 때 보관함으로 옮겨지고, 보드의 닫힘 열에서 계속 읽을 수 있습니다. `/z taskentry`와 그 설정도 함께 없어졌고, 예전 설정 값은 무시합니다.

### 🖼️ 대시보드 산출물

모델이 Slack으로 보낸 파일(HTML 리포트, PNG, WAV·음성, 영상, PDF, 텍스트)이 웹 대시보드에 최신순으로 보인다: 세션 카드의 칩, 펼친 카드의 썸네일 스트립, 상세 카드 산출물 탭의 같은 썸네일 타일(모든 파일을 한눈에 보는 그리드, 낮은 패널에서는 옆으로 넘기는 한 줄 — 미니멀·어드밴스드 모두. 펼친 카드의 **전체 N개 →**로 열면 그 탭에 착지)과 답변마다 그 턴의 파일. 마크다운 답변은 채팅에 나오고 산출물 목록에는 들어가지 않는다. 마우스를 올리면 미니맵 미리보기, 누르면 파일에 맞춘 뷰어(HTML 페이지·이미지·영상·PDF는 화면을 가득 채우고, 문서는 높이를 가득 쓰고, 오디오는 작은 창 — HTML은 샌드박스에서 실행, 오디오는 카드에서 바로 재생). 뷰어 아래 ‹ n / m ›를 누르면 세션의 모든 파일 목록에서 골라 연다. 기능 도입 전 업로드는 세션 작업 로그에서 백필한다. 세션이 만든 URL — 이 머신에서 서빙하는 페이지·앱, YouTube에 올린 영상 — 도 모델이 slack-mcp `send_link`로 올리면 산출물이 된다: 링크와 호스트로 표시되고, 누르면 새 탭에서 그 URL이 열린다. slack-mcp는 세션의 첫 턴을 포함한 모든 Slack 턴에 붙으므로 그곳에서 보낸 영상·음악·링크가 목록에 오른다(2026-11-09 전에는 첫 턴에 slack-mcp가 없어서 다른 방법으로 보낸 미디어가 보이지 않았다). 시각화 하나는 산출물 하나다: `local:html`, `local:dimensional-drawing`, `qa-report`는 HTML만 올리고 PNG는 만들지 않으며(페이지는 `render.mjs --check`로 헤드리스 브라우저에서 검수), `local:architecture-diagram`과 `diagram` 라우터는 PNG만 올리고 `.excalidraw` 원본은 요청할 때만 올리며, `dimensional-drawing-motion`은 MP4만 올린다.

**판** (#1074): 같은 세션에서 같은 키로 다시 보낸 파일 — 모델이 `send_file` / `send_media`에 준 `artifact_key`, 없으면 시각만 뺀 파일 이름이 같은 것 — 은 새 파일이 아니라 그 산출물의 다음 판이다. 목록에는 한 줄로 묶여 "판 N · 이전 판 이후 바뀜"이 보이고, Slack 업로드 코멘트도 그렇게 말한다. 내용이 같으면 "바뀐 것 없음"이라고 말하고 새 판을 남기지 않는다. 뷰어의 **이전 판 열기**로 이전 판들을 넘겨 보고, **이전 판과 비교**로 HTML·마크다운·텍스트 소스의 줄 단위 차이를 본다(`GET …/artifacts/:id/versions`, `GET …/artifacts/:id/diff[?against=<id>]`). 같은 바이트는 한 번만 저장하고, 산출물마다 최근 10판의 바이트만 남긴다(그보다 오래된 판은 Slack 링크만). 보드와 실시간 푸시에는 판 배지만 실린다. PR 본문을 고칠 때도 같은 방식으로 이전 본문을 남기고(`artifact_key="pr-<n>-body"`), `local:html` 서버는 같은 이름의 이전 파일을 `.versions/<이름>/v<N><확장자>`로 보관한다.

턴의 Executive Summary가 나오면(작업이 끝나고 5분쯤 뒤 — Slack 스레드 헤드의 TL;DR) 대시보드에도 보인다: 세션 패널 Chat에 요약 전문이 답변으로, 태스크 카드에 TL;DR 상자로. 상자는 다음 지시가 오면 사라지고, 휴면·보관 카드에는 보이지 않으며, 우상단 ×를 누르면 이 브라우저에서 그 카드의 상자를 지운다. 세션이 만든 이슈나 PR이 아직 완료가 아니면(열림·드래프트·미머지·배포 대기) 요약은 TL;DR의 굵은 ⚠️ 줄에 그 이유를 쓰고, 맨 아래 ⚠️ User follow-up required 섹션에 무엇이 막혔는지·누가 해야 하는지·단계·확인 방법·처리 후 보낼 답을 쓴다. 그러면 유저에게 다음에 할 일을 묻는다 — 질문 없이 기다리는 카드는 없다(#917): 모델이 쓰는 요약은 직접 묻고, 아니면 호스트가 후속 작업 질문(다음 행동 3개, 1번이 추천, 마지막에 ✏️ 직접 입력)을 올리며, 그 질문이 카드를 NEEDS YOU에 둔다. 이후 요약에 ⚠️ 줄이 없거나 `/new`를 하면 후속 작업이 풀리고 열린 질문은 거둬진다. 다만 아래 두 가지에는 ⚠️ 줄을 붙이지 않으므로, 끝난 세션이 이것 때문에 기다리지는 않는다.
- **넘기기용 후속 이슈:** 범위 밖 작업을 맡기려고 등록한 이슈다. 등록하고 링크하면 완료로 본다.
- **사용자가 그만하거나 건너뛴 단계:** "여기까지해", "그건 생략" 같은 경우다.

이 요약은 soma-work 하네스 스킬 `local:auto-es`다: 턴 종료 요약은 그 턴 종료 규칙으로 돌고, 모델이 (`es` 대신) 실행하면 같은 TL;DR을 카드에 직접 쓴다(`UPDATE_SESSION { executiveSummary: { tldr } }`, 이슈·PR·문서 링크와 상태도 함께).

**다음 행동 버튼**(#1199): 턴이 끝나면 그 답변이 끝에 단 다음 행동 — Executive Summary의 Next Actions, 단계마다 무엇을 하는지 한 줄과 그 명령의 코드 블록 — 이 펼친 작업 카드(카드가 묻는 것 아래에 세로로)와 디테일 카드의 입력창 바로 위 줄에 버튼으로 나온다. 권장(`(권장)`, `(recommended)`) 단계는 진한 버튼이다. 한 번 누르면 그 단계의 명령이 입력창으로 보낼 때와 똑같이 내 지시로 간다: 대화에 내 턴으로 남고, 남의 작업이면 소유자 승인을 기다리고, 그 답변의 버튼은 사라진다. 턴이 도는 동안, 작업이 다른 것(질문·권한·시작할 계획·목표 결정)을 묻는 동안, 끝났거나 휴면인 작업, 지시할 수 없는 사람에게는 나오지 않는다. 서버가 답변에서 단계를 읽어(`src/conversation/next-actions.ts`) 턴에 `nextActions`로 실어 보낸다. 답변 원문은 여전히 보드로 가지 않는다.

**followup 바**(#983): 작업 카드가 완료됐거나 응답을 기다리면, 아직 열려 있는 연결 이슈·PR(열림·초안 PR, 열린 GitHub 이슈, 완료도 취소도 아닌 Jira 이슈)이 카드 타이틀바 바로 밑에 한 줄씩 그레이디언트 글자로 보인다 — 최대 다섯 줄, 그 뒤는 `외 N개`. 줄을 누르면 대시보드를 떠나지 않고 아티팩트 뷰어에서 그 이슈를 읽는다: 제목·상태·라벨·본문·최근 댓글 다섯 개(카드 주인과 관리자만, 다른 사람은 카드에 보이는 번호·제목·상태만)와 **GitHub에서 열기**. 대시보드는 링크의 owner·repo·번호로 GitHub API를 부르고, 그 카드의 링크만 읽는다(`GET /api/dashboard/session/:key/link-embed?url=…`). 뷰어를 닫으면 누른 줄이 이 브라우저에서 그 카드에서 사라지고, 그 이슈가 나중에 닫혔다가 다시 열리면 다시 보인다. 실행 중·휴면·보관 카드에는 바가 없다.

### 📎 대시보드의 지시 첨부

지시와 함께 보낸 파일(스크린샷, PDF, 텍스트, 음성, 영상)이 웹 대시보드에서 그 지시와 함께 보인다. 모델 산출물과 섞이지 않는다. 세션 패널에서는 지시 글 위에 놓인다(80px 이미지 타일, 4개를 넘으면 "+N", 종류·크기가 있는 파일 카드, 음성은 그 자리에서 재생). 펼친 카드의 지시 행에는 작게, 카드 앞면에는 클립 아이콘과 개수가 나오고, 패널 공통 서피스의 "지시 첨부" 줄(기본은 접힘)에 세션의 모든 파일이 모인다. 누르면 산출물과 같은 뷰어가 열리고 그 지시의 파일끼리 넘겨 본다. 모델이 일하는 중에 보낸 메시지는 모델이 읽은 시점에 파일과 함께 기록된다. 영상과 음성도 사본을 남겨 대시보드에서 재생된다. 봇이 받지 못한 파일(50 MB 초과, 다운로드 실패)도 Slack 링크와 함께 표시된다. 업로드된 HTML·SVG·텍스트는 대시보드에서 실행되지 않는다.

### 🧾 직접 입력하지 않은 턴은 한 줄로

세션 패널 대화창, 작업 로그, 인박스 카드를 펼쳤을 때의 지시 / 응답에서 soma-work가 스스로 보낸 턴은 원본 프롬프트 대신 **System** 이름과 톱니 아바타로 한 줄로 보인다(유저 이름이 아니다) — 언제, 뱃지, 무엇을 했는지: **자동 압축** / **압축** (`/compact`), **시스템 재시작**, **자동 재시도**(오류 뒤), **Goal #2/10**(goal continuation), **크론**(cron 실행), **세션 갱신**(`/renew` 저장·불러오기), **백그라운드 재개 #1/6**(백그라운드 작업이 아직 돌고 있어 턴을 이어 간 경우), 그 밖의 호스트 턴은 **자동 입력**. 줄을 누르면 세부 사항과 원본 프롬프트가 펼쳐진다. 압축이 도는 동안은 경과 시간과 예상 시간(대화의 직전 압축 시간, 없으면 2분 30초), 진행률 막대를 보여 주고, 끝나면 압축 전 → 후 토큰과 걸린 시간을 보여 준다. 지시가 발동한 스킬(`$skill`, autoskill)은 지시 아래 뱃지로 보인다 — `local:using-ssot · ≈1.1K tokens`(추정치). 뱃지를 누르면 그 스킬 본문이 펼쳐진다. 인박스 카드에서는 압축이 도는 동안의 진행률과 끝난 뒤의 결과가 응답 자리에 보이고, 펼친 줄이나 스킬은 카드가 다시 그려져도 펼쳐진 채로 남는다. 예전 턴은 텍스트로 판별한다. 이 변경 전에 기록된 `/compact`는 누가 보냈는지 남아 있지 않아 **압축**으로 보인다.

이런 턴이 아무것도 바꾸지 않았으면 — 조건이 아직 안 된 크론 점검, 고칠 것이 없는 리뷰 메시지 — 메시지 없이 끝난다. 모델이 그 침묵 대신 자리표시 문구만 쓰면(`(no message)`, `(no content)`, `No response requested.`, `(응답 없음)`) 스레드에 아무것도 올라가지 않고 작업 로그에도 그 턴의 응답이 남지 않는다. 자리표시 문구를 언급만 하는 글은 평소처럼 올라가고, 사람이 시작한 턴은 자리표시 문구여도 그대로 답이 올라간다.

### 🖥️ 웹 대시보드

대시보드(`/dashboard`, Slack 로그인)는 모든 세션을 카드로 보여주고, 세션 소유자가 바로 조작할 수 있게 한다.

- **표시 언어 (en / ko)**: 기본은 한국어입니다. 위쪽 막대 오른쪽 끝의 **EN | KO** 토글, 슬랙의 `lang en` / `lang ko`, 설정 화면의 표시 언어 행이 유저마다 하나인 같은 설정을 바꿉니다. 대시보드, 슬랙 스레드의 봇 문구, 모델의 답변이 이 언어를 씁니다. 세션의 첫 지시 맨 아래에 `<display-lang>ko</display-lang>`가 붙고, 언어를 바꾸면 다음 지시에 다시 붙습니다. 번역은 서버에서 나가는 곳(슬랙 Web API 호출, `respond()`, 대시보드 페이지와 JSON 오류)에서 `packages/common/src/i18n-catalog/`의 영어 카탈로그로 합니다. 아직 영어가 없는 한국어 문구는 `npm run i18n:extract`로 확인합니다.
- **미니멀과 어드밴스드 화면**: 대시보드는 **미니멀** 모드로 열린다. 보드 카드는 종류 표시(일반 작업은 체크, 에픽은 **EPIC**, 크론 실행은 **CRON**), 제목, 상태와 시간, 진행 중 작업, 묻는 질문, 만든 파일 한 줄, 그리고 맨 아래 오른쪽에 비용과 모델만 보여 준다. 모델은 아이콘으로만 나온다. 회사 마크(Claude, OpenAI, Grok, Gemini, 그 밖은 칩 아이콘)를 그 회사 대표색(Claude 클레이, Gemini 파랑, OpenAI·Grok 검정)으로 칠하고, 옆에 추론 강도 게이지(막대 1–5칸, 매우 높음은 빨강, 최대는 금박, 울트라는 홀로그램)를 둔다. 이름과 추론 강도는 툴팁과 화면 낭독기로 알려 주고, 상세 카드는 지시(전송) 버튼 옆 모델·추론 강도 선택기에 모델 이름을 보여 준다. 같은 회사 마크가 모델 선택기 타일(이름 첫 글자 대신), 에이전트 트리, 세션 패널의 에이전트 탭에도 나온다. 에이전트 트리와 탭에서 메인은 세션 모델(메인 탭은 id가 아니라 "Opus 5.5 (1M)" 같은 이름으로), 서브에이전트는 실제로 실행된 모델을 표시한다. 펼친 카드는 액션과 입력이 필요한 것만 남긴다. 상세 카드는 위쪽에 머리와 입력 필요만 두고 나머지를 작업 목록과 채팅에 준다. 통계 줄, 기본 모델·추론 칩, 사용자를 고른 뒤의 보드 사용자 선택은 물러난다. CRON 줄과 LLM 가용량은 두 모드 모두에 보인다(답을 기다리는 크론 실행은 그 잡의 카드로 거기 있고, LLM 가용량은 접힌 칩으로 시작한다). 상단바 오른쪽 끝 **어드밴스드**를 켜면 아래 내용이 모두 다시 보인다. 선택은 유저마다 저장된다(`dashboardMode` 설정, 설정 페이지에도 있음). 스펙: [`.prd/19-dashboard-view-mode-spec.md`](../../../.prd/19-dashboard-view-mode-spec.md).
- **크론 잡 내용 보기·편집·지금 실행·삭제** (#1080): CRON 줄의 잡 타일을 누르면 서랍이 열린다(스케줄, 다음 실행, 실행 방식, 남아 있는 실행 기록). 잡 소유자나 관리자 모드를 켠 관리자에게는 서랍 맨 위, 사실 목록 위에 동작 한 줄이 있다: **지금 실행**과 **편집**, 그리고 끝에 떨어져 위험 색으로 **삭제**. 다른 사람에게는 이 줄이 없다. 지금 실행과 삭제는 되돌릴 수 없어서 한 번 묻는다 — 첫 번째 누름은 버튼을 4초 동안 **한 번 더 눌러 실행** / **한 번 더 눌러 삭제**로 바꾸고 줄 바로 아래에 무슨 일이 일어나는지 한 줄로 말한다. 두 번째 누름이 실행한다(0.4초 안의 두 번째 누름은 더블클릭이라 세지 않는다). 지금 실행은 예약 실행과 같은 길로 스케줄러가 잡을 실행하고(실행 방식·출력·모델 그대로, 소유자로) 누가 눌렀는지 기록한다. 서랍은 스케줄러가 한 일(잡의 세션에서 실행, 그 세션 뒤에 대기, DM 전송, 스레드 답글)이나 실행이 시작됐다는 것을 말하고, 실행은 일어나는 대로 보드와 실행 기록에 나타난다. 삭제는 잡을 지운다 — 스케줄러가 다시 실행하지 않는다 — 서랍을 닫고 토스트로 알린다. **편집**은 짧은 사실에서도 한 번에 된다: 잡 전체를 불러와 폼을 연다. 같은 사람에게 **내용 보기**가 있다. 프롬프트를 포함한 모든 항목을 보여 준다: 스케줄과 그 식(UTC), 다음 실행, 프롬프트, 채널, 스레드, 실행 방식, 출력, 모델, 수동 실행 허용, 소유자, 만든 때, 스케줄 바꾼 때, 마지막 실행. **편집**을 누르면 이름, 스케줄(5칸 cron 식, UTC), 프롬프트, 채널 ID, 실행 방식, 출력, 모델(직접 입력이면 모델 ID)을 고치는 폼이 된다. 서버는 Slack 편집 모달과 `cron_update`와 같은 규칙으로 검사한다. 채널을 옮기면 스레드 연결이 풀리고, 스레드 답글은 잡에 이미 연결된 스레드가 있어야 한다(대시보드에서는 스레드를 고를 수 없다). 그 밖의 사람에게는 프롬프트가 보이지 않고, 누가 볼 수 있는지 한 줄만 보인다. 스케줄러가 1분마다 잡을 다시 읽으므로 바꾼 내용은 다음 분부터 적용된다. API: `GET /api/dashboard/cron/:id`, `PATCH /api/dashboard/cron/:id`, `POST /api/dashboard/cron/:id/run`(4초 안에 스케줄러가 한 일을 답하고, 아니면 202 — 실행은 계속된다), `DELETE /api/dashboard/cron/:id`(소유자, `X-Admin-Mode: on`인 관리자, 뷰어 토큰. 쓰기는 모두 CSRF 필요).
- **폰에서는 화면을 내용에 준다**(좁은 화면, 또는 가로로 든 폰): 상단바는 한 줄이다 — 승인, 관리자, 보드 사용자 선택은 상단바에서 보드 머리로 옮겨 보드와 함께 스크롤된다. 640px 미만에서는 엄지가 닿는 아래쪽에 탭 바가 있다(@2lab.ai/ui `<ui-dock>`): 보드(응답이 필요한 실행 수), 대화, 새 작업(가운데 솟은 +), 설정, 기억 — 그 화면에서는 상단바의 메뉴와 플로팅 새 작업 버튼을 대신한다(가로로 든 폰은 메뉴를 그대로 쓴다). 보드 머리는 두 줄이다: 카드 검색과 보드 | 목록, 그 아래 칩(사용자, 관리자, 필터, 정렬 …)이 줄바꿈 대신 옆으로 넘기는 한 줄이다. 상세 카드는 열 때와 머리가 다시 나올 때 제목 전체를 보여 준다(세 줄까지, 긴 URL도 줄을 바꾼다). 대화나 작업 로그를 스크롤하는 동안에는 제목바가 상단바와 같은 높이의 한 줄이 되고, 제목바와 대화 · 작업 로그 탭만 남는다. 상태 줄과 탭 줄은 그 아래로 스크롤되어 나가고, 대화와 작업 로그를 오가도 그대로이며, 제목바나 그 안의 ˅ 버튼(카드 위쪽 보이기 — 읽는 동안에만 보여서 키보드로도 부를 수 있다)을 누르거나 기록의 처음까지 올라가면 다시 나온다. 입력창은 대화나 작업 로그를 거슬러 스크롤하는 동안 아래로 미끄러져 사라졌다가 맨 아래에 닿으면 다시 나오고, 그사이 오른쪽 아래의 ^ 버튼으로 바로 불러올 수 있다. 세션의 모델·추론 강도 선택기는 입력창 줄의 전송 버튼 왼쪽에 있다 — 입력창의 `end` 슬롯이 자리를 잡고, 그 줄에서는 제조사 마크와 추론 강도만 보인다. 브라우저 검증: `scripts/screenshot-mobile-chrome.ts`.
- **화면 구성안 (1 · 2 · 3안)**: 미니멀과 어드밴스드의 카드 면 · 펼친 카드 · 상세 카드, 6개 화면에 무엇을 보여 줄지는 설정 페이지에서 고르는 안을 따른다(**대시보드 › 화면 구성안**, `dashboardPlan` 설정). 기본은 1안이다. 미니멀 1안은 카드 맨 아래에 PR을 더하고, 요약 줄은 입력이 필요할 때만 보여 준다. 펼친 카드에는 링크와 모델 전환이 있다. 2안은 진행 상황(진행 n/m, 작업 창, 서브에이전트 탭)을 보여 주고, 어드밴스드 2안은 안을 만들기 전 화면 그대로다. 3안이 가장 가볍다. 미니멀에서는 카드가 제목 · 상태 · 비용 · 모델뿐이고 상세 카드의 작업은 한 줄로 접힌다. 어드밴스드에서는 숫자가 맨 아래 줄로 가고, 펼친 카드는 조작만 남기고, 상세 카드는 접힌 채 열린다. 어느 안이든 승인 · 질문 · 중지 · 입력창은 남는다. 칸별 표가 있는 스펙: [`.prd/20-dashboard-view-plans-spec.md`](../../../.prd/20-dashboard-view-plans-spec.md).
- **변경점 탭 (.prd/26)**: 상세 카드의 대화 · 작업 로그 옆 **변경점** 탭이 세션이 코드에 한 일을 보여 준다. 위에서부터 요약(레포 수 · 파일 수 · +/− · 기준 시각, 새로 고침), 범위 칩(전체 · 커밋 안 함 · 커밋함 · PR · 머지됨 — 네 층은 겹치지 않는다: 커밋함은 아직 어느 세션 PR에도 없는 커밋, PR · 머지됨은 세션 시작 뒤 만든 PR만), 세션 **이슈 트리**(.prd/29: 세션의 이슈 — GitHub · Jira, 또는 이 세션에만 있는 내부 이슈 — 아래에 그 PR들. 모든 세션은 이슈를 하나 이상 갖고 루트 PR은 없다. 자식이 있는 노드는 접히고 머리 줄은 트리 전체를 접는다. PR 줄을 누르면 그 PR 하나가 범위, ↗는 원본), 그리고 레포 → 디렉터리 → 파일 트리(자식이 하나뿐인 디렉터리는 `src/conversation`처럼 한 줄로 접고, 줄마다 +/−와 층 표시). 파일을 누르면 뷰어가 두 모드 중 하나로 열린다. 데스크톱에서 옆에 붙은 상세 카드 옆(카드가 왼쪽에 붙으면 오른쪽)이 640px 이상이면 보드 자리에 파일만 띄우는 **패널**이다. 층마다 GitHub처럼 hunk와 이전 · 새 줄 번호가 나오고, 파일은 상세 카드의 트리가 강조하고 고른다. 아니면 화면 전체를 덮고, 왼쪽에 같은 트리가 나온다(지금 파일 강조, 좁은 화면에서는 "파일 목록" 버튼). **전체 화면** · **패널로** 버튼으로 연 파일 그대로 모드를 바꾸고, 기기는 전체 화면 선택을 기억한다. 창이 패널에 좁아지면 전체 화면이 된다. ‹ ›로 이전 · 다음 파일, Esc는 뷰어만 닫고 누른 줄로 돌아간다. 턴이 끝날 때마다 다시 모으고, 탭을 열면 살아 있는 세션은 그 자리에서 한 번 더 모은다. 세션 소유자와 어드민만 본다(작업 로그와 같다). 저장소 설정이 명령을 부르게 되어 있으면(filter · textconv · gpg 등) 그 체크아웃은 읽지 않고 이유를 보여 준다. 모델은 UPDATE_SESSION으로 이슈 트리를 고치고(이슈 · PR 추가의 `parent`, `add_internal`, `move`), 호스트는 GitHub가 알려 주는 관계로 자리를 정한다(PR이 닫는 이슈, 쌓인 PR, 하위 이슈의 부모). 스펙: [`.prd/26-session-code-changes-spec.md`](../../../.prd/26-session-code-changes-spec.md), [`.prd/29-session-issue-tree-spec.md`](../../../.prd/29-session-issue-tree-spec.md).
- **프로세스 — 작업의 Claude Code가 머신을 얼마나 쓰나**: 작업 하나가 Claude Code 프로세스 하나(Agent SDK의 자식)를 돌리고, 그 프로세스가 띄운 셸 · MCP 서버 · 테스트 러너 · 백그라운드 작업은 모두 그 아래에서 돈다. 디테일 카드의 세부 오른쪽 **프로세스** 탭은 모든 프로세스를 트리로 보여 준다(htop처럼 `├─ └─ │` 가이드, 부모를 접으면 그 아래 합계). 이름 · CPU · 메모리(각각 뱃지 하나, 채움이 사용량)가 나오고, 줄 아래에 PID · 상태 · **작업 폴더** · **하는 일**(미리보기: 프로그램, `npm run build` · `git status` 같은 하위 명령, 아는 플래그. 값은 잘라냄)이 있다. 위에는 노드 줄(노드 id · 코어 수 · 노드 CPU 사용 · 여유/전체 메모리)이 있다. CPU는 세 단계로 읽힌다: 코어 1% 미만은 흐리게, **10% 이상은 주황 굵게**, **100% 이상(코어 1개 넘김)은 빨강 · ▲ · 같은 뱃지 안의 코어 수(`▲ 475% · 4.8코어`)와 빗금 테두리 · 빨간 줄**. 작업 폴더와 명령은 작업 소유자와 관리자에게만 보인다. 그들은 줄을 눌러 그 프로세스를 자세히 본다 — **스냅샷**이라 한 번 읽고 타이머로 새로 고치지 않는다(다시 찍기로 다시 읽음): 실행 파일, 비밀 값을 가린 전체 명령줄(JSON · 비밀 이름의 플래그와 변수 · 인증 헤더 · URL 비밀번호 · 키 모양), 작업 폴더, 사용자, 시작 시각, 부모 체인, CPU 시간, 우선순위, 스레드, 메모리, 열린 파일 · 소켓, 자식 프로세스(`GET /api/dashboard/session/:key/processes/:pid/detail?start=`). 트리가 살아 있는 동안 작업 카드 머리에는 **노드 뱃지** 하나가 붙고, 한 줄로 접은 카드에도 남는다: 노드 이름과 **이 작업의** CPU · 메모리를 10단계 계급장 막대 두 개로(거의 놀면 녹색 한 칸, 꽉 차면 빨강). CPU는 코어 1개(100%, `top`과 같은 계산, 기본 한도)에서 가득 차고 한 칸이 코어 10%다. 메모리(각 프로세스 상주 메모리의 합)는 노드 메모리를 코어 수로 나눈 몫에서 가득 찬다. 뱃지에 숫자는 없다: 코어 1개를 넘으면 뱃지가 빨간 단색으로 바뀌고, 숫자 · 일시중지 수 · 한도는 툴팁에 나온다. 코어 1개를 넘으면 카드 전체가 프로세스 탭의 CPU 뱃지처럼 바뀐다: 은은한 빨간 채움과 빨간 테두리, 오른쪽으로 흐르는 밑변의 가는 빗금, 노드 뱃지 바로 앞의 Slack `:alert:` 사이렌, 빨간 단색 노드 뱃지. 코어 2 · 4 · 8개를 넘을 때마다 한 단계씩 진해진다(채움과 테두리가 진해지고, 빗금이 굵어지며 더 빨리 흐른다. 동작 줄이기에서는 멈춰 있다). 그래서 CPU를 많이 쓰는 작업은 보드 멀리서도 보인다. **작업별 CPU 한도**: 작업 하나는 그 주인의 한도까지만 CPU를 쓴다 — 기본 100%(코어 1개), 관리자는 무제한. 관리자가 설정의 작업 큐 탭에서 사람마다 정한다(CPU 한도: 기본값 · 50–800% · 무제한, `PUT /api/settings/cpu-limits/:userId`). macOS도 Linux도 데몬이 이미 도는 트리에 거는 할당량을 주지 않아서, 한도를 넘은 작업은 듀티 사이클로 맞춘다: 주기마다(250ms, `ps`가 느리거나 몫이 작으면 최대 30초) Claude Code 아래 프로세스가 한도만큼의 몫만 돌고 나머지는 멈춘다(`SIGSTOP`). Claude Code 자체는 멈추지 않고, 사람이 누른 일시중지는 건드리지 않으며, 중지 · 한도 변경 · 종료 때 멈춘 것을 모두 이어 실행한다. 맞추는 동안 탭에 `CPU 한도 100% · 맞추는 중`이 뜨고, 잡힌 프로세스는 일시중지가 아니라 `한도`로 보인다. 작업 소유자나 관리자 모드의 관리자에게는 줄마다 **일시중지**(`SIGSTOP`)와 **재개**(`SIGCONT`)가 있다. Claude Code 프로세스 자체를 멈추면 재개할 때까지 작업 전체가 멈춘다. 일시중지 요청은 PID와 그 시작 시각을 함께 보내고, 서버는 그 프로세스가 지금 이 작업의 트리에 그 시작 시각으로 있을 때만 신호를 보낸다 — 운영체제가 다른 프로그램에 다시 준 PID는 건드리지 않는다. 작업을 중지하면 멈춰 둔 프로세스를 이어 실행해 중지가 끝까지 닿게 한다. 부모가 끝난 프로세스도 그 작업에 남는다(모니터가 본 것을 기억한다). 모니터는 프로세스가 있는 작업이 하나라도 있으면 5초마다 수집하고(macOS · Linux의 `ps`), 뱃지가 바뀐 카드만 푸시한다. 탭은 열려 있는 동안 3초마다 `GET /api/dashboard/session/:key/processes`를 읽는다. 어드민은 스케줄러가 볼 모양 그대로 노드를 `GET /api/dashboard/nodes`로 읽는다(가용량과 작업별 합계). 모양이 노드 단위라 나중에 워커 노드가 같은 스냅샷을 보고하면 된다. **설정 › 작업 워커**(어드민)는 작업이 도는 머신 — 지금은 이 soma-work가 설치된 노드 하나, 나중에는 워커 노드 전부 — 을 플랫폼 · 코어 · 메모리 · 사용 중 CPU · 그 위에서 도는 작업과 프로세스 수와 함께 보여 주고, 머신마다 **닉네임**(1~24자, 관리자 모드)을 붙인다. 그러면 카드의 노드 배지와 프로세스 탭의 노드 줄에 노드 id 대신 닉네임이 나오고(id는 배지 툴팁에 남는다), 긴 호스트 이름이 짧게 읽힌다. 카드는 다음 샘플에 바뀐다(`GET /api/settings/workers`, `PUT /api/settings/workers/:nodeId/nickname`, 저장 `DATA_DIR/worker-nicknames.json`). 코드: `src/process-monitor/`, 결정: [ADR 0003](../../adr/0003-session-process-monitor.md).
- **대시보드 화면 편집기**: 설정의 새 탭이다. 유저마다 태스크 카드(접힘과 펼침은 따로), 디테일 카드, 슬랙 스레드 헤더("스레드 태스크 카드")를 고친다. 디테일 카드는 구역별로 고친다: 타이틀 바(시간 오른쪽의 모델 · 비용 · 토큰 · tok/s · 컨텍스트 · 소유자 · 워크플로, 각각 켜고 끔), 입력 필요(항상 그 바로 아래), 탭 바(어느 레이아웃이든 맨 앞 작업 계획 · 맨 끝 사용자 작업, 그 사이에 목표 · 작업 · 에이전트 · 산출물 · 세부 · 프로세스와 그 숫자 — 누른 탭의 내용만 열림), 아래(대화 · 작업 로그). 미리보기는 보드의 카드 코드가 그대로 그린다. 화면이 보여 줄 수 있는 항목이 모두 나열된다. 스위치로 켜고 끄고, 손잡이를 끌거나 ↑ ↓로 순서를 바꾼다. 항상 보이는 것은 잠금으로 표시된다. 1 · 2 · 3안은 고칠 수 있는 프리셋이다. 태스크 카드와 디테일 카드가 각각 기본 안을 고르고, "한 번에"로 둘을 같이 바꾼다. 바꾸면 바로 저장되고, 되돌리기와 "이 화면 기본값으로"가 있다. 스레드 카드는 기본으로 태스크 카드를 슬랙에서 따라간다(소유자, 현재 작업, 비용, 모델, 카드가 연결을 보이면 링크 기록). 따로 설정하거나 서버의 `ui.threadheader` 테마를 쓸 수도 있다. 유저별 `dashboardLayout`에 저장된다(`GET/PUT /api/settings/dashboard-layout`). 스펙: [`.prd/21-dashboard-surface-editor-spec.md`](../../../.prd/21-dashboard-surface-editor-spec.md).
- **디테일 카드 위치 — 왼쪽 · 오른쪽과 잠금**: 840px 이상에서 디테일 카드는 보드 옆에 붙고, 따로 고르지 않으면 오른쪽이다. 설정 › 대시보드 화면 › **디테일 카드 위치**에서 대시보드 그림 두 장(왼쪽에 붙은 카드, 오른쪽에 붙은 카드)으로 쪽을 고르고 **위치 잠금**을 켜고 끈다. 잠금이 꺼져 있으면(기본) 디테일 카드 상단바 가운데 위에 손잡이가 있다. 손잡이(또는 상단바의 빈 곳)를 끌면 카드가 떠올라 포인터를 따라오고, 두 자리가 칸으로 보이며 놓일 칸에 불이 들어온다. 놓으면 카드 가운데가 있는 쪽으로 미끄러져 붙고(빠르게 던지면 던진 쪽), 보드 카드들도 반대편으로 함께 옮겨 간다. 가운데를 넘기 전에 놓거나 Esc를 누르면 제자리로 돌아간다. 손잡이를 누르거나 손잡이에서 ←/→ 키를 눌러도 옮겨진다. 옮기면 토스트가 어디로 갔는지 알려 주고 실행 취소를 준다. 잠금이 켜져 있으면 손잡이가 없고 상단바를 끌어도 움직이지 않는다 — 설정에서만 바뀐다. 840px 미만에서는 전체 화면 시트라 손잡이가 없다. 위치는 `dashboardLayout`의 `panel`(`{ side: 'left' | 'right', locked }`)이다. 두 페이지 모두 `PUT /api/settings/dashboard-layout/panel`로 위치만, 그것도 바꾼 필드만 저장한다(드래그는 쪽, 설정의 각 컨트롤은 자기 필드). 그래서 드래그와 편집기가 서로를 덮어쓰지 않는다 — 설정에서 켠 잠금은 늦게 도착한 드래그에도 남고, 잠금 토글은 카드를 되돌리지 않는다. 서버는 위치를 쓸 때마다 번호(`rev`)를 붙이고, 모든 페이지와 공유 캐시는 번호가 가장 큰 위치만 받아들인다 — 늦게 온 응답이나 읽기, 다른 탭의 옛 복사본은 더 새로운 위치를 이기지 못한다. 위치가 빠진 레이아웃 전체 저장은 저장된 위치를 그대로 둔다. 브라우저 검증: `scripts/screenshot-panel-place.ts`.
- **작업 카드의 연결**: 모든 작업 카드가 기본으로 현재 작업 바로 아래에 연결된 이슈(Jira, GitHub)와 이슈 상태, 연결된 PR과 머지 상태(열림 · 초안 · 머지됨 · 닫힘), 연결된 위키(Confluence, Notion 등 문서)를 보여 준다. 지금 이슈 · PR · 위키가 먼저 온다. 상태는 슬랙 스레드의 실시간 PR 확인, 링크 메타데이터 캐시(전체 예산 안에서 백그라운드로 갱신, 머지된 PR은 다시 가져오지 않음), 링크에 기록된 상태 순으로 고르고, 하나라도 머지면 머지됨이다. 칩을 누르면 그 페이지가 새 탭으로 열리고 카드는 열리지 않는다. 이 줄은 모든 프리셋에서 켜져 있고, 화면 편집기에서 끄거나 옮길 수 있다. 같은 PR을 보여 주던 맨 아래 PR 칩은 기본으로 꺼진다. 링크는 대화에서 저절로 기록된다. 매 턴 유저 메시지에 나온 이슈 · PR · 위키, GitHub 쓰기로 방금 만든 PR · 이슈(`gh` · `gh api` · `curl` · `fetch` · GitHub MCP 도구 무엇으로 만들었든, 호출 자신의 결과에서 후보를 고르고 GitHub가 확인한 것 — 그 턴이 시작된 뒤 그 호출의 결과까지 만들어졌거나 머지 · 닫혔고, 호출이 head 브랜치나 제목을 적었다면 그것이 그 PR · 이슈의 것이어야 한다. 머지 · 닫기는 카드에 이미 있는 링크의 상태를 바꾼다), 답변에 나온 링크다. 매 턴이 끝나면 호스트가 세션 자신의 브랜치(세션 디렉터리 아래 git 체크아웃마다)에 어떤 PR이 있는지 GitHub에 묻는다. 그래서 웹 UI나 다른 도구로 만든 PR도 카드에 오른다. 세션이 시작된 뒤 만든 PR은 지금 PR이 되고, 그보다 오래됐거나 다른 세션도 체크아웃한 브랜치의 PR은 기록에만 들어간다. 그 PR이 닫는 이슈도 기록에 들어간다. 답변에 나온 링크는 지금 링크를 바꾸지 않는다. 스펙: [`.prd/22-task-card-links-spec.md`](../../../.prd/22-task-card-links-spec.md).
- **모델에 따른 작업 카드 테두리**: 카드 테두리가 그 작업을 돌리는 모델을 알려 준다. Sonnet과 여기 적지 않은 모델(Grok, Haiku)은 지금처럼 1px 테두리다. Opus와 Sol은 2px에 더 밝은 테두리다 — 다크 테마에서는 더 밝게, 라이트 테마에서는 더 진하게 보인다.   - **상태 웨이브**: 카드 상태가 바뀌면 상태 표시에서 새 상태 색의 고리가 퍼진다. Fable 카드는 요란하다: 렌즈, 빨려 들었다 터지는 박자, 입자, 그리고 카드가 새 열에 내려앉을 때까지 남는 테두리 빛(약 1.2–2.5초, →대기·→완료·→실행은 스펙트럼 색). 다른 모델은 살짝: 색만, 약 1.1–1.4초, →휴면은 없음. 보드에서 동시에 최대 4개(요란한 것은 2개), 변경이 3개를 넘게 몰리면 재생하지 않고, 요란한 웨이브는 카드마다 30초에 한 번, 150ms 간격으로 나온다. 동작 줄이기 설정에서는 잠깐 테두리 색만 바뀐다. 모델은 단어 단위로 본다(`fable`은 되고 `fabled`는 아님). 조사: [`docs/misc/research/2026-11-21-libraries-effects-status-wave-intensity.md`](../research/2026-11-21-libraries-effects-status-wave-intensity.md), 코드: `src/conversation/card-finish-client.ts`의 `cardWaveOf`, 검증: `scripts/screenshot-status-wave.ts`.
  - **시작 중 카드**는 세션이 될 때까지 테두리를 빛줄기가 돈다.
  - **상세 카드 머리**에 카드의 얼굴(`<ui-bot-avatar>`)이 있다: 모델 계열마다 하나(Fable 별, Opus 드로이드, Sonnet 구름 …), 턴이 도는 동안 일하고 세션이 잠들면 잔다.
  - **대화의 작성 중 줄**은 에이전트가 마지막으로 쓴 도구를 따라 움직이는 생각 오브다(읽기·검색, 편집, 명령 실행, 에이전트 시작, 계획, 커넥터 호출) — 메인 에이전트와 실행 중인 서브에이전트 모두. 상세 카드에서 보낸 지시라면 모델이 그 지시를 받은 뒤에만 이 줄이 뜬다.
  - **내 지시가 지금 어디 있는지** (#1466): 상세 카드에서 보낸 지시 위에는 서버가 그 지시를 어떻게 처리했는지 보여 주는 칩이 붙는다. 칩은 서버가 단계를 알려 줄 때마다 바뀐다: 보내는 중(브라우저가 아직 서버 응답을 못 받음) → 접수됨(서버가 받음) → 승인 대기(다른 사람의 작업이라 소유자 승인을 기다림) / 작업 큐 대기 · N번째(내 다른 작업이 끝날 때까지 작업 큐가 붙잡음) / 시작 안 함(같은 작업이 다른 스레드에서 이미 진행 중) → 처리 중(턴을 시작하는 중) → 모델이 받았어요(모델이 프롬프트를 받음), 또는 모델에 전달되지 않았어요(모델이 받기 전에 실행이 끝남). 답이 오거나 실행이 끝나면 칩이 사라진다. 지시마다 단계를 따로 기록하므로, 승인이나 작업 큐에서 기다리는 지시가 둘이면 각자 자기 단계를 보여 준다. 실행 중인 턴에 보낸 메시지는 지금처럼 큐 칩(대기 중 · 처리 중 · 반영됨)을 쓴다. 단계 기록은 서버 메모리에만 있어서, 재시작하면 그 전에 보낸 지시에는 단계가 보이지 않는다.
  - **상세 카드의 다음 행동** 버튼은 한 액체의 방울이다(`<ui-gooey>`): 새 답변의 버튼이 한 방울에서 갈라져 나오고(답변마다 한 번), 누른 버튼이 보내지면서 나머지를 빨아들인다. 버튼은 그대로 진짜 버튼이다.
  - **진행 중인 전화 통화 보기**에는 통화 기록을 따라 움직이는 보이스 링(`<ui-voice-ring>`)이 있다: 거는 중이거나 상대가 말한 뒤에는 생각 중, 에이전트 음성이 나가는 동안은 말하는 중, 그 밖에는 듣는 중. 통화가 끝나면 사라진다.
  - **산출물 뷰어**는 큰 이미지를 불러오는 동안 그림이 되는 픽셀 모자이크 로더를 그린다(캐시된 이미지는 바로 보인다). **입력창**은 음성 메모를 녹음하는 동안 목소리를 따라 빛난다.
  - **로그인**: `/login`과 계정 전환 페이지의 soma-work 글자는 리퀴드 메탈(`<ui-metal-text>`)이다. WebGL2나 JavaScript가 없거나 동작 줄이기 설정이면 그냥 글자다.
  - 일부러 쓰지 않은 것: Magnetic(포인터 모드는 촘촘한 보드에서 정밀한 포인팅을 끌어당기고, 터치에서는 아무것도 하지 않는다)과 Voice position(스테레오 마이크가 필요한데 브라우저 마이크는 모노이고 통화 음성은 서버에 있다). 이펙트별 자리와 이유: [`docs/misc/research/2026-11-21-libraries-effects-dashboard-spots.md`](../research/2026-11-21-libraries-effects-dashboard-spots.md).
- **보드 필터와 정렬**: 모든 카드 하단에 작업이 어디서 진행되는지 나온다 — 레포(그 작업의 PR·이슈의 레포, 없으면 채널에 연결된 레포가 하나일 때 그 레포)와 채널(`#이름`, `DM`, Slack 스레드가 없는 작업은 대시보드). 비공개 채널은 이름과 채널에 연결된 레포 없이 비공개 채널로만 나온다. **비공개 작업(#1315)**: Slack 대화를 모두가 읽을 수 없는 작업 — 비공개 채널, 봇과의 DM, 봇이 공개라고 확인하지 못한 채널(그룹 DM, 봇이 나간 채널, 재시작 직후 채널 목록을 읽기 전의 모든 채널) — 은 작업 주인과 관리자만 본다. 카드 제목 앞에 🔑가 붙고(상세 카드 제목에도, 마우스를 올리면 이유), 다른 사람에게는 카드도 실시간 갱신도 대화 목록·크론 레인 항목도 없고 그 작업의 주소는 404로, 없는 작업처럼 답한다. 관리자는 관리자 모드 없이 읽는다. 주인이 아닌 사람이 비공개 작업에 지시하려면 관리자 모드의 관리자여야 한다(DM과 같은 규칙). 공개 채널 작업은 전처럼 모두에게 보인다. 둘 다 카드 면의 **레포** · **채널** 칩이고, 모든 기본 화면 구성안에서 켜져 있으며 화면 편집기에서 끌 수 있다. 보드 머리의 보관함 · 휴면 오른쪽에 **내 카드만**(내가 시작한 카드만, 로그인한 상태로 모든 사용자 보드에서), **필터**(보드에 있는 사용자 · 채널 · 레포를 카드 수와 함께 하나씩 켜고 끄기, 그리고 즐겨찾기만, 연결된 PR 상태(열림 · 머지 · 닫힘 · 없음), 최근 활동(24시간 · 7일 · 30일)), **정렬**(작업이 마지막으로 진행된 시간 또는 처음 시작한 시간, 최근 먼저 또는 오래된 먼저 — 즐겨찾기 카드는 여전히 열 맨 위, 완료 열의 날짜도 방향을 따른다. 단 응답 필요 열은 정렬과 관계없이 즐겨찾기 다음 가장 오래 기다린 카드부터 놓이고, 열 머리에 '응답 필요 · 오래 기다린 순'이라고 쓴다), 카드 검색(제목 · 요약 · 사용자 · 레포 · 채널 · 링크)이 있다. 같은 묶음 안의 선택은 넓히고, 묶음끼리는 좁힌다. 필터 버튼의 숫자는 적용 중인 필터 수, 툴팁은 숨긴 카드 수다. 필터와 정렬은 이 브라우저에 저장되고 검색은 저장되지 않는다. 필터가 숨긴 카드도 링크로 열면 보인다. 추가 필터는 GitHub Projects, Linear, Jira, Trello, Devin, Cursor, Copilot 에이전트 세션을 조사해 골랐다. 사람의 답을 기다리는 세션의 Slack 스레드 머리에는 언제부터 기다렸는지가 보인다(`3분 전부터 기다림` — Slack 날짜 토큰이라 며칠 뒤에도 맞다). 기다리기 시작한 시각은 저장되므로 재시작 뒤에도 같은 시각에서 세고, 새 질문이 와도 리셋되지 않으며, 답하면 사라진다(#1072).
- **세 서피스, 세 가지 일**: 세션 하나가 세 군데에 나오고, 각자 다른 질문에 답한다. **카드**는 분류다 — 나를 기다리나, 움직이나(제목, 여기 있는 이유, 진행 중 task, 서브에이전트 펄스, 토큰·비용, 상태와 멈춘 카드가 그 상태에 든 지 얼마인지(질문 대기는 질문이 온 때부터, 완료는 작업이 끝난 때부터), 60%를 넘으면 호박색·80%를 넘으면 빨간색이 되는 컨텍스트, 상태(열림·초안·머지됨·닫힘)가 붙은 PR 배지). **펼친 카드**는 그 자리에서 처리하며, 섹션이 카드 상태를 따른다: 질문·권한 요청이 먼저, 실행 중이면 task 창·에이전트(compact 행)·최근 지시 ↔ 응답, 끝났으면 응답·산출물·goal — 그 뒤 goal 한 줄, 짧은 참조, 모델·effort. 액션(☆ Star, 잠든·보관된 카드의 살리기, Stop / Close / Trash, Slack)은 접힌 면 바로 밑 첫 줄이다. 닫기는 항상 빨간색이고 한 번 확인한다: 첫 번째로 누르면 **한 번 더 눌러 닫기**로 바뀌고 4초 안에 다시 누르면 닫힌다(상세 카드 상태 바도 같은 방식). 확인한 순간부터 보드가 닫힌 카드를 받을 때까지 카드는 빨간 **닫는 중**으로 보인다. 서버는 세션 폴더를 즉시 비우고 삭제는 백그라운드에서 하므로, 레포 클론을 지우는 동안 서버 전체가 멈추지 않는다. 카드의 숫자를 다시 그리지 않는다. 카드 머리에는 창 버튼이 있고, 버튼마다 하는 일이 하나다(.prd/34): 왼쪽 **−**는 카드를 한 줄로 줄이고(**+**는 줄이기 전 모습으로 되돌린다, 이 브라우저에 저장), **제목**은 오른쪽에 **상세 카드**(세션 패널)를 연다(호버하면 밑줄과 옆 패널 표시가 나오고, 상세 카드가 앞에 있는 동안 그 카드는 한 줄 + 강조 테두리), 오른쪽 **▽**는 상세 카드 없이 카드를 제자리에서 펼친다(제자리에서 뛰어올라 돌아 △로 내려앉는다). 카드 면의 나머지는 눌러도 아무 일도 없어 글을 선택할 수 있다. 한 줄 카드는 상태를 점으로 남기고, TL;DR이 있으면 TL;DR의 ×를 누를 때까지 머리 아래에 둔다. 즐겨찾기 카드(휴면 · 보관 안 됨)는 마지막으로 움직인 지 하루가 지나면, 남의 작업 카드(로그인한 나와 주인이 다른 카드)는 언제나 한 줄로 시작한다(+로 펼친 카드는 그대로). 카드를 −로 줄이거나 +로 펼친 것은 이 브라우저에 저장되어 새로 고침해도 그대로이고, 건드리지 않은 카드는 기본대로 보인다. 상세 카드를 여러 개 열면 덱으로 쌓이고 우상단 ‹ n / m ›로 넘기며 뒤 카드의 가장자리가 보인다. 보드에서 한 줄인 것은 앞에 보이는 상세 카드의 카드 하나뿐이다: 다른 카드의 제목을 누르거나 ‹ ›로 넘기면, 앞에 있던 카드는 제목을 누르기 전 모습(보통, 펼쳐 뒀으면 펼친 채)으로 돌아온다. ✕는 앞 카드를 빼고 그 카드를 원래 모습으로 되돌린다(직접 줄인 카드는 그대로). 스펙: [`.prd/34-dashboard-task-card-window-controls-spec.md`](../../../.prd/34-dashboard-task-card-window-controls-spec.md). 상세 카드 제목 바로 오른쪽에 카드 면과 같은 별(켜면 채워진 호박색, 레이블 없음)이 있고, 그 뒤에 작은 버튼 두 개가 있다: **퍼머링크**는 카드 링크를 복사하고(Slack 스레드 헤더가 거는 대시보드 링크, ⌘·Ctrl을 누르고 클릭하면 연다), **전체 문맥 복사**는 지시와 답변 전부를 마크다운으로 복사한다(다른 인스턴스의 카드에는 없다 — 그 대화는 그 인스턴스에 저장된다). 스펙: [`.prd/15-dashboard-detail-deck-spec.md`](../../../.prd/15-dashboard-detail-deck-spec.md). **세션 패널**은 파악과 조종이며 태스크 뷰로 배치된다: 세션 상태·실시간 시간·액션 하나가 있는 머리 칩, 태스크 공통 서피스(세션 정보 — 요약 한 줄과 링크, 필요하면 모든 숫자 이전 대화는 버튼 하나 뒤; 답변은 Slack 봇 이름, 하네스가 보낸 입력은 **System**), 작업 로그, 오른쪽 끝의 에이전트 트리. 패널은 맨 위에서 열려 서피스·탭·최신 답변이 한 화면에 들어온다. 답변은 렌더된 답변 자체가 보이고, 요약과 원문(raw)은 맨 아래에 있다. 그 밑에 여러 줄 입력창이 있고, 붙여넣거나 끌어놓은 이미지·파일·음성 녹음을 함께 보낸다. 모델·effort는 입력창 줄의 전송 버튼 왼쪽에 있다. 어드밴스드 모드에서는 모든 섹션이 펼쳐진다 — 세션 정보 전체, 모든 대화(기기별 **자세히** 칩은 없어졌고 화면 모드가 대신한다). 스펙: - **메인과 서브에이전트 — 하나의 재귀 트리**: 카드 하나가 메인 에이전트, 곧 세션 에이전트 트리의 루트다. 메인이 `Agent` 도구로 띄운 SDK 서브에이전트(와 그들이 다시 띄운 것)는 그 밑의 같은 타입 노드다 — 각자 상태·시간·툴 호출 수와 자기 태스크 목록·작업 로그를 갖고, 어느 깊이든 같은 렌더러로 그린다(방향키로 다루는 ARIA 트리). 사이드 패널은 메인을 포함한 어떤 노드로든 드릴한다 — 경로(`메인 › A1 Explore › A3 …`), 그 노드의 헤더와 하위 트리 — 부모의 작업 로그에서는 띄운 자식마다 실시간 블록이 보인다. 메인의 태스크·로그가 서브의 것과 섞이지 않는다. 스펙: [`.prd/12-dashboard-agent-tree-spec.md`](../../../.prd/12-dashboard-agent-tree-spec.md).
- **task마다 어떻게 됐는지**: TodoWrite는 목록을 통째로 바꾸므로, 새 계획은 이전 계획에서 끝나지 않은 단계를 뺀다. task ledger가 단계가 목록에서 빠진 시각을 기록하고, Tasks는 단계마다 완료·진행 중·멈춤(시작했지만 세션이 멈춤)·대기·중단(진행 후 새 계획에서 빠짐)·실행 안 됨(시작 전에 빠짐)을 보여 준다. 지금 도는 단계만 스피너가 돈다. 이전 계획은 개수가 적힌 한 줄로 접혀 있고, 열면 새 계획으로 교체된 시점별로 묶여 나온다. 카드의 task 개수는 실행 안 된 단계를 세지 않는다. 스펙: [`.prd/14-dashboard-task-view-spec.md`](../../../.prd/14-dashboard-task-view-spec.md) §3.
- **폰·폴더블·PC**: 배치는 기종이 아니라 화면 크기를 따른다. 840px 미만에서는 세션 패널이 전체 화면 시트이고, 840px 이상(펼친 iPhone Duo·Galaxy Z Fold8, 태블릿, PC)에서는 보드 옆에 붙는다 — 보드가 살아 있어서 패널을 연 채로 다음 카드를 누를 수 있다. 보드는 폭이 720px 이상이면 3칸이 모두 보이고(세로로 든 태블릿에서도 보드 전체가 보인다), 그보다 좁으면 옆으로 넘겨 본다. 접거나 펴거나 돌리면 카드가 새 자리로 움직인다(동작 줄이기 설정에서는 페이드만). 키보드로 한 변화(카드의 ▽에서 Enter로 펼치기, Esc로 닫기, 열린 상세 카드 사이 ←/→)는 움직임 없이 바로 바뀐다. 패널에서 에이전트 탭은 스크롤 영역 맨 위에 남고, 입력창은 화면 키보드 위에 남는다. 창이 840×1000보다 작으면 CRON 레인이 접힌 채로 시작하고(머리줄과 응답을 기다리는 잡만), LLM 가용량은 항상 접힌 채로 시작한다(공급자별 칩에 두 기준을 합계 대비 계정분과 %로, `Claude 지금 5.2/16.0 33% · 주 5.6/16.0 35%`, 840px 미만에서는 두 줄까지 감싼다). 그래서 보드가 첫 화면에 보이고, 펼치기·접기 선택은 그 기기에 저장된다. 기기 크기와 출처: [`docs/misc/research/2026-10-24-dashboard-device-viewports.md`](../../../docs/misc/research/2026-10-24-dashboard-device-viewports.md).
- **최상단에서 모델·effort 원클릭 변경**: top bar에 새 세션의 기본 모델과 기본 effort가 모델 메뉴 하나로 있다(세션 메뉴와 같은 메뉴). 값을 고르면 바로 저장된다 — Slack `model set <m>`, `effort <level>`과 같은 설정이다. 세션 패널이 보드 옆에 붙어 있으면 "열린 세션에도"(기본 켜짐)로 그 세션도 함께 바뀐다(폰에서는 패널 시트가 top bar를 덮으므로 패널 자체의 컨트롤을 쓴다).
- **세션별 모델·effort**: 카드와 세션 패널 입력창에서 그 세션만 바꾼다(`%effort <level>`과 같은 범위). 다음 턴부터 적용된다. 상세 카드의 선택기는 화면 크기와 상관없이 입력창 줄의 전송(지시) 버튼 바로 왼쪽에 있다 — 음성 녹음이 그 줄을 쓰는 동안에도 취소 · 완료 앞에 남는다. 폰의 좁은 줄에서는 모델 제조사 마크와 추론 강도만 보이고, 모델 이름은 툴팁과 접근성 이름에 있다. 추론 강도는 고르는 순간 바로 바뀐다 — 서버를 기다리지 않고 메뉴도 열린 채로 있다. 연달아 고르면 마지막 값만 보내고, 서버가 거절하면 세션의 원래 값과 이유를 보여 준다. 모델이 effort를 낮춰 실행하면 실제 실행 값을 함께 보여준다.
- **모델이 실행하는 effort만**: 모든 모델 메뉴(세션·새 작업·기본값)는 그 모델의 llmux 카탈로그가 나열한 단계만 보여 주고, 서버도 그 밖의 값은 거절한다. 모델을 바꾸면 effort는 새 모델이 실행하는 가장 가까운 단계로 맞춰진다. **Ultra**는 카탈로그에 있는 codex 티어(sol·terra·astra — luna·grok·Claude는 없음)에만 있고, 와이어에서는 어느 백엔드도 받는 가장 강한 단계인 `max`로 실행된다 — codex 백엔드도 Claude 모델도 `ultra`를 거절한다(llmux도 모든 클라이언트의 `ultra`를 `max`로 바꾼다). XHigh는 빨간 그라데이션, Max는 금색 포일, Ultra는 홀로그램 포일로 보인다.
- **goal이 있는 카드는 goal의 자리에**: 보드가 DONE에 둘 카드는 goal이 자리를 정한다. goal 루프가 방금 턴을 판정하거나 다음 턴을 넣는 중이거나 턴이 아직 시작 중이면 RUNNING(목표 이어가는 중 · 턴 시작 중)에 있다. goal이 주인을 기다리면 — 이어하기 한도의 "계속할까요?", 같은 이유로 두 번 실패 — 또는 루프가 스스로 멈췄으면(완료 판정이 계속 실패, 이어하기가 시작되지 않음, 재시작 뒤 재개 실패) NEEDS YOU에 있고 상태 줄이 이유를 말한다. 사람이 멈춘 goal은 DONE에 남는다. goal 줄의 칩은 goal의 단계를 말한다: 시작 중 · 진행 중 · 판정 재시도 · 계속할까요? · 답을 기다림 · 멈춤 · 일시정지.
- **퍼미션 요청**: 턴이 퍼미션 요청(Slack의 "🔐 Permission Request" 카드 — 예: 위험 명령 규칙에 걸린 Bash 명령)에서 멈추면 그 카드가 NEEDS YOU로 옮겨지고, 카드와 세션 패널에 같은 요청이 뜬다: 도구, 파라미터, 매칭된 규칙, **Approve / Deny / Explain / Approve & disable rule (this session)**. 파라미터를 보고 응답할 수 있는 건 요청이 걸린 본인뿐이다 — Slack 버튼과 같은 규칙. Slack과 대시보드는 한 경로(`src/permission-prompt-response.ts`)로 응답하므로 먼저 누른 쪽이 이기고, 나머지는 이미 응답됐다고 안내받는다. 모든 요청에는 auto 모드 AI의 권고도 함께 뜬다 — 이 호출이 무엇을 하는지, 왜 위험한지, 승인해도 되는지. AI가 승인을 추천하면 카드가 초록색이다. 실행하지 말라고 하면 빨간색이고, 그때 승인은 Slack과 대시보드 모두에서 한 번 더 묻는다. 되돌릴 수 없는 호출 — 배포·게시(`gh pr merge`, `deploy/*`로 push, 릴리스 태그, `npm publish`, `vercel --prod`)나 파괴적 명령(`rm -r`, force push, `git reset --hard`, `DROP TABLE`) — 이면 요청에 그 사실이 한 줄로 뜨고, 대시보드 카드는 클릭 대신 밀어서 승인하며(⌘↵로는 승인되지 않는다), Slack의 Approve는 확인 대화상자를 먼저 연다(빨간 카드는 대화상자 대신 원래의 2차 확인을 쓴다). 이미 떠 있는 요청의 승인 모양만 바꿀 뿐 요청을 새로 띄우거나 막지 않는다 — 유저가 배포까지 지시한 작업이나 bypass 모드의 호출은 지금처럼 그대로 실행된다. 분류기: `somalib/permission/irreversible.ts`. 모든 응답은 세션의 작업 로그에 배지 행으로 남는다(권한 승인 · 권한 거부 · 설명 요청 · 2차 확인 승인). API: `GET /api/dashboard/session/:key/permission/:approvalId`, `POST /api/dashboard/session/:key/permission` (auth + CSRF).
- **Goal 일시정지**: `goal pause`(또는 `goal` 목록의 ⏸️, 대시보드 goal 카드)는 지금 goal을 옆으로 빼고 세션을 다음으로 넘긴다: 대기 중인 goal이 있으면 그 goal이 시작되고, 없으면 goal 작업이 끝난다. 이미 돌고 있는 턴은 끝까지 마친다. `goal resume [n]`(목록의 ▶️, 대시보드 카드 아래의 재개)은 마지막(또는 n번째) 일시정지 goal을 되살린다: 진행 중인 goal이 없으면 바로 지금 goal이 되어 시작하고, 있으면 그 goal 바로 다음 차례로 들어간다. 일시정지한 goal은 대기열을 막지 않고 재시작·잠들기·보관 뒤에도 남는다. 한도 질문의 🛑 취소는 여전히 goal을 그 자리에 멈춰 둔다 — 그 goal에서 ⏸️를 누르면 옆으로 빠진다. 스펙: [`docs/goal-command/spec.md`](../../../docs/goal-command/spec.md#pausing-and-resuming-goals).
- **대시보드에서 목표 추가·정리** (2026-11-26): 목표 탭의 추가 칸은 평소 한 줄이고, 누르면 세션 지시창과 같은 입력창으로 펼쳐진다 — 여러 줄 목표, 파일, 붙여넣은 스크린샷, 폰 카메라, 음성 메모, 받아쓰기, 4,000자 가까이 쓰면 나오는 글자 수. Enter로 추가(Shift+Enter 줄바꿈)하면 파일은 Slack 스레드에 올라가 그 목표의 첫 턴에 함께 간다 — 목표가 대기열에서 기다렸다가 나중에 시작해도 마찬가지다. 파일만으로는 목표가 되지 않는다. 지시창에 있는 기능은 다 있다: `/`·`%`·`$` 메뉴, 줄 끝의 세션 모델·effort 선택기(만든 곳 마크와 강도만 보이는 compact). 명령(`/model sonnet`, `%effort high`, `! …`)은 지시창에서 보낸 것처럼 바로 실행되고 목표가 되지 않는다. 메뉴에 없는 `/` 단어(`/tmp` 같은 경로)는 목표 글로 남는다. 목표 글에 `$스킬`을 쓰면(`배포 체크 $z`) 목표의 첫 턴에 그 스킬이 실행된다. 목표 글은 쓴 그대로 남고, 대기 목표를 편집하면 스킬도 다시 판정한다. 실제로 있는 스킬만 해당한다 — 목표 안의 `$REDIS_HOST:6379`는 그냥 글이다. 다음 목표마다 끌어서 옮기는 손잡이(마우스·손가락, 또는 포커스 후 ↑ ↓)와 글을 그 자리에서 고치는 편집 버튼(Enter 저장, Esc 취소)이 있다. 옮기기는 조용히, 편집은 스레드에 한 줄 남긴다. 이미 시작한 목표는 옮기거나 고치지 않는다(카드에 새로고침하라고 알린다). API: `POST /api/dashboard/session/:key/goal`의 `add`(+ `attachments`), `move`(`goalId`, `to`), `edit`(`goalId`, `objective`). 요소: @2lab.ai/ui 0.50.0 `<ui-goal-card>`(`slot="add"`, `ui-move`, `ui-edit`)와 `<ui-composer collapse>`.
- **goal이 도는 카드 중지**: goal이 돌고 있으면 중지만으로는 멈추지 않는다 — goal이 다음 턴을 다시 시작한다. 그래서 그런 카드에서 대시보드 중지를 누르면 먼저 묻는다(**진행 중인 goal이 있어요**: 목표와 그대로 기다릴 대기 goal 수). 취소와 **goal 일시정지하고 중지** 중에서 고른다. 확인하면 goal을 먼저 일시정지하고 작업을 중지한다. 대기 중인 goal도 시작하지 않는다(대기 goal이 있으면 그 자리에서 멈추고, goal 카드의 ▶️로 재개한다). 돌고 있는 goal이 없으면 중지는 바로 멈춘다. 스펙: [`docs/goal-command/spec.md`](../../../docs/goal-command/spec.md#stopping-a-card-whose-goal-runs).
- **누가 중지하나, 중지는 유지된다**: 소유자, 또는 어느 관리자든. 관리자는 관리자 모드를 켜지 않아도 남의 실행 중인 카드를 중지한다(닫기·휴지통 같은 다른 조작은 여전히 관리자 모드가 필요하다). 슬랙에서 관리자가 남의 스레드에 맨 `!`만 보내면 소유자 승인을 기다리지 않고 바로 작업을 멈춘다. `!{지시}`와 다른 말은 그대로 승인을 기다린다. 사람의 중지가 마지막 말이다: 중지가 들어올 때 아직 준비 중이던 턴(끊을 실행이 아직 없는 때 — 재시작이 이어 가는 중일 때처럼)은 모델에 가지 않고, 재시작(크래시 포함)은 턴이 시작된 뒤 사람이 중지한 카드를 자동으로 이어 가지 않는다(중지는 세션과 함께 저장되고, 카드는 대기로 돌아온다).
- **Goal 계속 진행 확인**: goal 자동 진행이 한도(기본 10/10)에 닿으면 소유자의 Slack DM이 "Goal 계속 진행할까요?"를 묻고, 세션 카드와 패널의 입력 필요에도 같은 질문이 승인 카드로 뜬다: 한도, 목표, 최근 사유, **✅ 계속 / 🛑 취소**. 답할 수 있는 건 goal 소유자뿐이다. 두 표면은 한 경로(`src/slack/goal-cap-decision.ts`)로 회차당 한 번만 응답한다 — 대시보드에서 답하면 DM이 결과로 바뀌고, DM에서 답하면 카드가 사라지며, 다른 이유(메시지·일시정지·완료)로 회차가 끝나면 DM의 버튼이 사라진다. DM 전송이 실패해도 카드는 뜬다. API: `POST /api/dashboard/session/:key/goal-decision` (auth + CSRF).
- **어드민 승인함** (어드민 전용): Slack DM으로 어드민에게 오는 승인 요청이 대시보드에도 뜬다. 상단 바의 "승인" 버튼에 대기 개수가 실시간으로 표시되고, 누르면 승인 카드 목록이 서랍으로 열린다. 새 요청이 오면 토스트로 알린다. 어드민 DM으로 오는 승인 요청 네 종류가 모두 대상이다: 환경 스킬 실행, MCP 도구 권한(`request_permission` — 서버·레벨·기간은 저장된 요청에서 읽고, 원자적 claim 하나로 먼저 온 응답만 통과시킨다), 새 사용자 접근 요청, 비어드민의 봇 메시지 삭제 요청. 뒤의 두 종류는 `DATA_DIR/admin-requests.json`에 라운드마다 어드민 DM 위치와 응답자를 기록하므로, 어느 쪽에서 답해도 한 번만 처리되고 모든 DM 사본이 같은 결과로 바뀐다. `admin accept|deny @user` 명령도 열린 라운드를 닫는다. 어드민 모드를 켠 어드민이 여기서 답하면 Slack 버튼과 같은 결정 경로를 타므로, 모든 어드민의 DM이 같은 결과로 바뀐다. Slack에서 답하면 카드가 대시보드에서 빠지고 누가 답했는지 보인다. 어드민 화면은 WebSocket(`admin_approvals`, 어드민에게만)과, 로드·재접속 때 호출하는 `GET /api/dashboard/admin-approvals`로 목록을 받는다. 응답 API는 `POST /api/dashboard/admin-approvals/answer`다(Slack으로 로그인한 어드민 + `X-Admin-Mode: on`, auth + CSRF). 레지스트리는 `src/admin-approvals.ts`이고, 종류마다 기존 요청 저장소를 읽는 어댑터 하나를 둔다. 에이전트가 `ASK_USER_QUESTION`에 `audience: 'admins'`를 붙여 묻는 질문(#1070)도 여기에 카드로 뜬다. 카드에는 질문과 선택지, 질문한 스레드가 나온다. 카드에서 답하면 세션 화면에서 답한 것과 같은 경로를 탄다. 그래서 Slack 질문은 답한 것으로 바뀌고 세션이 이어진다. 이런 질문에 어드민이 답하면 세션 주인의 승인을 기다리지 않는다. 그 답으로 시작되는 턴은 세션 주인의 이름과 권한으로 돌고, 스레드에는 답한 어드민이 표시된다. 카드는 그 턴을 기다리지 않고 질문을 잡는 즉시 처리된다.
  - **여러 건 한 번에 (#1131)**: 대기 중인 카드마다 한 줄이 붙는다. 승인하면 무엇이 되는지(요청의 `summary`), 위험도, 요청한 사람, 얼마나 됐는지가 나온다(카운트다운은 없다). 종류가 승인·거부 선택지를 알려 주는 요청(`batch`)에는 체크박스가 있다. **전체 선택**은 그런 요청을 모두 고르되, 위험이 높은 요청은 빼고 하나씩 고르게 한다. **선택 승인** / **선택 거부**를 누르면 확인 시트가 열린다. 시트에는 고른 요청마다 무엇이 되는지, 위험도, 요청한 사람이 나오고, 위험이 높은 요청은 하나씩 체크해야 확인 버튼 하나가 눌린다. 보낸 뒤에는 요청마다 결과(승인됨, 거부됨, 이미 처리됨, 실패와 그 이유)를 보여 준다. API는 `POST /api/dashboard/admin-approvals/answer-batch`다(`{ items: [{ id, choiceId }] }`, 최대 `MAX_BATCH_ANSWERS`건, 한 건 응답과 같은 관문). `src/admin-approvals.ts`의 `answerAdminApprovals`가 종류별로 묶어, 어댑터에 `answerMany`가 있으면 한 번에, 없으면 한 건씩 `answer`로 처리한다. 한 종류가 실패해도 다른 종류의 결과는 남는다. 에이전트 질문은 한 건씩 답한다. 환경 스킬의 일괄 승인은 가장 좁은 허용(그 스레드에서 1회)이다.

- **즐겨찾기와 살리기**: 모든 카드 면 오른쪽 위의 별 토글(또는 펼친 카드·세션 패널의 **☆ Star**)로 세션을 고정한다. 별 단 카드는 별이 채워지고, 자기 컬럼 맨 위에 놓이며(DONE에서는 날짜 그룹 위의 **★ Starred** 그룹, 별 단 크론 실행은 CRON 레인이 아니라 보드에 남는다), 계속 살아 있다 — 일이 끝났어도 sleep이나 보관(archive)으로 넘어가지 않고 만료 예고도 받지 않는다. 잠든 카드나 보관된 카드에 별을 달면 먼저 살린다. 잠든 카드와 보관된 카드의 **살리기**는 세션을 되살려 대시보드나 Slack에서 대화를 이어가게 한다: 잠든 세션은 깨우고, 보관된 세션은 같은 SDK 세션·작업 폴더·대화 기록으로 돌아온다 — 대화 기록(transcript)이 있고 작업 폴더가 그 기록으로 이어진다는 것이 확인될 때만이고, 아니면 거절 이유를 보여준다. 작업 폴더 안의 파일은 복구되지 않는다. 별을 떼면 일반 수명 주기로 돌아가되 유휴 시간을 처음부터 다시 센다. 별 단 세션은 휴지통으로 옮길 수 없고, Close는 그대로 세션을 끝낸다. API: `POST /api/dashboard/session/:key/star` `{ starred }`, `POST /api/dashboard/session/:key/revive` (세션 소유자, auth + CSRF; 보관된 카드는 그 보관본의 소유자).
- **설정 페이지**(`/dashboard/settings`, top bar의 "⚙ 설정"): Slack 명령으로 바꿀 수 있는 개인 설정 전부를 그룹(모델·effort, 출력, 알림, 목표, 자동 스킬, 계정, 권한)으로 보여주고, 대시보드 자신의 화면 모드(대시보드)도 있다. 선택형은 바로 저장되고, 직접 입력하는 값은 저장 버튼으로 저장한다. 행마다 기본값, 다를 때 "기본값으로" 되돌리기, 같은 일을 하는 Slack 명령이 보인다. 위험한 변경(bypass, 샌드박스 끄기, 네트워크 허용 목록 끄기)은 먼저 묻고, 관리자 전용 행은 잠긴 이유를 보여준다. 권한 그룹에는 **항상 승인하는 사람**(내 스레드에서 승인 없이 지시가 실행되는 사람) 목록도 있고, 한 명씩 뺄 수 있다.
- **인터페이스 소리**(기본 꺼짐): 보드와 설정 페이지의 테마 스위치 옆 스피커로 켠다. `@2lab.ai/ui`의 짧은 소리가 난다 — 탭·옵션을 바꾸면 딸깍, 대화상자·서랍이 열리면 바람 소리, 내가 한 일이 성공하면 부드러운 화음. 소리는 Cuelume가 Web Audio로 그 자리에서 합성한다. 오디오 파일이 없고, 플레이어는 스피커에 다가갈 때(마우스 올림·포커스·누름)나 소리가 이미 켜져 있을 때만 불러온다. 브라우저가 클릭 안에서 오디오를 시작하지 못하면 다음 클릭이나 키 입력이 시작한다. 선택은 브라우저마다 저장된다(`soma-sound`, 테마처럼). 마우스를 올릴 때, 스트리밍 출력, 내가 일으키지 않은 갱신에는 소리가 나지 않는다.
- **기억 탭**(`/dashboard/settings#memory`, top bar의 "🧠 기억"): 개인 기억 전부를 보고 고친다 — 에이전트 노트(`MEMORY.md`)와 사용자 프로필(`USER.md`)은 항목마다 한 줄, 용량 미터, 추가·수정·삭제(되돌리기)·모두 지우기(개수를 밝힌 확인); 지식 페이지(agent / sites / concepts / projects / cron)는 Current와 History 전체를 편집·생성·삭제; 관찰 기록(에피소딕)은 날짜별로 항목을 고치거나 지우고 오늘 기록에 메모를 더한다. 모든 편집은 탭이 불러온 revision 조건부라, 그사이 에이전트나 Slack이 바꿨으면 그 부분을 다시 불러오고 작성하던 내용은 남긴다. host 프로세스·model-command MCP 서브프로세스·대시보드가 같은 사용자별 메모리 잠금(`somalib/model-commands/memory-lock.ts`)을 써서 편집과 에이전트 기록이 서로를 지우지 않는다. API: `/api/memory/*`, 로그인 본인만, 쓰기는 auth + CSRF.
- **공유 프로젝트 메모리**(`/dashboard/settings#project`): 저장소(`owner/repo`, 채널 레지스트리가 채널을 묶는 키)마다 하나의 메모 목록. 그 저장소에 연결된 채널의 모든 세션 시스템 프롬프트에 관리자가 관리하는 `<project-memory>` 블록으로 들어간다. 로그인한 사용자는 누구나 읽고, 바꾸는 건 관리자만이다 — 서버가 관리자 게이트(viewer token, 또는 관리자 모드를 켠 `ADMIN_USERS` 구성원)와 CSRF를 요구하고, 비관리자 화면은 잠금 배너와 함께 내용만 보여준다(인증이 설정되지 않은 대시보드는 읽기만 가능). 항목은 블록 태그를 열거나 닫을 수 없고(`<` 이스케이프), 검증에 실패한 저장 파일은 `.bak`으로 복구되며 화면에 표시된다. 편집은 revision 조건부(관리자 둘이 서로 덮어쓰지 않음)이고, 바뀌면 해당 세션의 프롬프트 캐시를 비운다. 기억 탭의 개인 `project/<name>` 페이지와는 다르다. 이 메모를 쓰는 모델 명령은 없고, 네이티브 쓰기 경계(#389)가 비관리자 세션의 파일 도구를 data 디렉터리 밖에 묶는다. 다만 모든 세션이 대시보드 자격을 포함한 호스트 env를 물려받고(#391), 샌드박스를 끈 세션은 그 자격으로 대시보드 API를 부르는 것을 막는 것이 없다. API `/api/project-memory`, 저장 `DATA_DIR/project-memory.json`(원자적, `.bak`).
- **스킬 탭**(`/dashboard/settings#skills`, #1079): 세 영역이다. **내 스킬**은 Slack에서 만든 개인 스킬 목록이다. 스킬을 열면 SKILL.md를 고치고(쓴 그대로 저장, 다른 파일이 있는 스킬은 SKILL.md만 고침, 그사이 다른 곳에서 바뀌었으면 덮어쓰지 않고 거절), 그 스킬 또는 내 모든 스킬을 실행할 수 있는 사람을 더하고 뺀다 — Slack 권한 요청 흐름이 쓰는 것과 같은 권한이다. **환경 스킬**은 이 호스트의 환경 플러그인 스킬 목록이다. 누구나 이름과 자기 권한(관리자 / 허용됨 / 권한 없음)을 본다. 설명과 SKILL.md는 호스트 환경 값이 들어 있어 관리자와 그 스킬을 허용받은 사람만 본다. 누가 실행할 수 있는지는 관리자만 보고, 관리자 모드에서 바꾼다(대시보드 관리자 게이트와 CSRF, 인증이 설정되지 않은 대시보드는 못 바꿈). 관리자 모드를 켠 관리자는 SKILL.md도 고친다(같은 게이트, 그사이 다른 곳에서 바뀌었으면 거절). 고친 것은 이 호스트의 파일이다: 재시작과 배포는 그대로 두고, 플러그인 저장소에 새 커밋이 생기거나 강제 업데이트를 하면 저장소의 내용으로 덮어쓴다. 화면이 편집 칸 위에서 그렇게 알린다. **시스템 스킬**은 환경 플러그인을 뺀 설치된 기본 스킬과 플러그인 스킬 전부를 출처별로 보여 주고, 읽기만 한다. API: `/api/skills`, `/api/skills/mine/:name`, `/api/skills/env/:key`(GET, 관리자 PUT), `/api/skills/system/:source/:name`, `POST /api/skills/grants`.
- **비밀 탭**(`/dashboard/settings#secrets`, secret-access WU1, #1337): 이 호스트의 비밀 저장소(`<config dir>/secrets/`)를 GitHub 저장소 secrets처럼 보여 준다 — 이름, 바꾼 시각과 바꾼 사람, 설정에서 쓰는 곳(`dev2 › github.token`). 설정이 가리키는데 저장소에 없는 이름은 "없는 비밀"로 따로 보이고 "이 이름으로 추가"로 바로 넣는다. 값은 다시 보이지 않는다: 한 번 입력해 보내면 입력란을 비운다. 관리자 모드를 켠 관리자가 추가 · 값 바꾸기(옛 값은 어디에도 남지 않음) · 삭제를 한다. 삭제 확인 창은 멈추는 설정 절을 그대로 보여 준다. 탭은 관리자에게만 보이고, API는 Slack으로 로그인한 관리자에게만 답한다(뷰어 토큰 · 인증 없는 대시보드는 읽기도 거절). 바꾸기에는 관리자 모드와 CSRF가 더 필요하다. 모든 바꾸기는 `DATA_DIR/secret-audit.jsonl`에 한 줄씩 남는다(누가 · 언제 · 무엇을 · 어떤 이름 — 값은 없음). 이 파일은 어떤 모델도 읽거나 쓰지 못한다. server-tools는 추가하거나 바꾼 비밀을 설정 변경이나 새 세션 없이 다음 호출에서 푼다. 줄마다 **누가 쓸 수 있나**도 보인다: 관리자 · 환경 유저는 항상, 이 비밀을 쓰는 환경 서버의 환경 허락을 가진 사람(그 환경에서 고친다), 직접 허락(관리자 모드에서 승인된 유저 목록으로 추가, ✕로 빼기). API: `GET /api/secrets`, `PUT /api/secrets/:name`(`{ value, overwrite? }`, 있는 이름에 `overwrite` 없이 보내면 409), `DELETE /api/secrets/:name`, `POST /api/secrets/:name/grants`(`{ userId, allow }`).
- **비밀 사용 승인**(secret-access WU2, #1338): 어드민이 아닌 유저의 모델이 부른 server-tools 도구가 그 유저에게 허락되지 않은 비밀을 쓰려 하면 호출이 멈추고, 모델에게는 어떤 비밀을 기다리는지만 알린다(값은 절대 아님). 모든 어드민에게 카드 한 장이 간다 — DM과 대시보드 관리자 승인 서랍(`secret_use`) — 답은 셋: **✅ 수락 (이 스레드)**(그 비밀들, 그 스레드, 12시간), **❌ 거부**(기록 없음, 요청자에게 알림), **🔁 앞으로 계속 자동 수락**(그 유저에게 그 비밀들을 앞으로 계속 — 비밀 탭에 보인다). 허락하면 요청자의 작업을 다시 보낸다. 길을 더하기만 한다: 환경 허락이나 server-tools 도구 grant로 이미 열린 호출은 묻지 않고, 비밀을 쓰지 않는 도구(`ssh_exec` · `logs`)는 이 길로 열리지 않는다. 어드민 전용 도구(`gh_pr` · `cf_api` · `login` …)는 쓰는 비밀이 모두 허락되면 열린다 — 도구 자체 조건표는 그대로이고 카드가 경고한다. 한 스레드에서 거듭 불러도 카드는 한 장이다. 답은 비밀마다 `DATA_DIR/secret-audit.jsonl`에 한 줄. 허락은 `DATA_DIR/env-skill-grants.json`(`perSecret`, 스레드 허락은 메모리).
- **서버 도구 탭**(`/dashboard/settings#server-tools`, secret-access WU3, #1339): server-tools의 모든 도구를 하는 일 · 읽기/쓰기 · 필요한 절 · 수준과 함께 보여 준다. 수준(`read` · `write` · 표에 없음 = 어드민만)은 선택 상자로 바꾸고 `config.json` `server-tools.permission` 그 키에만 쓴다(읽은 뒤 누가 파일을 바꿨으면 덮어쓰지 않는다). 어드민 전용 도구는 코드에 정해져 있어 잠겨 보인다. 표가 아예 없으면 server-tools가 모든 유저에게 열려 있다고 경고하고(#1170) **표 만들기**(읽기 도구 `read`, 쓰기 도구 `write`)를 준다. server-tools 허락(사람 · read/write · 최대 4주)을 보고 · 더하고 · 거두며, 서버마다 절 · 거기서 도는 도구 · 쓰는 비밀(없는 비밀 경고) · 환경 서버면 그 환경 허락을 가진 사람을 보여 주고 여기서 더하고 뺀다. Slack으로 로그인한 어드민만 보고, 바꾸기는 어드민 모드가 필요하며 모든 변경이 감사 원장에 남는다.
- **개인 설정 API**: `GET /api/settings`, `PATCH /api/settings/:key`로 Slack 명령으로 바꿀 수 있는 개인 설정 전부를 로그인한 본인 것만 읽고 바꾼다. 쓰기는 Slack과 같은 검증기·`/z` 카드 핸들러를 거치고, 대시보드에 없는 Slack 설정 명령이 생기면 계약 테스트가 실패한다.

### 🤖 서브 에이전트 (부분 구현 · 프로비저닝 미지원)

서브 에이전트는 같은 프로세스 안에서 각자의 Slack App·Socket Mode 연결·세션 레지스트리를 갖는다.
다만 **추가 서브 에이전트를 만드는 지원 경로는 오늘 존재하지 않는다.** `somawork setup`은 프로파일의
주 Slack App 하나만 만들고, 옛 스크립트 두 개는 대체재가 아니다: `scripts/provision-agent.ts`는
아무것도 프로비저닝하지 않는 deprecation 래퍼이고(configuration token 저장·OAuth 콜백 수집·수동
app-token 프롬프트는 금지된 자격증명 경로라 삭제됨), `scripts/create-agent.sh`는 아직 돌지만
터미널에서 토큰을 받아 평문 config에 쓴다 — **자격증명을 발급·복사·저장하는 용도로 실행하지 마라.**
둘 다 패키징된 런타임에 들어가지 않는다.

상태·아키텍처 노트: [docs/misc/guides/how-to-new-agent.md](../../../docs/misc/guides/how-to-new-agent.md)
(설치 안내서가 아니다). 스키마의 정본은 `src/types.ts`의 `AgentConfig`.
