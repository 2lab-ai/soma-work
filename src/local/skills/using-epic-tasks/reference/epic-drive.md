# Case B 드라이브 — 에픽을 실환경 실측까지 모는 루프

SKILL.md §Case B는 계획(에픽·서브이슈 생성)이다.
이 문서는 그 뒤 에픽을 실환경 실측까지 모는 실행 계약이다.

## 역할

| 역할 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 디스패처 | 조사·근거 위치 확보, 지시서 작성, 게이트 재실행, 결과 검증, 되돌릴 수 있는 결정 | 문서·코드 직접 작성 |
| 작업자 | 서브이슈 1개의 문서·코드·시험 | 다른 서브이슈, 머지 |
| 외부 리뷰 엔진 | 설계 문서·PR 델타 판정 | 수정 |
| 머지 담당 | 리뷰·머지 판단, 머지 | 작성자 대신 수정 |
| 오너 | 방향·우선순위, 되돌릴 수 없는 행동 | 진행 추적 — 페이지가 대신한다 |

## 0. 진입

| 들어오는 길 | 입력 | 건너뛰는 것 |

| 넘겨받은 기존 에픽 | 기존 에픽·서브이슈·진행 정본(진행표) | 에픽·서브이슈 생성, tier 재판정 |

- 넘겨받은 에픽은 입력을 읽어 1단계로 바로 들어간다. 이미 있는 이슈·PR을 새로 만들지 않는다.
- 완료 조건이나 단위 목록이 비어 있으면 디스패처가 방향을 정해 작업자가 채우고, 오너 페이지에 적는다.

## 1. 목표·계기판 고정

1. 목표 원문을 그대로 옮겨 SSOT로 고정한다. 요약·의역하지 않는다.
2. 완료 조건 = 실환경 실측. 시험 통과·머지는 완료 조건이 아니다.
3. 오너가 보는 페이지는 1개다. 칸은 아래 다섯 개로 고정한다.
4. 갱신 = 주기 예약 + 사건 즉시.
5. 시각은 실제 시계에서 읽는다. 추정한 시각을 쓰지 않는다.
6. 질문 순서 = 페이지 "질문 중" 칸에 먼저 쓴다 → 객관식으로 1회 묻는다(1번 = 추천).
7. 오너는 대화가 아니라 페이지로 판단한다.
8. 단계가 끝날 때마다 페이지를 먼저 갱신하고, 채팅 보고는 그다음에 한다.

| 칸 | 내용 |
|---|---|
| 지금 | 진행 중인 서브이슈와 단계 |
| 다음 | 다음 서브이슈와 시작 조건 |
| 주의 | 막힌 것, 위험, 기준선 실패 |
| 질문 중 | 오너 답을 기다리는 질문 |
| 사건 기록 | 시각 + 일어난 일 한 줄 |

## 2. 스펙 먼저

코드 전에 네 문서를 쓴다.

| 문서 | 내용 | 통과 조건 |
|---|---|---|
| 현재 흐름 | 동작마다 코드 근거 위치 | 근거 없는 동작 0 |
| 분해·순서 | 서브이슈 = PR 단위, 순서 | `trinity` 합의. 분열 보고로 끝나면 결정은 caller인 디스패처가 한다 — 되돌릴 수 있으면 다수안을 이유와 함께 채택하고 소수 의견은 시험 1개로 남긴다. 되돌릴 수 없으면 오너에게 객관식으로 묻는다. |
| 설계 | 결정마다 번호, 사실 충돌은 별도 절 | 두 엔진 모두 통과 |
| 시험 목록 | 서브이슈별 시험 + 반례 | 설계 결정 번호와 대응 |

리뷰 루프:

1. 외부 리뷰 엔진이 문서를 판정한다.
2. 고칠 것마다 디스패처가 방향을 정해 작성자에게 지시한다.
3. 재리뷰한다. 통과 조건을 채울 때까지 반복한다.
4. 판마다 리뷰 반영 표를 남긴다.

| 지적 | 결정 | 반영 위치 |
|---|---|---|
| 리뷰 지적 한 줄 | 반영 또는 반려 + 이유 한 줄 | 문서 절 또는 커밋 |

## 3. 작업 단위 PR 루프

1. 서브이슈 1 = 작업자 1 = 워크트리 1 = PR 1.
2. 지시서 = 고정 결정(작업자가 다시 정하면 안 되는 것) · 수용 시험 · 실측한 게이트 명령 · 체크포인트 커밋 · 중단 시 반환 문구.
3. 의존 단위는 의존 대상 위에 쌓는다. 부모가 머지되면 재배치는 아직 푸시하지 않은 브랜치에만 한다. 푸시한 브랜치는 부모 머지를 병합해 따라가거나, main에서 새 브랜치로 다시 만든다.
4. 시험 먼저 커밋한다. 수정 전 코드에서 실패해야 한다.
5. 수정 커밋 → 변이 확인. 핵심 줄을 되돌리면 그 시험이 실패하는지 본다.
6. 디스패처가 게이트를 직접 재실행한다. 기존 실패는 기준선 비교 + 단독 실행으로 분리한다.
7. 외부 리뷰는 바뀐 부분만, 두 형태로 받는다 — 증거 파일 리뷰 1 + 작업 트리 직접 리뷰 1. 작업자가 보고한 이탈 목록을 리뷰 축에 넣는다. 지적은 같은 작업자에게 한 라운드로 묶어 보내고, 두 리뷰가 모두 승인할 때까지 반복한다.
8. PR 본문 3칸 = 무엇을 바꿨나 / 기존 동작에서 달라지는 것 / 확인한 것.
9. 머지 담당에게 리뷰·머지 판단만 요청한다. 지적은 한 묶음으로 반영하고, 반영 요약을 PR과 요청 스레드에 남긴다.
10. 머지 → 테스트 환경 반영 → 반영 후 확인.
11. 트래커에 기록하고 워크트리를 제거한다. 범위 밖 지적은 후속 항목으로 남긴다.

### 리시트 표 (PR마다 채운다)

| 항목 | 증거 |
|---|---|
| 시험 먼저 | 수정 전 실패 로그 |
| 변이 | 핵심 줄을 되돌렸을 때 실패 로그 |
| 게이트 | 디스패처 재실행 로그 |
| 기준선 분리 | 기준선 동일 실패 목록, 단독 실행 결과 |
| 외부 리뷰 | 두 형태 판정 + 반영 표 |
| PR 본문 | 3칸 |
| 반영 후 확인 | 기동 상태, 오류 0, 의도치 않게 바뀐 데이터 0 |

PR만 올리고 멈추지 않는다 — 끝은 테스트 환경 반영 후 확인이다.

## 4. 실측·종결 (오너 게이트)

1. 사전 조건(잔액·한도·보류 기준·기능 스위치)은 디스패처가 DB·API에서 직접 읽는다.
2. 되돌릴 수 있는 설정은 디스패처가 바꾼다.
3. 되돌릴 수 없는 행동(실제 송금 등)만 오너에게 한 번에 요청한다. 요청 1건 = 무엇을 / 얼마를 / 어디로 / 무엇을 확인할지.
4. 결과는 1차 원본으로 대조한다 — 외부 시스템 기록, 장부, 잠금 상태.
5. 실측 후 설정을 원복하고 트래커에 기록한다.
6. 실측 중 오너가 바꾸라고 한 설정은 바로 바꾼다. 범위는 테스트 환경 안이다.
7. 완료 조건 전체가 실측되기 전에는 에픽 완료로 보고하지 않는다.
8. 종결 = 트래커 상태 대조, 완료 조건마다 증거(머지 커밋 · 반영 · 실측), 오너 페이지 마지막 갱신, 주기 갱신 예약 해제.

## 작업 중 발견한 운영 결함

1. 리뷰나 실측이 지금 운영 중인 코드의 결함을 가리키면, 그 경로를 hop마다 직접 읽어 확인한다.
2. 실데이터를 읽기 전용으로 대조해 이미 피해가 있었는지 본다.
3. 에픽과 별도 hotfix 단위로 만든다. 처리 방식은 질문 규칙대로 묻는다.
4. 공유 문서에는 악용 가능한 재현 세부를 쓰지 않고, 접근이 제한된 기록으로 연결한다.

## 공통 규칙

| 규칙 | 계약 |
|---|---|
| 위임 | 디스패처는 조사·지시·게이트 재실행·검증만 한다. 문서·코드는 작업자가 쓴다. |
| 단위 | 대상이 N개면 작업자 N명. 하나에 몰지 않는다. |
| 증거 | 주장 1개당 근거 위치 1개. 에이전트 보고는 입력이지 판정이 아니다. |
| 결정 | 되돌릴 수 있으면 디스패처가 정하고 이유를 한 줄 남긴다. 묻는 것은 되돌릴 수 없는 결정뿐이다. 결정과 답은 진행 정본에 기록해 다음 세션이 다시 묻지 않게 한다. 본인 확인이 약한 채널(공유 페이지 등)에서 온 되돌릴 수 없는 선택은 본인 확인이 되는 대화 채널에서 재확인한 뒤 실행한다. |
| 질문 | 묻는 시점은 그 답이 다음 행동을 실제로 막을 때다. 그 전에는 추천안으로 진행하고, 막히는 시점에 모아서 객관식으로 1회 묻는다(1번 = 추천). 막힌 질문 하나 때문에 다른 작업을 멈추지 않는다. |
| 돈 | 송금을 요청할 때는 어느 지갑·계정인지 먼저, 그다음 금액·주소(네트워크). 지갑·계정 이름은 프로젝트 용어집에 정한 이름만 쓴다. |
| 비밀 | 비밀값은 출력하지 않는다. 관리자 로그인·계정·토큰 생성 금지. 돈을 움직이는 API는 직접 부르지 않는다. |
| 범위 | 배포는 테스트 환경까지. 그 위 환경은 오너 지시로만. |
| 글 | 오너가 읽는 글엔 내부 코드명 금지. 게시 전 비공개 맥락 검사. 완료 표시 이모지 금지. |
| 머지 | 머지는 머지 담당이 한다. 강제 푸시 금지, 올린 커밋을 고쳐 쓰지 않는다. 재배치는 아직 푸시하지 않은 브랜치에만 한다. |
| 장애 | 작업자가 한도에 걸리면 다른 엔진으로 넘긴다. 지시서 = "이미 된 것부터 판정하고 나머지만". |
| 중복 | 다른 세션이 같은 일을 하면 멈추고 그 사실을 기록한다. |
