## 확정 스코프

1. **기존 실시간 스티어링**(follow-up Queue 이전)의 실제 동작을 코드 근거(file:line)로 기술한다 — 무엇이 턴을 끊고, 부분 출력이 보존되는지, 같은 세션이 이어지는지.
2. **현재 Queue + Send now**의 동작을 같은 기준으로 기술한다.
3. **Claude Agent SDK가 툴 호출 사이에 유저 입력을 받는 지점**을 공식 문서·설치본(0.3.251) 기준으로 리서치해, 턴을 끊지 않고 자연스럽게 끼워 넣는 경로가 있으면 그것을 1순위로 한 통합안을 정의한다.
4. 산출물은 `.prd/06-user-steering-spec.md`(계약·인수 기준)와 `.prd/steering/loop.md`(구현 라운드). **배포·머지는 이 문서의 승인 후** — 유저 지시 "마음대로 배포하지 말고".

## 비스코프

- 패널 최하단 고정·컴팩트 레이아웃·Cancel 버튼은 별도 워크스트림(`feat/queue-panel-tail`)에서 진행 중 — 여기서는 참조만.
- `agent_view` 전환(비가역, 미인가).

## 2026-09-17 16:50 추가 원문 (배포 v0.2.1137 실측 중)

> 그리고 메세지 큐 출력을 thread panel이 아니라 thread안에 유저가 메세지 쳤을때마다 출력해줘 즉시 send now / cancel 할수 있도록. thread panel에서 뺴줘
> - 따로 명령어 추가해주고 메세지 큐확인할수 있게 해주고 처리된 메세지는 삭제해줘

확정 스코프 추가:
5. 큐 항목의 표시 위치를 결합 패널에서 **유저 메시지 직후의 스레드 메시지**로 옮긴다: 메시지가 큐에 들어갈 때마다 그 자리에 항목 1건(원문·상태·`Send now`·`Cancel`)을 게시한다. 결합 패널의 Queue 섹션은 제거한다.
6. 큐 확인 명령(`queue` / `큐`)을 추가한다: 대기·전달됨·보류 항목만 나열하고 각 항목에 같은 컨트롤을 붙인다. 처리된(consumed/resolved/cancelled/failed) 항목은 목록에서 빠진다.
7. 항목이 처리되면 그 항목의 스레드 메시지는 삭제한다(버튼이 남아 있지 않게).
