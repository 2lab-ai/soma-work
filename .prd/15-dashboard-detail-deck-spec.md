## 0. 한 줄 정의

펼친 카드는 언제나 오른쪽에 자기 상세 카드를 둔다. 여러 개를 펼치면 상세 카드가 덱으로 쌓이고 우상단 ‹ n / m ›로 넘긴다. 상세 카드의 Tasks는 모델이 고쳐 쓴 목록이 아니라 **실제로 실행된 태스크**를 시간 순으로 보여 주고, 태스크마다 시작 · 종료 · 툴 · 토큰 · 비용이 붙는다. 대화는 Chat이 기본이고, 하네스가 보낸 입력은 System, 답변은 Slack 봇 이름으로 나온다.

## 2. 상세 카드 덱 (T2)

```
보드                                  상세 카드 (도킹, ≥840px)
┌ 카드 A (펼침) ┐                     ╭──────────────╮  ← 뒤 카드 가장자리 (data-deck=1..2)
│ Stop  Slack   │ ──── 펼치면 ────▶   │ 제목   ‹ 2/2 › [자세히] ✕ │
│ …             │                     │ 세션 칩 · 서피스 · 탭 · Tasks │
└───────────────┘                     │ Chat │ 작업 로그 │ … 에이전트 트리 │
┌ 카드 B (펼침) ┐                     │ …                          │
```

- 상태: `_deck` = 상세 카드가 덱에 있는 세션 키, 연 순서.
- 보드 카드는 `@2lab.ai/ui` `<ui-agent-inbox>`가 그린다(#560). 카드를 펼치면 요소의 `ui-toggle`(열림) → `wireInbox`가 `openPanel(key)`(`deckAdd`) — 그 카드가 앞으로 온다. 포커스는 카드에 남는다.
- 카드를 접으면(요소의 클릭 · Enter · Escape) `ui-toggle`(닫힘) → `deckDrop(key)` — 앞에 있던 카드면 다음 카드(`deckNextAfter`: 뒤, 없으면 앞)가 앞으로, 덱이 비면 패널이 닫힌다. 보드에서 사라진 세션은 고르기 전에 덱에서 빠진다.
- ✕ · Escape · 시트 배경 = `closeDetailCard()`: 보드의 그 카드를 접고(요소에 공개 접기 메서드가 없어 그 카드 face를 누른다 — `cardFaceOf`, 요소의 open shadow root), 그 `ui-toggle`이 덱에서 뺀다(펼친 카드 ⇔ 상세 카드).
- 뒤에 있는 펼친 카드를 누르면 그 카드가 접힌다(요소는 클릭과 Escape를 구분해 주지 않는다) — 앞 카드 바꾸기는 ‹ ›.
- ‹ › = `deckGo(±1)`(`deckStep`, 끝에서 돈다). 버튼 title이 그 방향 세션 제목. 넘길 때 그 방향에서 짧게 미끄러져 들어온다(감소된 모션이면 없음).
- 뒤 카드 표시: 패널 맨 위 `.panel-deck-peek`의 가장자리 띠 1~2개(`data-deck`), 앞 카드 머리는 위 모서리가 둥글다.
- 폰(<840px)에서 상세 카드는 전체 화면 시트다. 펼치면 시트가 열리고, ✕로 닫으면 카드가 접힌다.

## 3. 태스크 리스트 (T5)

### 3.1 리서치 — 왜 툴 0회였나 (dev 실측, 2026-10-29)

브라우저가 실시간 데이터를 놓친 것이 아니다. ledger는 세션(`sessions.json`)과 보관본에 저장되고, 새로 연 브라우저도 서버의 숫자를 그린다. 숫자 자체가 틀렸다.

| 측정 | 값 |
|---|---|
| dev `sessions.json` 완료 태스크 중 툴 0회 | 888 / 949 (94%) |
| 그중 시작 = 종료(시간 0) | 878 / 949 (93%) |
| dev worklog의 메인 TodoWrite 목록 1,178개에서 직전 목록과 문구가 다른 항목 | 4,040 / 7,285 (55%) |
| 여러 태스크가 동시에 in_progress인 목록 | 371 / 1,178 (31%) |

원인 셋:

1. **문구 = 동일성.** 모델은 진행 결과를 태스크 문구에 써 넣는다("CI on 2e5cb5b → merge" → "CI green → PR #500 merged b8cdd17"). ledger가 같은 문구만 같은 태스크로 봐서, 고쳐 쓸 때마다 이미 완료된 새 태스크(툴 0, 시간 0)가 생기고 일을 한 원래 태스크는 "중단"으로 남았다. 스크린샷의 `#T7 중단 툴 17회`와 `#T10 … APPROVE, 3/3 툴 0회`가 그 한 쌍이다.
2. **새 SDK 세션 첫 턴의 TodoWrite 유실.** 스트림 컨텍스트가 `session.sessionId`를 값으로 복사했는데, 새 세션은 스트림 도중에 id를 받는다(`adoptSdkSessionId`). 첫 턴(그리고 `/new` · renew · 핸드오프 뒤 첫 턴)의 TodoWrite가 전부 버려져 ledger는 그 태스크들을 이미 완료된 채로 처음 들었다.
3. **귀속 규칙.** 툴은 "첫 in_progress 태스크"에만 셌고, 진행 중 표시 없이 완료로 넘어간 태스크와 병렬 태스크는 0이었다. 토큰은 태스크별로 세지 않았다.

### 3.2 기록 — ledger (`src/session/task-ledger.ts`)

- **슬롯 매칭.** 새 목록 항목은 ① 같은 문구, ② 남은 직전 항목 중 점수가 가장 높은 것(문구 유사도: 공유 단어 Jaccard, 또는 한쪽이 다른 쪽 전체를 이어 쓴 경우 0.9 · 같은 `activeForm` +0.35 · 같은 위치 +0.25, 최소 0.45). 고쳐 쓰기의 조건(리뷰 R1 · R2): 문구 유사도 0.3 이상 — 위치와 `activeForm`은 후보의 순위만 정하고 하한을 낮추지 않는다. 다른 대상을 가리키면 고쳐 쓰기가 아니다(`changesTarget`, 리뷰 R2 · R3): 두 문구의 `#N` 참조가 겹치지 않거나(원문에서 읽어 문장부호와 무관: "Review and merge PR #450." → "… #451."), 각자 환경을 하나씩 말하는데 서로 다르거나(development = dev, production = prod: "Deploy the dashboard to dev and verify" → "… to prod …"), 단어 3개 이하의 짧은 문구에서 단어를 맞바꾼 경우("Implement login API" → "Implement logout API"). 잘못 이은 고쳐 쓰기는 한 태스크의 일을 다른 태스크로 옮기지만, 놓친 고쳐 쓰기는 "교체됨 + 새 태스크"로 정직하게 남는다. 상태를 되돌리는 고쳐 쓰기(완료 → 진행 · 대기, 진행 → 대기)는 없다 — 같은 문구로만. 매칭된 고쳐 쓰기는 id · 시간 · 수치를 유지하고 이전 문구를 `revisions`(최대 12, 첫 문구 + 최근)로 남긴다.
- **합치지 않는다.** 짝을 못 찾은 직전 태스크는 목록에서 빠진 것이다. 돌았던 태스크면 그 일은 그 태스크에 남고 화면은 "교체됨"으로 보여 준다. 다른 태스크가 가져간 후보가 있었다는 것은 그 일이 그 태스크의 일이라는 증거가 아니다(리뷰 R1: "Implement login API"와 "Implement logout API").
- **귀속.** 진행 중인 태스크들이 일을 똑같이 나눈다(`shared` = 함께 돈 수). 진행 중인 태스크가 없을 때의 일은 `idle`로 들고 있다가, 다음 목록이 진행 중 표시 없이 완료로 넘긴 태스크들에게 준다(시작 = 직전 목록 시각, `startEstimated`). 그런 태스크도 없으면 `outside`(태스크 밖 작업). 합계가 실제 사용량과 같다.
- **일의 종류.** `toolCalls`(메인), `agentToolCalls`(그동안 서브에이전트가 한 툴 호출), `tokens`(입력 · 출력 · 캐시 읽기 · 캐시 쓰기 · API 환산 비용 — 메인과 서브에이전트의 API 호출 전부). 호출 단위 사용량은 스트림 실행기의 `onLiveUsage` → provider `notifyLiveUsage(sessionKey, call)` → `creditTaskUsage`. 같은 메시지가 여러 프레임에 다시 보고되면 처음 받은 태스크들에서 교체한다(런타임 `calls`, 64개, 저장 안 함).
- **목록 전의 일.** 첫 TodoWrite 전의 일(탐색 · 계획)도 버리지 않는다: 첫 툴 호출이나 API 호출에서 빈 ledger(`emptyTaskLedger`)를 만들어 `idle`로 들고, 첫 목록이 바로 완료로 넘긴 태스크에게 주거나 태스크 밖으로 둔다. 마지막 태스크가 끝난 뒤의 일(최종 답변)은 태스크 밖이다 — 보기에는 `outside` + `idle`이 함께 나온다.
- **저장.** ledger는 세션과 함께 `sessions.json`에, 보관 세션은 `archives/`에 저장된다(기존 경로). 새 필드는 `sanitizeTaskLedger`가 복원한다. 재보고 교체용 호출 기록은 ledger 객체 밖(`WeakMap`)에 있어 저장되지 않는다. 이 변경 전 태스크는 `tokens`가 없다 — 0이 아니라 "기록 없음".
- **첫 턴.** `streamContext.sessionId`는 getter다.

```
   ┌ 시작 10/29 18:48:23  종료 10/29 19:00:23  소요 12m 0s

```

- 실행된 태스크 = 시작한 적이 있는 모든 태스크(완료 · 진행 중 · 멈춤 · 교체됨), 시작 순. 12개를 넘으면 오래된 것이 접힌다.
- 결말 이름 "중단" → **교체됨**: 돌다가 새 계획으로 바뀐 태스크. 그 구간의 일은 그 태스크에 남는다.
- 행은 버튼이다. 누르면 상세(시작 · 종료 · 소요 · 도구 · 토큰 · 비용 · 분배 · 문구 변경)가 열린다. 추정이면 ≈를 붙인다(시작 추정, 나눠 가진 수치).
- 남은 계획 = 현재 목록에서 시작하지 않은 태스크. 실행 전에 빠진 태스크는 토글 하나 뒤.
