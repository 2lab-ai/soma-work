# SSOT — 대시보드 에이전트 트리 (메인 → 서브에이전트)

Status: 진행 · 작성 2026-10-23 · 기준 커밋 main `3c9576a` · 스펙: [`../12-dashboard-agent-tree-spec.md`](../12-dashboard-agent-tree-spec.md)

## 유저 원문 (verbatim, 2026-10-23 Slack)

> soma-work 대시보드 개선
>
> 현재 (아마도)  메인 모델과 메인모델이 호출한 서브에이전트의 태스크가 섞이고 작업 결과도 섞이고 있음
>
> 메인 에이전트
> ㄴ 서브 에이전트들
>
> 이런 식으로 하나의 인박스 아이템안에 서브에이전트들의 리스트를 볼수 있어야하고
> 메인 에이전트 포함 각각의 서브에이전트들이 각가 별도의 작업로그와 태스크를 각각 가지고 있다
>
> 이것을 대시보드에서 시각화 해서 볼 수 있어야함
>
> 충분히 리서치하고 어떻게 표시해야할지 충분히 고민해주고 이쁘고 responsive하게 구성해서 개선

## SSOT-TASK-TREE (ssot-task)

| T | 요건 (원문 근거) | 산출물 |
|---|---|---|
| T1 | "메인 모델과 … 서브에이전트의 태스크가 섞이고 작업 결과도 섞이고 있음" — 섞임 확정·분리 | 스펙 §1 진단 · §2 귀속 계약 (PR-A) |
| T2 | "하나의 인박스 아이템안에 서브에이전트들의 리스트" | 스펙 §3 payload (PR-A) · §4.1–4.2 카드 (PR-B) |
| T3 | "메인 에이전트 포함 각각의 서브에이전트들이 … 별도의 작업로그와 태스크" | 스펙 §2.3–2.4 레지스트리·로그 귀속 (PR-A) |
| T4 | "대시보드에서 시각화 해서 볼 수 있어야함" | 스펙 §4.3 패널 에이전트 범위 (PR-B) |
| T5 | "충분히 리서치하고 어떻게 표시해야할지 충분히 고민" | 선행 사례 조사 + 설계 자문 → 스펙 §4 근거 |
| T6 | "이쁘고 responsive하게" | 스펙 §4.4 + Playwright 실측 (PR-B) |

## 결정 (설계 자문: trinity-fallback astra-zhuge — grok 엔진 429로 패널 강등, fable 의견 병기)

- `forwardSubagentText` OFF, `agentProgressSummaries` OFF — 서브 로그 = 도구 호출/결과 + 수명주기 + 자기 task.
- 서브의 TodoWrite는 Slack 플랜 블록에서도 뺀다 — Slack 스레드의 task list = 메인 것만.
- PR 2개: PR-A 귀속·저장·payload, PR-B 대시보드 UI.

## 비목표

- Slack 쪽 `'Task'`만 검사하는 서브에이전트 렌더 분기(`tool-event-processor.ts`, `tool-formatter.ts`, TaskOutput 보강) 수리 — 후속 이슈.
  이번 작업이 Slack에서 바꾸는 것은 섞임 제거뿐이다: 서브의 TodoWrite는 플랜 블록에, 서브의 도구 호출·결과는 헤더의 현재 도구·도구 행·
  스킬 배너에 가지 않는다(모델 커맨드·git 메트릭 같은 호스트 처리는 서브 결과에도 그대로 돈다).
- SDK 업그레이드(`agent_id`·`parent_task_id`, 0.3.292+) — 재개된 서브에이전트 결합 개선. 후속.
- 과거 작업 로그의 추정 귀속(백필) — 하지 않는다.
