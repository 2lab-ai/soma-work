## 2. 지금 출력 (main `ddb3ed37` 기준)

"면"은 접힌 카드, "펼침"은 카드를 눌렀을 때 카드 아래에 열리는 본문, "상세"는 옆(휴대폰에서는 아래)에 열리는 상세 카드다. 카드를 열면 상세 카드도 같이 열린다.

### 2.1 미니멀 — 작업 카드 면 (`minimalCard`)

1. 왼쪽 위 종류 표시: 일반 작업 아이콘 · `EPIC` · `CRON` · `#노드`
2. 제목
3. 소유자 배지 (All Users 화면에서만)
4. 별 토글
5. 요약 줄 — 권한 요청 · 목표 결정 · 질문 · 재개 오류. 이것이 없으면 **원래 제목**(제목과 다를 때)
6. 현재 작업 줄 (`#id` · 이름 · 시간) — 작업 중 · 대기 칸만
7. 산출물 줄 (개수 + 최근 4개 칩 + 더 있음)
8. 바닥 줄: 상태 태그와 시간 · 비용 · 모델 아이콘과 이름

### 2.2 미니멀 — 작업 카드 펼침 (`renderCardBody(…, minimal)`)

1. 액션 줄: ☆ 즐겨찾기 · 살리기(잠든 카드) · 중지/닫기/휴지통 · Slack
2. 권한 승인 카드 · 목표 결정 카드
3. 자동 재개 안내
4. 마지막 턴 결과 · Slack 알림 실패 (Slack 없는 작업)
5. 질문 카드 (선택지)

### 2.3 미니멀 — 상세 카드

1. 머리: 제목 · 덱 `‹ n / m ›` · 닫기
2. 상태 바: 상태 · 시작 시각 · 경과 · Slack · 별 · 중지/닫기/휴지통 · 살리기
3. 입력 필요: 개수 머리 · 권한 카드 · 질문 카드
4. 작업 목록: "작업 목록 n / m 완료" + 현재 목록 체크리스트 (본문의 34%까지, 넘치면 자기 상자에서 스크롤)
5. 채팅 (지시와 답변)
6. 입력창 (파일 · 이미지 · 음성 · 받아쓰기 · 대기열)

숨김: 부제, 세션 정보, 목표, 산출물, 에이전트 탭, 에이전트 머리, 섹션 탭, 모델 컨트롤.

### 2.4 어드밴스드 — 작업 카드 면 (`cardOf`)

1. 왼쪽 위: ✦ (일반 작업) · `EPIC` · `CRON` · `#노드`
2. 제목 · 소유자 배지 · 별 토글
3. 요약 줄 (미니멀과 같은 규칙)
4. 현재 작업 줄
5. 서브에이전트 줄: 상태 점 6개 + "n개 · 실행 n · 완료 n · 실패 n"
6. 토큰 · 비용 줄
7. 산출물 줄 (최근 4개)
8. 바닥 줄: 상태 태그와 시간 · 진행 `n/m` · 컨텍스트 % · 첨부 n · PR `#n` 상태

### 2.5 어드밴스드 — 작업 카드 펼침 (`renderCardBody`)

1. 액션 줄 + 입력 필요 (미니멀과 같음)
2. 칸마다 다른 본문:
   - 작업 중: 작업 창(5줄) → 에이전트 트리 → 최근 지시와 답변
   - 대기: 최근 지시와 답변 → 산출물 → 작업 창 → 에이전트 트리
   - 쉼 · 닫힘: 최근 지시와 답변 → 산출물 → 에이전트 트리
3. 목표 줄 (goal · 상태 · n/max · 대기 n · 관리 →)
4. 짧은 참조: 환경 칩 · 이슈 · PR
5. 모델 · 추론 강도 전환 + 모델 안내

### 2.6 어드밴스드 — 상세 카드 (예전 자세히 켬)

1. 머리: 제목 + 부제(다시 만들기) · 덱 · 닫기 · 상태 바
2. 세션 정보: 요약 한 줄(소유자 · 워크플로 · 토큰 · 비용 · 컨텍스트 % · 마지막 활동), 링크(이슈 · PR · 전체 대화), 펼친 표(에이전트 모델, 시작한 사람, 도구 호출, 비용, 활성 시간, 워크플로, 환경, 누적 입력·출력·캐시 토큰, 서브에이전트 지출, 스레드 통계, 자동 재개 오류, 컨텍스트 윈도우)
3. 목표: 편집기 · 대기열 · 완료 목표
4. 입력 필요
5. 산출물: 작업 산출물 + 지시 첨부
6. 에이전트 탭: 메인 + 서브에이전트(상태 점)
7. 에이전트 머리 · 경로
8. 작업: 실행 표 · 남은 계획 · 이전 계획 · 합계
9. 섹션 탭: 대화 · 작업 로그 · 에이전트 트리
10. 모델 · 추론 강도 컨트롤 + 입력창

보드 전체(통계, 용량, CRON 줄, 기본 모델 칩, 사용자 선택, 생애주기 버튼)는 모드가 정한다. 안은 바꾸지 않는다.

## 4. 리서치와 원칙

조사(2026-11, 원문: 세션 scratch `research-cards.md`):

- **OpenAI Codex (cloud)** — 작업 행은 제목 · 경과 · 브랜치/레포 · `+N −M` · PR 배지(draft/open/merged/closed). 상세는 Diff · Logs 탭 · Create PR. 유저 불만 1위는 PR 배지가 GitHub와 안 맞는 것 ([openai/codex#50844](https://github.com/openai/codex/issues/50844), [changelog](https://learn.chatgpt.com/docs/changelog)).
- **Linear** — 보드 카드의 속성은 "Display options"에서 켜고 끈다. 필터가 아니라 보여 줄 데이터만 바꾼다 ([display options](https://linear.app/docs/display-options)). 에이전트 상태는 `pending · active · error · awaitingInput · complete · stale`이고, 입력 대기를 따로 분리한다. "Humans should be able to understand what's happening at a glance" ([AIG](https://linear.app/developers/aig), [agent interaction](https://linear.app/developers/agent-interaction)).
- **GitHub Projects** — 카드 필드는 보기마다 View › Fields에서 고른다 ([board layout](https://docs.github.com/en/issues/planning-and-tracking-with-projects/customizing-views-in-your-project/customizing-the-board-layout)).
- **Claude Code on the web** — 결과(`+42 −18`, PR)는 목록이 아니라 대화 옆 Changes 카드에 있다 ([docs](https://code.claude.com/docs/en/claude-code-on-the-web)).
- **Cursor Agents Window · Devin · Copilot agents** — 목록 행은 제목 · 상태 · 갱신 시각 정도이고, 누르면 대화와 로그가 열린다.
- **NN/g** — 처음에는 가장 중요한 몇 가지만 보여 준다. 공개 단계가 2단계를 넘으면 사용성이 대체로 낮다. 2차 정보로 가는 길을 여러 개 두는 건 좋지 않다 ([progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/)). 카드는 짧은 정보 몇 개로 된, 자세한 내용으로 들어가는 입구다 ([cards](https://www.nngroup.com/articles/cards-component/)).

## 6. 구현

- 설정: 레지스트리 키 `dashboardPlan` (그룹 `dashboard`, 라벨 **화면 구성안**, 값 `1` · `2` · `3`, 기본 `1`). 저장소 `UserSettings.dashboardPlan`. 쓰기는 `PATCH /api/settings/dashboardPlan`. 화면 모드처럼 Slack 명령이 없다.
- 대시보드: `VIEW_PLANS[mode][plan]`이 §5의 표다. 한 칸이 한 값이다.
  - `face` — 면에 남길 부분(`show`), 요약 규칙(`summary`: `all` · `asks`), 산출물 칩 수(`arts`), 종류 아이콘(`kind`), 바닥 오른쪽 순서(`foot`). `faceOf`가 읽는다.
  - `body` — 펼침의 별 버튼(`star`)과 칸별 부분 목록(`work` · `wait` · `done`). `renderCardBody`가 읽는다. 액션과 입력 필요는 목록 밖이다. 언제나 먼저 나온다.
  - `detail` — 상세 카드에 보일 섹션(`show` → `<body data-detail>`), 작업 표시(`tasks`: `runs` · `list` · `line`, `<body data-tasks>`), 작업 목록 높이(`tasksMax` → `--ptl-max`), 처음 펼침(`open` → `.is-detail`). CSS는 `data-detail`에 없는 섹션을 숨긴다.
- 같이 고친 버그: 첫 설정 로드(`loadMyDefaults`)가 스크립트 중간에서 시작해서 `_viewModeSeq`가 초기화되기 전 값(undefined)을 잡았다. 그래서 서버의 화면 모드가 새 기기에서 한 번도 적용되지 않았다(다른 기기에서 어드밴스드로 저장해도 미니멀로 열림). 이제 화면 모드와 안을 세운 뒤 boot 끝에서 시작한다. 실서버 확인(P1)에서 찾았다.
- 기기 사본 `soma-view-plan`은 첫 그림용이다. 서버 값이 이긴다. 설정 페이지에서 바꾸고 대시보드 탭으로 돌아오면(`visibilitychange` · `pageshow`) 다시 읽는다.
- 바꾸는 법: 상단바 **설정**(`/dashboard/settings`) › 개인 설정 › **대시보드 › 화면 구성안**. 미니멀 · 어드밴스드는 상단바 오른쪽 끝 버튼으로, 안은 여기서 고른다. 두 모드가 같은 번호를 쓴다.
