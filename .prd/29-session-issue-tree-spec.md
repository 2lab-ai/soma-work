# 29 — 세션 이슈 트리: 변경점의 PR 목록을 이슈 · PR 트리로

Status: shipped (구현된 계약 — 미래 목표가 아니다) · Date: 2026-11-16 · 기준 main `5fe1f0cf` · 구현 = https://github.com/2lab-ai/soma-work/pull/1321 (머지 `5069eafe`, dev 배포 2026-11-16) · SSOT = [`issue-tree/ssot.md`](issue-tree/ssot.md) ·

요약: 변경점 탭의 PR 목록은 세션의 PR을 평평하게 늘어놓을 뿐, 어느 이슈의 일인지 말하지 않는다. 이제 세션마다 **이슈 트리**가 있다. 노드는 외부 이슈(GitHub · Jira …), 세션 안에만 있는 내부 이슈, PR이다. 모든 세션은 대표 이슈를 하나 이상 갖고, 모든 PR은 부모 이슈나 부모 PR 아래에 있다. 관계없는 이슈는 루트에 선다. 새 노드가 들어오면 트리가 다시 정리된다. 모델은 작업 카드를 갱신하던 그 MCP 명령(UPDATE_SESSION)으로 트리를 직접 고친다. 변경점 탭은 PR 목록 대신 이 트리를 접을 수 있게 그린다.

## 1. 문제 (AS-IS, main `5fe1f0cf`)

- 변경점 탭의 PR 목록(`chgPrRows`)은 `doc.prs`를 만든 순서로 한 줄씩 그린다. 이 세션은 PR 9개가 이슈 없이 늘어선다(dev v0.3.61 화면, 상세 카드 440px).
- 세션의 이슈 · PR은 링크 기록(`links` · `linkHistory`)뿐이고 서로의 관계가 없다. 턴 끝 재조정기는 PR 본문의 `Closes #N`을 읽어 이슈를 기록하지만 "어느 PR이 어느 이슈를 닫는지"는 버린다. 쌓인 PR(base = 다른 세션 PR의 head)도, GitHub 하위 이슈(`parent_issue_url`)도 읽지 않는다.
- 이슈가 없는 세션(질문 · 탐색 · 문서 작업)은 PR이 생겨도 묶을 자리가 없다.

## 2. 목표 · 비목표

목표
- G1 세션 데이터에 이슈 트리가 있다. 노드 = 외부 이슈 · 내부 이슈 · PR (T21 · T22).
- G2 모든 세션은 이슈 노드를 하나 이상 가진다. 이슈가 없으면 내부 이슈(시드)를 세션 제목으로 만든다. 다른 이슈(외부 이슈, 또는 모델이 만든 내부 이슈)가 들어오면 손대지 않은 시드는 물러난다 (T21).
- G3 관계있는 이슈는 부모 아래, 관계없는 이슈는 루트. 노드가 들어오거나 관계가 새로 알려질 때마다 자리를 다시 정한다 (T23 · T24).
- G4 모든 PR은 부모 이슈나 부모 PR 아래에 있다 — 루트 PR은 없다 (T25).
- G5 변경점 탭이 PR 목록 대신 트리를 그린다. 노드마다, 그리고 트리 전체를 접을 수 있다. PR 줄은 지금처럼 누르면 그 PR의 파일만 보인다 (T20 · T26).
- G6 모델이 UPDATE_SESSION으로 트리를 고친다(부모 지정 · 내부 이슈 · 옮기기 · 지우기). GET_SESSION이 트리를 돌려준다. 시스템 프롬프트가 언제 무엇을 하는지 가르친다 (T27).

비목표
- 내부 이슈를 GitHub · Jira에 만들지 않는다(세션 데이터에만 있다 — SSOT_4).
- 작업 카드 면의 링크 칩 · 세션 정보 패널은 그대로다.
- 트리를 GitHub의 하위 이슈로 되써넣지 않는다(읽기만).

## 3. 데이터 — 노드 · 불변식 · 자리 정하기

노드(`IssueTreeNode`, 세션의 `issueTree.nodes`, `sessions.json`에 저장):

| 필드 | 뜻 |
|---|---|
| `id` | 외부 = 정규형 URL(소문자 호스트, 쿼리 · 해시 · 끝 `/` 없음). 내부 = `internal:<n>` |
| `kind` | `issue` · `pr` |
| `source` | `github` · `jira` · `linear` · `confluence` · `internal` · `unknown` |
| `url` · `label` · `title` · `status` | 외부 링크와 그 표시. 시드는 `title`이 없고 세션 제목을 보인다 |
| `parent` | 부모 노드 id. 없으면 루트 |
| `placed` | 왜 그 자리인가: `model`(모델이 정함 — 고정) · `sub-issue` · `closes` · `stack` · `default` · `seed` |
| `rel` | 호스트가 아는 관계: `subOf`(부모 이슈 id) · `closes`(닫는 이슈 id들) · `base`(부모 PR id) |

불변식 — 모든 쓰기 뒤에 `rebalanceIssueTree`가 지킨다.
1. 루트 이슈가 하나 이상 있다. 없으면(이슈가 없거나, 남은 이슈가 모두 PR 아래) 시드(`internal:1`, `placed: seed`)가 그 자리를 맡는다.
2. PR은 루트에 없다. 부모는 이슈나 PR이다.
3. 부모는 트리에 있는 노드이고 순환이 없다.
4. 노드는 200개까지. 꽉 차면 새 노드를 받지 않는다(호스트가 보는 링크는 무시, 모델 연산은 이유와 함께 거부). 있는 노드는 지우지 않는다. 꽉 찬 트리에서 루트 이슈가 사라질 자리(읽은 GitHub 부모 관계)면 시드를 새로 만들지 않고, 호스트가 부모 아래 둔 첫 이슈를 루트로 되돌린다. 이슈가 하나도 없는 꽉 찬 트리(저장본이 PR 200개뿐)는 호스트가 둔 PR 중 아무도 기대지 않는(자식 · `base` · `closes` · `subOf` 대상이 아닌) 가장 오래된 것이 시드에게 자리를 내준다. 그런 PR이 없으면(모든 호스트 PR에 무언가 기대 있음) 아무것도 지우지 않고 시드가 하나 넘는 노드가 된다 — 불러오기도 시드가 있으면 201개까지 지킨다. 어느 쪽이든 저장 · 불러오기에서 노드가 잘리지 않고 모델의 자리도 그대로다(G2).

자리 정하기 — `placed: model`이 아닌 노드마다, 위에서 먼저 맞는 것:
- 이슈: `rel.subOf`가 트리에 있으면 그 아래(`sub-issue`). 아니면 루트(`default`).
- PR: `rel.closes` 중 트리에 있는 첫 이슈 아래(`closes`) → `rel.base`가 트리에 있으면 그 PR 아래(`stack`) → 대표 이슈 아래(`default`). 어느 관계든 자기 자손(모델이 그 PR 아래 둔 이슈)을 가리키면 건너뛴다 — 호스트는 순환을 만들지 않고, 모델이 둔 자리를 옮기지 않는다.
- 대표 이슈 = 루트 이슈 중 가장 먼저 들어온(`addedAt`) 외부 이슈, 없으면 가장 먼저 들어온 내부 이슈 — 보기와 같은 순서라 MCP 미리보기도 같은 이슈를 고른다.
- 두 읽기(변경점 수집 · 턴 끝 재조정기)의 관계는 관계마다(`closes` · `base` · `subOf`) 읽기를 시작한 시각(`relReadAt`)으로 줄 세운다: 늦게 도착한 옛 읽기는 그 관계의 새 값을 덮지 않고, 읽지 않은 관계(저장본을 다시 쓴 PR)는 시각도 옮기지 않는다.
- 닫는 참조: `Closes #N` · `owner/repo#N` · 이슈 URL. 구분자는 `:`(뒤 공백 선택) 또는 공백 — 갈래가 겹치지 않아 긴 공백에도 선형이다.
- 시드가 물러나는 조건: 시드 없이도 루트 이슈(외부, 또는 모델이 만든 내부)가 남고, 시드가 `placed: seed` 그대로이며(모델이 이름을 붙이거나 옮기지 않음), 시드 아래에 `model`로 둔 노드가 없다. 시드 아래의 `default` 노드들은 새 대표 이슈 아래로 간다. 마지막 루트 이슈가 지워져 남은 이슈가 모두 PR 아래면 시드가 다시 선다.
- 형제 순서는 들어온 순서(`addedAt`)다.
- 호스트의 자리는 매번 관계에서 새로 계산한다(옛 자리를 지우고) — 한 번의 읽기로 바뀐 스택도 한 번에 자리 잡고, 결과가 노드 순서에 매이지 않는다.
- 같은 브랜치를 다시 쓴 PR들: 그 브랜치에 쌓인 PR은 살아 있는(열림 · 초안) PR 아래로 간다. 포크의 같은 이름 브랜치는 스택이 아니다.
- 노드 id의 포트: 기본 포트가 아니면 id에 남는다(다른 서버).
- PR 상태 `merged`는 끝이다: 늦게 오거나 저장본에서 온 읽기가 이전 상태로 되돌리지 않는다.
- 그 밖의 상태도 읽은 순서를 따른다(`statusReadAt`, G1): 읽기를 시작한 시각이 노드의 마지막 상태 읽기보다 이르면 적용하지 않는다(느린 수집, 저장본을 다시 쓴 PR). 더 새 읽기는 적용한다(재오픈 포함). 머지는 되돌릴 수 없어서 `merged`를 본 읽기는 언제 시작했든 적용한다. 시각이 없는 기록은 기록한 때를 읽은 때로 본다. 재조정기는 링크에 `statusCheckedAt`(읽기 시작)을 실어 보낸다.
- 읽기의 관계는 읽은 것만 바꾼다: `closes`가 없는 저장본(.prd/29 이전)은 관계를 건드리지 않는다. 그런 머지 PR 저장본은 다음 수집에서 PR 상세를 한 번 다시 읽어 `closes`를 채운다 — 파일은 같은 head · base라 다시 받지 않고, 그 뒤로는 그대로 다시 쓴다(G4). 수집 · 재조정기의 PR 항목은 트리에 있는 노드만 고친다(지운 PR을 되살리지 않는다).

## 4. 관계의 출처

- 모델: UPDATE_SESSION의 `parent`(§5). 모델이 정한 자리는 호스트가 바꾸지 않는다.
- 호스트가 링크를 기록할 때(사용자 · 모델 글의 링크, 확인된 GitHub 쓰기, 턴 끝 PR 재조정, PR 감시): 이슈 · PR 링크마다 노드를 넣거나 상태를 고친다. 재조정기가 PR 본문에서 읽은 `Closes #N`은 그 PR 노드의 `rel.closes`가 된다.
- 변경점 수집(턴 끝 · 새로 고침): PR 상세 응답에서 `base.ref`와 본문의 `Closes #N`을 함께 읽는다. 다른 세션 PR의 head 브랜치가 이 PR의 base면 `rel.base`. GitHub 이슈 노드는 한 번 조회해 제목 · 상태 · `parent_issue_url`을 읽는다. 부모 이슈가 트리에 없으면 루트로 들이고(`default`), 조회는 노드마다 한 번만 한다.
- 시드: 세션의 첫 턴 전에 트리가 없으면 만든다. 이미 있던 세션(링크 기록만 있는 세션)은 처음 읽을 때 링크 기록에서 트리를 만든다.

## 5. MCP — UPDATE_SESSION 연산 · GET_SESSION

UPDATE_SESSION `operations`에 더하는 것(기존 `add` · `remove` · `set_active`는 그대로 카드 링크를 고치고, 이슈 · PR이면 트리도 고친다):
- `add`에 `parent` — 문자열(부모 노드의 URL이나 id)이면 그 아래에 고정, `null`이면 "관계없음"으로 루트에 고정, 없으면 호스트가 자리를 정한다.
- `{ action: "add_internal", resourceType: "issue", title, status?, parent?, id? }` — 내부 이슈를 만든다(`id`가 있으면 그 내부 이슈의 제목 · 상태를 고친다). 상태는 `open` · `closed`.
- `{ action: "move", resourceType: "issue" | "pr", url | id, parent: string | null }` — 노드를 옮겨 고정한다.
- `remove` — 링크와 함께 노드를 지운다. 자식은 지운 노드의 부모로 올라간다.
- 실패: 없는 부모 · 순환 · PR을 루트로 · 200개 초과는 그 연산만 거부하고 이유를 돌려준다.

GET_SESSION `payload.session.issueTree` = `{ nodes: [{ id, kind, source, url?, label?, title?, status?, parent?, placed, rel? }], nextInternal }` — 시드의 제목은 세션 제목으로 채워진다. `rel`(아직 트리에 없는 이슈를 닫는 PR의 관계 포함)은 MCP 미리보기가 호스트와 같은 자리를 계산하게 한다. 대시보드 보드에는 `rel`을 보내지 않는다.

시스템 프롬프트(작업 카드 절): 이슈 · PR을 만들거나 다룰 때 관계가 있으면 `parent`를 준다. 관계없는 이슈는 `parent: null`. 외부 이슈 없이 일의 덩어리가 바뀌면 `add_internal`. 자리가 틀렸으면 `move`.

## 6. 변경점 탭 — 트리 그리기 · 접기

- PR 목록 자리에 "이슈 · PR" 트리가 선다. 머리 줄(접기 · 펼치기)과 노드 줄.
- 이슈 줄: 펼침 화살표(자식이 있을 때) · 출처 표시(GitHub `#1294`, Jira 키, 내부 = `내부`) · 제목 · 상태 칩 · 외부 링크(↗).
- PR 줄: 지금의 PR 줄 그대로(번호 · 제목 · 상태 · +/− · 파일 수 · ↗, 누르면 그 PR 범위). 들여쓰기가 깊이를 보인다.
- 트리에 없는 수집된 PR(옛 세션)은 대표 이슈 아래에 그린다.
- 접은 노드는 세션별로 기억한다(페이지 안에서). 세션이 바뀌면 처음 상태(모두 펼침)로 연다.
- 세션 푸시(`sessionUpdated`)로 트리가 바뀌면 열린 탭이 다시 그린다.

## 8. 인수 시나리오

| ID | 실행 | 기대 관측 |
|---|---|---|
| S1 | 링크 없는 새 세션의 첫 턴 | 트리 = 시드 하나(제목 = 세션 제목) |
| S2 | 그 세션에서 PR을 만듦(링크 자동 기록) | PR이 시드 아래 |
| S3 | GitHub 이슈 링크가 들어옴 | 시드가 물러나고 PR이 그 이슈 아래 |
| S4 | 관계없는 이슈를 `parent: null`로 추가 | 루트 두 개 |
| S5 | PR 본문 `Closes #N`(N이 트리에 있음) | PR이 #N 아래(`closes`) |
| S6 | 쌓인 PR(base = 세션 PR의 head) | 위 PR 아래(`stack`) |
| S7 | 하위 이슈(`parent_issue_url`)가 들어옴 | 부모 이슈 아래(`sub-issue`), 부모가 없으면 루트로 들임 |
| S8 | 모델 `move` · `add_internal` · `remove` | 고정 · 내부 이슈 · 자식이 위로 |
