## 한 줄

모델은 "어느 gh 계정으로" 또는 "어느 환경의 Cloudflare로" 무엇을 할지 부탁만 한다. 키는 모델이 열 수 없는 **키 보관소**가 쥐고 대신 실행한다.
위험한 일은 어드민이 Slack에서 직접 허락할 때만 일어난다.

## 1. 요청 → 끝상태 (SSOT-TASK-TREE 기준)

| | 요청 (원문) | 끝상태 | 확인하는 법 |
|---|---|---|---|
| **T2** | server-tools처럼 devops-tools 설정 추가 | 배포 설정에 devops-tools를 넣은 봇에서만 켜진다. 안 넣은 봇은 지금과 같다 | 설정 없는 봇에 도구가 안 보임 |
| **T3** | gh는 계정 단위, 계정 여러 개, 계정별 원하는 작업 | 모델이 계정을 골라 gh 작업을 한다. 계정은 여러 개 등록한다. 환경 구분은 없다 | 계정을 바꿔 같은 레포를 조회하면 각 계정 권한대로 보임 |
| **T4** | 유저별 퍼미션, 기본 읽기, 쓰기는 어드민 허락 | 읽기 = 어드민이 그 유저에게 기간을 정해 허락. 쓰기 = 건마다 어드민이 Slack에서 허락 | 허락 없는 유저의 조회 거절, 쓰기는 허락 클릭 전 실행 0 |
| **T5** | `work-m64` dev에 계정 2개 | `work-m64` dev 봇에 org-admin 계정과 member 계정이 등록된다 | 그 봇에서 두 계정이 목록에 보임 |
| **T6** | org-admin 계정으로 유저 추가·삭제, 레포 권한 부여, 항상 어드민 최종 확인 | 조직 유저 추가·삭제·역할 변경, 레포 읽기·쓰기 권한 부여를 전용 도구로 한다. 매번 어드민이 허락해야 실행된다 | 허락 카드에 "누구를 어디에 무슨 권한으로"가 보이고, 허락 후에만 GitHub에 반영 |
| **T7** | Cloudflare 환경별 포지키 | dev2 · stage0 · stage2마다 포지키 하나를 보관소가 쥔다. 포지키는 다른 키를 만드는 일만 할 수 있다 | 환경마다 포지키 1개 등록, 그 자체로는 DNS를 못 건드림 |
| **T8** | 매번 어드민 허락 → 3일 미만 단기 키 → 그 키로 작업 | 어드민이 허락하면 보관소가 그 환경·그 범위만 되는 키를 만든다(기본 1시간, 최대 71시간). 작업은 그 키로만 하고, 끝나면 지운다 | Cloudflare에 만료 시각이 붙은 키가 생겼다가 지워짐 |
| **T9** | 모델이 키를 직접 관리하지 않는다 | 키는 보관소에만 있다. 모델의 대화·출력·로그·Slack에 키가 안 나타나고, 모델이 보관소를 열 수 없다. 봇 컴퓨터 계정에서 사람 gh 계정을 뺀다 | 모델이 키를 꺼내려 하면 실패 |

T1·T11(시각화)과 T10(계획 → 컨펌 → 진행)은 작업 순서 항목이라 끝상태 표에 넣지 않았다.

## 2. 그림

```
Slack 유저 ── 부탁 ──▶ 봇 안의 모델 (키 없음)
                          │ "member 계정으로 PR 목록" / "stage2 DNS 바꿔줘"
                          ▼
                     키 보관소 (모델이 못 여는 별도 계정으로 실행)
                     ├─ gh 계정 키: org-admin 계정 · member 계정
                     ├─ Cloudflare 포지키: dev2 · stage0 · stage2
                     │
                     ├─ 읽기 ─────────────▶ 바로 실행 (유저 허락 기간 안)
                     └─ 쓰기·관리·단기 키 ─▶ 어드민 Slack 허락 카드 ─▶ 허락 시 1회 실행
                                                                      Cloudflare: 단기 키 생성 → 작업 → 삭제
```

## 3. 지켜야 할 것

- 키는 보관소 밖으로 안 나간다. 모델은 보관소를 열 수 없다.
- 위험한 일(쓰기, 조직·레포 권한 변경, 단기 키 생성)은 건마다 어드민 허락. 어드민 본인이 부탁해도 마찬가지.
- 허락 카드에 적힌 내용이 곧 실행 내용이다. 카드를 모델이 바꿀 수 없다.
- 레포 삭제·이전·공개 전환은 하지 않는다(요청에 없음).

## 4. 고를 것 (어드민 결정 — 2026-10-26 전부 1번으로 확정)

1. **허락 카드를 어디서 받나** — ① 보관소 전용 Slack 앱(설치 1회, 모델이 카드를 못 건드림) ② 기존 봇(설치 없음, 카드를 모델이 바꿀 수 있는지 먼저 시험) ③ 지금 버튼(흉내 가능)
2. **어드민 본인 부탁도 허락을 거치나** — ① 거침, 본인이 허락 가능 ② 다른 어드민만 ③ 자동 통과
3. **gh 쓰기 허락 단위** — ① 건마다 ② member 계정 쓰기는 기간 허락
4. **Cloudflare 단기 키** — ① 기본 1시간·최대 71시간, 허락 1번 = 키 1개, 그 범위 안에서는 이 봇이 같이 씀 ② 고정 24시간 ③ 호출마다 허락
5. **server-tools 유저별 허락을 지금 켜나** — ① 네 봇 모두 ② `work-m64` dev만 ③ 안 켬
6. **봇 컴퓨터 계정의 사람 gh 계정** — ① `work-m64`·`work-m16`에서 빼고 `fable-m5max`는 운영자 본인 계정이라 유지 ② 세 곳 다 ③ `work-m64`만

## 5. 이 설계로도 남는 것

같은 봇 안에서는 "누가 부탁했는지"를 완전히 증명할 수 없다. 그래서 읽기 허락과 카드의 요청자 이름은 같은 봇 안에서 빌려 쓸 수 있고,
Cloudflare 단기 키는 허락된 범위 안에서 그 봇의 다른 대화도 쓸 수 있다. 실행 범위는 어드민이 본 카드를 넘지 못한다.
근본 해결은 모델이 도는 계정 자체를 봇과 나누는 것이다(이번 범위 밖).

## 6. 하지 않는 것

prod 환경, test2의 Cloudflare, 레포 삭제·이전·공개 전환, 팀 관리, 다른 세 봇에 devops-tools 설치.
