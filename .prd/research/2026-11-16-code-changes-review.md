## 2. 높음 — 정확성

**F1 세션 시작 전에 만든 PR에 이어 커밋하면 "PR에 없는 커밋"으로 잡힌다.**
- 원인: `pr-changes.ts`에서 세션 시작 전 PR은 `continue`로 통째로 빠진다. 그래서 그 head가 `committedBase`의 기준점 후보가 되지 못한다.
- 장면: "PR #N 리뷰 반영해줘" → `gh pr checkout N` → 커밋 · push. 다음 턴 컨텍스트가 "commits in no PR yet"이라고 말하고, 모델이 PR을 하나 더 만들 수 있다. 스펙 26 §3("어느 PR에도 없는 커밋")과 어긋난다.
- 고침: 세션 전 PR의 head(와 head 저장소)는 기준점 후보로만 남긴다. PR · 머지됨 층과 지표에서는 계속 뺀다.

**F2 amend와 충돌을 푼 merge가 커밋 지표를 부풀린다.**
- 원인: reflog 패턴이 `commit (amend)`와 `commit (merge)`를 새 커밋처럼 센다. 각각 부모 대비 전체 numstat이다.
- 재현(리뷰어): 한 커밋을 두 번 amend하면 `commit_created` 3행, 줄 수 50+51+52 = 153이 된다. 마지막 변경은 52줄이다. 충돌 merge는 main이 그사이 받은 변경 전부를 이 세션 몫으로 센다.
- 이 저장소는 sanitize 규칙 때문에 `git commit --amend`가 흔하다. 현재 시험 하나가 amend 계산을 의도대로 고정하고 있다.
- 고침: amend는 바꾼 커밋 대비 차이만 세고 `commit_created`는 새로 내지 않는다. 충돌 merge는 해결분만 세거나(`--remerge-diff`) 세지 않는다.

**F3 `.git` 안이 정리되는 중에 읽으면 "링크가 있다"로 오판하고, 지난 읽기까지 지운다.**
- 원인: `noLinksIn`은 세 가지 서로 다른 일에 같은 `false`를 돌려준다. 진짜 링크, 도는 중 사라진 폴더, 항목 10만 개 초과다. 셋 다 `repo-links-outside`가 된다.
- 재현(리뷰어): `git prune` 도중 104번 읽기 중 92번이 그렇게 나왔다(실제 링크 0). 턴 끝 수집은 모델의 마지막 커밋 뒤 자동 gc와 겹치기 쉽다.
- 결과: 지난 읽기를 지키는 사유가 아니라서 그 체크아웃의 수가 0이 된다. 탭에는 엉뚱한 안내가 나오고, 모델의 "커밋 안 한 변경" 줄도 사라진다.
- 고침: 결과를 셋으로 나눈다. 링크 → 거부. 사라짐 → `repo-changed-during-read`(지난 읽기 유지). 초과 → 고유 사유와 문구.

## 3. 중간

- **F4 PR 상한 20개를 남의 PR 링크가 채운다.** 세션의 PR 기록은 본문에 언급된 PR까지 담는다. 상한은 그것까지 센다(`seen.size`). 재현: 오래된 PR 링크 20개가 세션의 머지된 PR을 저장본에서 밀어냈다. 수집마다 GitHub 호출 20번도 남의 PR에 쓴다. 고침: 세션 PR이 아닌 id를 기억해 건너뛰고, 상한은 세션 PR에만 적용한다.
- **F5 큰 저장소 비용.** 커밋 안 함 층은 추적 파일마다 stat을 한다. 4만 파일에서 cold 9.0초, warm 0.7초다(이 저장소 3.7k 파일은 491 / 140 ms). 캐시는 메모리에 있어서 재시작하면 cold다. 20만 항목을 넘으면 통째로 비운다. 고침: git index의 stat을 쓰고(racy 규칙 포함), 병렬 lstat에 상한을 두고, 수집마다 시간 예산을 둔다.
- **F6 수집마다 열린 뷰어가 비고 맨 위로 튄다.** 클라이언트 쪽은 이번 라운드 #1313에서 고쳤다(§5). 서버 쪽은 남았다. 내용이 같아도 `updatedAt`을 다시 쓰고, `.bak`을 돌리고, 카드에 푸시한다(1.9 MB 문서에 동기 I/O 12 + 14 ms). 고침: 내용 해시가 같으면 쓰지 않고 "확인 시각"만 따로 둔다.
- **F7 잘림과 오래됨을 말하지 않는다.** 층 1,000파일 상한, PR 300파일 잘림(행은 "파일 500", 트리는 300), `filesStale`을 화면이 말하지 않는다. 기준 시각은 HH:MM뿐이라 일주일 전 스냅샷도 지금처럼 보인다. 새로 고침은 바쁨 표시가 없고, 닫힌 세션에서는 조용히 아무 일도 하지 않는다.

## 4. 낮음 · 운영

- F8: 탭을 열 때마다 `refresh=1`로 전체 수집을 한다(GitHub 호출 포함). 서브에이전트를 바꿔도 다시 연다. 저장본이 N초보다 오래됐을 때만 다시 모으면 된다.
- F9(이번 라운드에서 발견, 기존 결함): 상세 카드 탭 줄의 펼침 화살표(`<i class="pm-caret" data-ui-icon="chevron-down">`)가 처음부터 그려지지 않았다. `fillUiIcons`는 `data-ui-icon`이 먼저인 슬롯만 채운다. 같은 꼴의 슬롯이 다른 곳에도 있는지 한 번 훑어야 한다.
- 확인 못 함(리뷰어): 재조정기가 게이트 전에 `git worktree list`를 강화 플래그 없이 부른다. 명령을 부르는 설정 키는 찾지 못했다.
- 옛 파서가 만든 가짜 지표: 배포 전 명령 출력 파서가 이 세션의 Bash 출력(테스트 픽스처 `[main abc1234] …`)에서 커밋 지표 6행을 만들었다. 스펙대로 지우지 않았다. 원하면 sha가 실제로 없는 `commit_created` 행을 찾아 지우는 1회 정리를 할 수 있다.
- 배포가 진행 중인 턴을 끊는다: 이 세션에서만 세 번 끊겼다(dev 재시작). 재개 장치는 돌았지만, 끊긴 명령은 다시 확인하고 다시 돌려야 했다.
- G1 저장 문서 정리 정책 없음: 대화 하나에 0.5–2.7 MB와 같은 크기의 `.bak`이 붙는다.
- G5 카드의 지난 PR 칩: 머지 뒤에도 "열림"으로 남는다. 변경점 탭은 맞다.

## 6. 제품 개선 아이디어

1. 커밋함 층에 커밋 목록(sha · 제목)과 브랜치를 보인다. 이미 저장돼 있는데 화면에 없다. 지금은 "커밋함 3"이 어느 커밋인지 모른다.
2. 세션이 닫힐 때 커밋 안 한 변경이나 push 안 한 커밋이 있으면 경고한다. 세션 폴더는 지워지므로 일을 잃는다.
3. 커밋 안 함 층을 patch로 내려받는다. 세션 폴더가 지워진 뒤에는 저장된 패치가 유일한 사본이다(파일당 256 KiB, 문서 6 MiB 안).
4. 사용자의 세션 전부에서 "안 올린 일"을 한 화면에 모은다. "어디에 변경을 두고 왔지?"에 답한다.
5. 뷰어에 키보드 이동(j/k, 다음 파일)과 좌우 나란히 diff를 넣는다.
