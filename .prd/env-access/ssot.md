## 용어 고정

- **어드민** = `ADMIN_USERS`의 사람. 모델은 넓은 샌드박스 안에서 돈다.
- **일반 유저** = 그 밖의 사람. 모델은 좁은 샌드박스 안에서 돈다.
- **환경 사용자** = `env:<org>-dev2`처럼 `env:`로 시작하는 ID를 가진, 사람이 아닌 사용자. 환경의 비밀 · 호스트 · GitHub 권한 · 스킬을
  가진다. 사람의 요청을 어드민의 허락 아래 대신 수행한다. 어드민급이지만 그 환경 하나에 묶인다.
- **환경 grant** = (요청자, 환경 사용자, 스킬 또는 전체, 범위 = 이 스레드 또는 항상). 어드민이 4버튼으로 만든다.
- **비밀 저장소** = 봇 배포 디렉터리의 `secrets/`. 봇 프로세스만 읽는다. 어떤 모델도 어떤 방법으로도 읽지 못한다.
- **환경 도구** = 비밀이 필요한 동작을 하는 MCP 도구. 봇 프로세스 쪽(샌드박스 밖)에서 돌고, 결과만 돌려준다.

- **D2 = org-admin 토큰** — 봇 PR의 develop 승인은 `<org-admin 계정>` 토큰으로 한다. 토큰은 브로커에서 봇 비밀 저장소로 옮긴다 (SSOT_4).
- **D3 = ssh는 MCP로만** — 모델(어드민 포함)은 ssh 키를 읽지 못하고 Bash로 ssh하지 않는다. 호스트 작업은 server-tools와 같은 방식의 MCP 도구로 (SSOT_4).
- **D4 = 환경 = 별도 어드민급 사용자** — `env:<org>-dev2` · `env:<org>-stage0` (SSOT_4).
- **D5 = 별도 브로커 제거** — 비밀과 승인은 한 바이너리 안에서, 모든 모델을 샌드박스에 넣어 지킨다 (SSOT_3).
- **D6 = 환경 유저는 샌드박스 없는 어드민, 새 실행기 없음** — 배포·QA 스킬은 환경 유저의 개인 스킬과 크론이다. 일반 유저는 `$<org>-dev2:skill`(다른 유저 스킬)과 `cron run`(크론 실행 요청)으로 부르고, 승인은 어드민이 한다. 승인된 요청은 크론처럼 오너(환경 유저)로 새 스레드에서 돈다. 비밀 파일은 지금처럼 어떤 모델도 읽지 못한다 (SSOT_5).

## 확정 스코프

1. 모든 모델 세션을 샌드박스 안에서 돌린다. 어드민은 넓은 프로필, 일반 유저는 좁은 프로필. 샌드박스가 뜨지 못하면 실행하지 않는다.
2. 비밀은 비밀 저장소 한 곳에만 둔다. 어떤 모델도 Bash · Read · Grep · Glob · Write · Edit로 닿지 못한다. 승인·grant 기록도 모델이 쓰지 못한다.
3. 환경 사용자를 도입한다. 각 환경 사용자는 비밀 · 호스트 · GitHub 권한 · 스킬을 가진다.
4. 사람(어드민이 아닌)이 환경 사용자의 일을 요청하면 어드민 4버튼 카드가 한 번 뜬다. 허락 뒤에는 카드 없이 돈다. 어드민은 묻지 않는다.
5. 비밀이 필요한 동작(GitHub 승인·머지, 환경 계정 로그인, DB 조회, 로그, ssh, Cloudflare)은 환경 도구가 한다. 모델은 결과와 세션만 받는다.
6. 별도 브로커(별도 OS 유저 데몬, 브로커 Slack 앱, 중계 MCP, 대시보드 대기열)를 걷어낸다.
7. 첫 적용 배포 = `team-host` dev 봇.

## 비스코프 (근거)

- prod 봇 적용 — 첫 적용은 `team-host` dev(확정 스코프 7). prod는 같은 코드가 배포될 때 설정으로 켠다.
- 모델 세션을 봇과 다른 OS 유저로 내리는 것 — 샌드박스가 그 경계를 맡는다(SSOT_3).
- 고객 레포의 브랜치 규칙 변경 — 승인은 org-admin 토큰으로 한다(D2).
