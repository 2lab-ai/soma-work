## 0. 한 줄 정의

대시보드에서 슬랙 스레드 없이 태스크를 만들고, 슬랙 세션과 같은 권한 규칙으로 도구를 쓰고, 대시보드에서 승인받고, 재시작해도
살아 있는 태스크 하나. 기존 슬랙 세션은 그대로 동작한다. 에픽이 자식을 만드는 기능은 다음 에픽(E4)이다.

읽는 순서: §1(지금 무엇이 슬랙에 묶여 있나) → §2(결정) → §3(ID 수명 계약 초안) → §4(시험 목록) → §5(E4 출시 조건) → §6(모르는 것).

## 3. ID 수명 계약 (초안 — #595에서 확정)

| ID | 생기는 때 | 바뀌는 때 | 바뀌지 않는 때 |
|---|---|---|---|
| 태스크 ID | 태스크 생성(영속 저장 후 반환) | 없음 — 카드 한 장의 수명 | `/new`, 재시도, 컨텍스트 교체, 모델 변경, CONTINUE_SESSION, 봇 스레드 이전 |
| 실행 세션 ID (SDK `sessionId`) | 첫 SDK 턴 | `/new`, 잘못된 resume 복구 | 태스크 ID와 무관 |
| 대화 기록 ID | 지금은 세션 초기화 때 | — | — |

채택 규칙: 대화 기록 ID(`conversationId`)를 태스크 ID로 쓴다. 단 다음 셋을 모두 만족할 때만이다.
(a) 생성이 저장 완료를 기다린다. (b) `ConversationRecord`의 채널 · 스레드가 선택 속성이 된다. (c) 태스크 ID → 세션 역조회가 선형 탐색이 아니다.
하나라도 막히면 태스크 ID를 따로 만들고 대화 기록 ID를 거기에 연결한다. 이 판정과 근거를 #595 PR에 남긴다.

## 5. 다음 에픽(E4) 출시 조건 — 여기서 확정, 구현은 E4

- 부모 · 자식은 태스크 ID로 가리킨다. 슬랙 스레드 키는 쓰지 않는다. 같은 자식 중복 생성을 막는다(부모 · 계획 노드 기준 멱등 키).
- 상한: 자식 수(초깃값 7 — 제품 정책, Case B의 PR 상한에서 끌어온 숫자가 아님), 깊이 1(자식은 자식을 못 만든다), 유저 전체 동시 실행, 비용.
- 자식의 소유자는 호스트가 부모 유저로 고정한다. 작업 폴더는 검증된 상속이다. 모델 입력이 권한을 넓히지 못한다.
- 부모가 잠들어도 관계 · 진행 상태 · 대기 이벤트는 보존하고, 정확한 부모를 깨운다. 지금 크론의 깨우기 경로는 그대로 쓰지 않는다 — 잠든 세션을 빼고, 스레드가 안 맞으면 같은 유저 · 채널의 다른 세션으로 넘어가며, 못 찾으면 새 스레드를 만든다(`src/cron-scheduler.ts:314-355`). `wakeFromSleep`도 채널 키다(`src/session-registry.ts:750`).
- 진행도는 서버가 기록한 자식 상태로 계산한다. 자식의 "완료" 문장이나 메시지는 정보이지 승인이 아니다. 부모 취소 시 자식을 취소할지 남길지 규칙을 정한다.
- 세션 간 포크 질문(E3)은 선행 조건이 아니다. 부모가 자식에게 중간에 물을 때 쓰며, 계획안 v3의 원본 불변 · 도구 없는 1턴 · 질문자 과금 · 비신뢰 입력 규칙을 그대로 따른다.
