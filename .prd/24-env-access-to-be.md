## 한 줄

모든 모델은 샌드박스 안에서 돈다. 비밀은 봇만 읽는다. 환경은 `env:<org>-dev2` 같은 별도의 어드민급 사용자가 되어 비밀·호스트·GitHub
권한·스킬을 가진다. 사람의 요청은 어드민이 한 번 허락하면 그 환경 사용자가 대신 수행하고, 그다음부터는 카드가 뜨지 않는다.

## 1. 세 주체

| 주체 | 모델 샌드박스 | 비밀 | 무엇을 할 수 있나 |
|---|---|---|---|
| **어드민** (`ADMIN_USERS`) | 넓은 프로필 — 쓰기: 홈 · 봇 배포 디렉터리(비밀·승인 기록 제외), 네트워크: 넓게, `gh` TLS 가능 | 못 읽는다 | 모든 환경 사용자의 일을 묻지 않고 시킨다. ssh는 MCP 도구로만 |
| **일반 유저** | 좁은 프로필 — 쓰기: `/tmp/{uid}`, 네트워크: dev 목록 (+ 허락받은 환경 사용자의 도메인) | 못 읽는다 | 환경 사용자의 일은 어드민 허락이 있어야 시킨다 |
| **환경 사용자** (`env:<org>-dev2` · `env:<org>-stage0` …) | 사람이 아니라 모델을 직접 돌리지 않는다. 사람의 턴이 이 사용자로 "대신 수행"할 때 그 턴의 샌드박스에 이 환경의 도메인·작업 폴더가 더해진다 | 환경 도구만 쓴다 | 자기 환경의 GitHub 승인·머지, 계정 로그인, DB·로그, ssh, Cloudflare. 자기 스킬(배포·QA)을 가진다 |

## 2. 요청 → 끝상태 (SSOT-TASK-TREE 기준)

| | 요청 (원문) | 끝상태 | 확인하는 법 |
|---|---|---|---|
| **T4** | GitHub 권한을 얻고 기다리고 처리하는 부분 | 봇 PR의 통합 브랜치 승인은 환경 도구가 org-admin 토큰으로 조건(작성자 = 봇, 필수 체크 녹색, head SHA 고정)을 확인하고 바로 한다. 카드 대기 없음 | 05:00 정기 작업의 봇 PR 승인 카드 0장, 승인까지 지연 < 1분 |
| **T5** | 한 번 허락하면 그다음부터 · 4가지 답 | 어드민 카드 4버튼: **수락**(이 스레드) · **거절** · **이 유저에게 이 스킬 항상** · **이 유저에게 이 환경 전체 항상**. 저장은 환경 grant 하나 | 비어드민 "dev2 배포" → 카드 1장 → "dev2 전체 항상" → 다음 요청 카드 0장 |
| **T6** | approve·머지 권한, 대신 로그인해서 세션만 | 환경 사용자가 GitHub 권한과 환경 계정을 가진다. `login`은 로그인 결과(쿠키·토큰, 만료 시각)만 요청자 작업 폴더에 남긴다 | 세션 기록·로그·출력에 환경 계정 비밀번호 0회, 세션으로 환경 API 200 |
| **T7** | 일반 유저 모델은 샌드박스 안, 환경 권한은 밖 | 비밀이 필요한 동작은 환경 도구(봇 프로세스 쪽 MCP)가 한다. 모델은 결과만 받는다 | 일반 유저 세션에서 비밀 경로 읽기 시도 → OS 거부 |
| **T10** | 어드민도 넓은 샌드박스, 별도 브로커 제거 | 어드민 샌드박스 기본 켜짐. 브로커 데몬·브로커 Slack 앱·중계 MCP·대기열 삭제. 배포는 번들 하나 | 어드민 세션에서 `cat <비밀 저장소>/*` → OS 거부 · 배포 워크플로에 브로커 설치 단계 없음 |
| **T11** | 어드민 · 일반 유저 · 환경 구분 | 권한 축이 셋이다: 누가 어드민인가 · 어떤 샌드박스 프로필인가 · 어떤 환경 grant가 있는가 | 23 §2의 8겹이 셋으로 흡수됨 (§4 표) |
| **T12** | 환경 = 별도 어드민급 사용자 | `env:` 로 시작하는 사용자 ID. 자기 스킬 저장소, 비밀 참조, 호스트, GitHub 권한을 가진다. 스킬은 `$env:<org>-dev2:deploy` 처럼 부른다 | `env:<org>-dev2`의 스킬 목록이 보이고, 허락 없는 비어드민의 호출은 카드로 간다 |
| **T13** | ssh는 MCP로만, 키 직접 읽기 금지 | 어떤 모델도 Bash ssh를 못 하고 ssh 키를 못 읽는다. 호스트 명령은 `ssh_exec` 환경 도구로 (어드민 = 등록된 모든 호스트, 환경 사용자 = 자기 호스트) | 어드민 세션 `ssh host` → 거부, `ssh_exec` → 결과 |
| **T14** | org-admin 토큰 → 봇 비밀 저장소 | 브로커가 쥐던 토큰을 봇 비밀 저장소로 옮긴다 | 브로커 제거 뒤 승인 동작 |

## 3. 4버튼의 뜻

| 버튼 | 범위 | 기록 |
|---|---|---|
| 수락 | 그 요청자 · 그 환경 사용자 · 그 스킬 · **이 스레드** (12시간) | 스레드 grant |
| 거절 | 없음. 요청자에게 알림 | 없음 |
| 이 유저에게 이 스킬 항상 | 그 요청자 · 그 환경 사용자 · 그 스킬 · 모든 스레드 | 항상 grant (스킬) |
| 이 유저에게 이 환경 전체 항상 | 그 요청자 · 그 환경 사용자의 모든 스킬과 환경 도구 · 모든 스레드 | 항상 grant (전체) |

어드민은 카드를 받지 않는다. 어드민의 크론도 마찬가지다.

## 4. 지금 → 바뀌는 것

| 지금 (23 §2) | 바뀜 |
|---|---|
| `ADMIN_USERS` | 그대로 |
| 어드민 `sandboxDisabled` | 어드민 프로필 샌드박스가 기본. 토글은 비상용으로만, 켜면 스레드에 경고 |
| `deploySandbox.users` 고정 명단 | 환경 grant에서 계산 (허락받은 환경 사용자의 도메인·작업 폴더) |
| 환경 스킬 grant (모든 환경 스킬) | 환경 grant (요청자 × 환경 사용자 × 스킬 또는 전체) |
| 어드민 개인 배포 스킬의 소유자 허락 | 그 스킬을 환경 사용자의 스킬로 옮긴다 |
| MCP grant (server-tools · devops-tools) | 환경 도구는 환경 grant로 연다. server-tools의 환경별 도구는 환경 도구로 들어간다 |
| 브로커 정책 · 건별 카드 · 대기열 | 삭제 |
| github MCP 쓰기 (게이트 없음) | 쓰기 도구는 grant가 있어야 한다. 환경 레포 쓰기는 환경 도구 `gh`로 |

## 5. 지켜야 할 것

- 비밀 저장소는 봇 프로세스와 그 MCP 서버만 읽는다. 어떤 모델도 어떤 도구·셸 철자로도 닿지 못한다 (OS 샌드박스 + 정책 1b, 어드민 포함).
- 승인·grant 기록은 모델이 쓰지 못한다. 기록은 카드 버튼과 대시보드 결정만 바꾼다.
- 샌드박스가 뜨지 못하면 모델 명령을 실행하지 않는다 (fail-closed).
- 환경 도구의 모든 쓰기는 감사 원장(append-only)에 요청자 · 환경 사용자 · grant · 명령 · 결과로 남는다.
- 환경 도구는 허용표 안의 요청만 실행한다 (GitHub: 하위 명령별 인자 표, REST 쓰기는 지정 경로만).

## 6. 남는 위험 (알고 받아들이는 것)

- 봇 App 설치 토큰(1시간)은 git push를 위해 모델 세션에 남는다. macOS 샌드박스는 자격증명 가림(mask)을 지원하지 않는다(SDK 문서: deny로 떨어짐).
  그래서 봇 App 이름으로 하는 쓰기(배포 브랜치 머지 포함)는 샌드박스 안에서도 가능하다. 배포 브랜치를 환경 사용자만 머지하게 하려면
  고객 레포의 배포 브랜치에 PR 승인 규칙을 거는 것이 근본 해결이다 — 이번 비스코프, 어드민 결정 사항으로 남긴다.
- 봇 프로세스와 그 안에서 도는 MCP 서버·허가된 플러그인 코드는 신뢰 대상이다.
- 같은 봇 안에서 요청자 신원은 봇이 붙인다. 어드민이 아닌 모델이 다른 사람인 척할 길은 샌드박스와 정책이 막는다.
