# 28 — 상세 카드: 사용자 할 일은 목표 탭 안, 변경점 뷰어는 두 모드

앞선 계약: [`26`](26-session-code-changes-spec.md) §4.2(뷰어), [`docs/current/spec/15-user-action.md`](../docs/current/spec/15-user-action.md)(사용자 할 일),
[`15`](15-dashboard-detail-deck-spec.md)(상세 카드, 탭 줄 SSOT 2026-11-03)

요약: 상세 카드의 사용자 할 일이 탭 줄 위에서 카드 절반을 차지해 대화를 밀어낸다. 이제 탭 줄은 `[작업 계획] | 목표 | 작업 … | 세부 | 사용자 작업`이다. 사용자 할 일은 맨 끝 탭 안에 들어가 누르면 보이고 다시 누르면 접히며, 대기 수는 탭 배지로 남는다. 작업 계획은 맨 앞에서 눈에 띄게 그려진다. 변경점 뷰어는 두 모드다. 데스크톱에서 상세 카드 왼쪽이 넓으면 그 자리(보드)에 파일만 띄우는 패널, 아니면 지금의 전체 화면.

## 1. 문제 (AS-IS, [LIVE] dev v0.3.56 `cda9d40a`, 하네스 = 배포 빌드 + dev 저장본 사본, 사용자 할 일 대기 1 · 완료 1)

| 화면 | 사용자 할 일 영역 | 탭 줄(목표 …) | 첫 섹션 탭(대화) | 뷰어 |
|---|---|---|---|---|
| 1440×900 | 1001,−27 439×460 | y 433 | y 471 | modal 0,0 1440×900 — 상세 카드(1000,56 440×844)까지 덮음 |
| 1024×768 | 585,−78 439×460 | y 382 | y 420 | modal 0,0 1024×768 |

- 사용자 할 일 영역은 탭 줄 위라 접을 수 없다. 1440×900에서 상세 카드 높이 844px의 54%(460px)를 차지하고, 대화는 y 471 아래 남은 곳에만 보인다.
- 뷰어는 늘 modal이라 열려 있는 동안 상세 카드를 쓸 수 없다. 다른 파일은 뷰어 안의 트리로만 고른다. 1440 폭에서는 보드 자리(1000px)가 비어 있는데도 그렇다.

## 2. 목표 · 비목표

목표
- G1 탭 줄은 `[작업 계획] | 목표 | 작업 … | 세부 | 사용자 작업`이다(SSOT_3). 사용자 할 일 전체(대기 · 끝난 것)는 맨 끝 탭 "사용자 작업" 안에 있다. 누르면 보이고 다시 누르면 접힌다.
- G2 접혀 있어도 대기 중인 필수 할 일의 수는 보인다. 사용자 작업 탭에 대기 배지가 붙는다(카드 면 배지와 같은 수).
- G2a 작업 계획은 맨 앞 탭이고 눈에 띈다. 시작을 기다리는 계획이면 그 탭이 열린 채 카드가 열린다.
- G3 상세 카드가 옆에 붙은 데스크톱에서 카드 왼쪽이 넓으면, 뷰어는 그 자리에 파일만 띄운다(패널 모드). 트리는 상세 카드의 변경점 탭이 맡는다.
- G4 두 모드를 오간다. 패널의 "전체 화면" 버튼과 전체 화면의 "패널로" 버튼(패널이 들어갈 때만)을 쓰고, 고른 것은 기기에 기억한다.

비목표
- 사용자 할 일의 내용 · 응답(완료했어요 / 안 됐어요) · Slack 카드는 바꾸지 않는다.
- diff 렌더(hunk · 줄 번호 · 층 블록)는 26 §4.2 그대로다.
- 폰 · 접힌 폴더블(< 840px)은 지금 그대로 시트 + 전체 화면이다.

## 3. 탭 줄 — [작업 계획] | 목표 | 작업 … | 세부 | 사용자 작업 (WU-A, SSOT_3)

탭 줄은 어느 레이아웃이든 맨 앞이 **작업 계획**, 맨 끝이 **사용자 작업**이다. 그 사이는 레이아웃의 탭(목표 · 작업 · 에이전트 · 산출물 · 세부)이다. 양 끝은 레이아웃이 끄지 못한다. 모든 탭은 카드를 열 때 닫혀 있고(탭 줄 규칙), 누르면 열리고 다시 누르면 닫힌다.

작업 계획
- 내용: 계획 문서(`#panel-plan`)다. 입력 필요에서 나왔다. 그래서 승인 대기 계획은 더 이상 입력 필요의 수에 들지 않고, 대화의 마지막 메시지로 옮겨 가지도 않는다.
- 라벨: 목록 아이콘 · `작업 계획` · `v2` · 상태(`승인 대기` · `계획 작성 중` · `시작됨` · `취소됨`).
- 눈에 띄게: 계획이 있으면 강조 색의 둥근 탭이다(연한 accent 바탕 · accent 글자 · 굵게). 열리면 accent로 채워진다. 시작을 기다리는 동안에는 둘레에 고리가 하나 더 생긴다.
- 시작을 기다리는 계획이 있으면 카드가 이 탭이 열린 채 열린다. 승인하려면 읽어야 하기 때문이다. 그 밖의 상태에서는 닫힌 채 열린다.
- 시작 · 취소는 머리 줄과 입력창 위 바(`#panel-plan-bar`)에 그대로 남는다. 탭을 닫아도 결정은 손에 있다.
- 계획이 없으면 비활성 탭이다(`작업 계획 없음`).

사용자 작업
- 내용: 사용자 할 일 영역(`#panel-user-actions`)이다. 대기 중인 것과 끝난 것이 다 들어 있다.
- 라벨: `사용자 작업` · 전체 수, 그리고 대기 중인 필수 할 일 수의 배지(대기 톤 — 카드 면 배지와 같은 수). title은 `사용자 작업 3 · 사용자 할 일 대기 1`.
- 할 일이 없으면 비활성 탭이다(`사용자 작업 없음`).

## 4. 변경점 뷰어 — 패널 · 전체 화면 (WU-B)

모드 판정 — 파일을 열 때, 창 크기나 상세 카드 폭이 바뀔 때:
- 패널: 상세 카드가 옆에 붙은 화면(창 폭 ≥ 840px, 카드가 열려 있음)이고 카드 왼쪽 폭(창 폭 − 카드 폭) ≥ 640px이며, 기기에 기억된 선택이 "전체 화면"이 아닐 때.
- 그 밖: 전체 화면(26 §4.2).

패널 모드
- 자리: 위는 상단 바 아래(상세 카드와 같은 선), 아래는 화면 끝, 왼쪽 끝부터 상세 카드 왼쪽 가장자리까지 — 보드가 있던 곳. modal이 아니라 상세 카드를 그대로 쓴다.
- 머리: 범위 · 레포 › 경로 · 이전/다음 파일 · 전체 화면 · 닫기. 뷰어 안 트리 패널과 "파일 목록" 버튼은 없다.
- 파일 고르기: 상세 카드 변경점 탭의 파일 줄을 누르면 패널이 그 파일로 바뀐다. 탭의 트리는 지금 파일을 강조한다.
- Esc: 패널만 닫는다(상세 카드는 남는다). 포커스가 패널에 있든 상세 카드에 있든 같다. 닫으면 포커스는 그 파일의 줄로 간다.
- 상세 카드가 닫히거나 다른 세션 카드로 바뀌면 뷰어도 닫힌다.
- 창이나 상세 카드가 넓어져 패널이 들어가지 않으면 같은 파일로 전체 화면이 된다. 다시 넓어지면 패널로 돌아간다(기억된 선택이 "전체 화면"이 아니면).
- 새 작업 버튼(FAB)은 패널이 열린 동안 숨는다(패널 오른쪽 아래를 가리므로).

전체 화면 모드
- 26 §4.2 그대로다. 머리에 "패널로" 버튼이 더해진다(패널이 들어갈 때만 보임). 누르면 기억된 "전체 화면"이 지워지고 패널로 간다.

## 5. 구현 경계

- WU-A — `src/conversation/dashboard.ts`
  - `panelBarTabIds(layoutTabs)` = `['plan', …layoutTabs, 'useractions']`. `renderPanelMidbar`이 이것으로 탭을 만든다.
  - `panelMidTabsOf`: `plan`(버전 · 상태 · tone · waiting, 없으면 empty), `useractions`(수 · `wait` = `userActionsWaiting`, 없으면 empty).
  - `panelMidTabHtml`: 계획이 있으면 `is-plan` 클래스 · `data-waiting` · 아이콘(`<i data-ui-icon="list" class="pm-icon">` — `fillUiIcons`는 이 속성 순서만 채운다) · 상태 칩. 사용자 작업은 대기 배지.
  - 마크업: `#panel-plan`을 `#panel-needs`에서 꺼내 탭 줄 바로 아래로, `#panel-user-actions`를 탭 내용 끝으로 옮긴다. CSS: 두 영역은 각자의 `data-midtab`일 때만 보인다.
  - `panelNeedsCount`에서 승인 대기 계획을 뺀다. `renderPanelPlan`은 `syncPanelNeeds` 대신 `renderPanelMidbar`를 부른다.
  - `openPanel`: 새로 열 때 `planWaitsOnReader(s)`면 `_panelMid = 'plan'`. 랜딩 대상 계획 상자는 그 탭이 열려 있을 때만.
  - en-page 카탈로그에 새 문구를 넣는다.
- WU-B — `src/conversation/code-changes-client.ts`
  - 순수 함수 `chgViewerModeFor(vw, panelW, docked, pref)` → `panel` | `full`. 기억은 `localStorage['soma-chg-viewer']`(`full` | 없음).
  - dialog `data-mode`: 패널 = `show()`, 전체 화면 = `showModal()`. 모드를 바꿀 때는 닫았다 다시 연다(`_chg.switching`이 close 정리를 막는다).
  - `chgCloseViewer()`. 패널에서는 `chgPaint`가 지금 파일 줄을 강조한다.
  - 창 `resize`와 상세 카드 `ui-resize`에서 `chgSyncViewerMode()`를 부른다.
  - `src/conversation/dashboard.ts`: `closePanel`과 세션 전환에서 뷰어를 닫는다. 상세 카드의 `ui-close`와 페이지 Esc는 패널이 열려 있으면 패널만 닫는다.

## 6. 인수 시나리오 — 리시트는 좌표를 남긴다

하네스 `e2e-detail.cjs`(배포 빌드 또는 소스, scratch 설정 폴더)를 쓰고, 출력에 rect를 남긴다.

| ID | 실행 | 기대 관측 |
|---|---|---|
| A1 | 사용자 할 일 대기 1 · 완료 1, 시작된 계획인 카드를 연다(1440×900) | 할 일 영역 · 계획 상자 안 보임; 첫 섹션 탭 y ≤ 탭 줄 bottom + 4 (AS-IS 471) |
| A2 | 탭 줄 | 순서 plan, (레이아웃 탭), useractions; plan은 `is-plan`(강조 배경 · 굵게); 사용자 작업에 대기 배지 `1` |
| A3 | 사용자 작업을 누름 → 다시 누름 | 할 일 영역이 보임 → 숨음 |
| A4 | 시작을 기다리는 계획인 카드를 연다 | `data-midtab=plan`, 계획 상자 보임, 탭은 accent로 채워짐; 탭을 닫아도 `#panel-plan-bar`(시작 · 취소) 보임 |
| V1 | 1440×900, 변경점 탭에서 파일을 누름 | `data-mode=panel`, modal 아님, 뷰어 rect x=0, 오른쪽 끝 = 상세 카드 x, 위 = 상세 카드 y; 뷰어 트리 없음 |
| V2 | 패널이 열린 채 상세 카드 트리의 다른 파일을 누름 | 패널 제목이 그 파일, 탭 트리에 `.on` 1개 |

| V4 | 1024×768(카드 왼쪽 584 < 640) | `data-mode=full`, modal, rect 0,0 1024×768 |
| V5 | 패널에서 "전체 화면" → 다시 열기 | 전체 화면(기억); "패널로" → 패널 |
| V6 | 패널이 열린 채 창을 1024로 줄임 | 같은 파일로 전체 화면 |
