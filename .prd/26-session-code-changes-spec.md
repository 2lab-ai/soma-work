## 1. 문제

- **볼 곳이 없다.** 상세 카드에는 PR 링크 칩(22)만 있다. 세션이 어느 파일을 바꿨는지, 아직 커밋하지 않은 변경이 있는지는 슬랙 스레드나 GitHub를 직접 열어야 안다. 레포 여러 개를 건드린 세션은 더 그렇다.
- **통계의 코드 변경이 비어 있다.** [LIVE] dev 인스턴스 지표 DB, 2026-10-17 ~ 2026-11-15:

  | 지표 | 건수 | 무엇과 비교 |
  |---|---|---|
  | `pr_merged` | 1,076 | — |
  | `merge_lines_added` | 4 | 머지 1,076건 중 4건만 줄 수가 있다 |
  | `pr_created` | 1,326 | — |
  | `commit_created` | 48 | PR 1,326건에 커밋 48건 |

  원인 [RULES] `src/metrics/tool-result-interceptor.ts`: 머지 줄은 모델이 `gh pr view --json additions,deletions,number`를 직접 실행해야만 생기고(머지 여부를 보지 않아 머지 안 된 PR도, 다시 보면 또 센다), 커밋 줄은 `git commit` 출력이 Bash 결과에 그대로 찍혀야만 생긴다(`-q`, 파이프, `(root-commit)`, 서브에이전트 셸이면 빠진다).
- **모델이 모른다.** 턴을 끝낼 때 세션 폴더에 커밋하지 않은 변경이 남아 있어도 모델이 그것을 보는 곳이 없다.

## 2. 목표 · 비목표

목표
- G1 세션별 변경 스냅샷: 세션 폴더의 git 체크아웃 전부 + 세션이 만든 PR 전부, 네 층으로 (§3).
- G2 변경점 탭: 요약 · 범위 선택(전체 · 층 · PR 하나) · 레포 → 디렉터리 → 파일 트리 (§4.1).
- G3 전체 화면 뷰어: 왼쪽 트리 패널, 오른쪽 GitHub식 diff — 줄 번호 두 열, 추가 · 삭제 색 (§4.2).
- G4 통계의 머지 줄 · 커밋 줄이 실제 머지 · 커밋과 같은 값 (§5).
- G5 모델이 GET_SESSION으로 요약을 읽고, 커밋 안 한 변경이 있으면 턴 컨텍스트에서 본다 (§6).

비목표
- 대시보드에서 커밋 · 푸시 · PR 만들기 같은 쓰기. 보기만 한다.
- 세션 폴더 밖 체크아웃(세션이 `cd`로 나간 곳), GitHub 밖 PR(GitLab 등).
- 줄 단위 코멘트 · 리뷰.

## 3. 네 층 — 겹치지 않는다

| 층 | 뜻 | 출처 |
|---|---|---|
| 커밋 안 함 | 작업 트리 + 인덱스 vs HEAD, 추적 안 하는 새 파일 포함 | 체크아웃의 git |
| 커밋함 | HEAD에 있지만 아직 어느 PR에도 없는 커밋 | 체크아웃의 git — 기준점은 이 브랜치 PR의 head(HEAD의 조상일 때 — 단 원격 기본 브랜치와의 merge-base가 그 head를 품으면 merge-base), 없으면 원격 기본 브랜치와의 merge-base, 원격도 없으면 세션 시작 뒤 첫 커밋의 부모 |
| PR | 세션이 만든 열린 PR(초안 포함)의 파일 | GitHub `pulls/{n}` · `pulls/{n}/files` |
| 머지됨 | 세션이 만든 PR 중 머지된 것의 파일 | 같음 |

- **세션이 만든 PR** = 세션 카드에 기록된 PR(22 `linkHistory.prs` + 현재 PR) 중 GitHub의 생성 시각이 세션 시작 이후인 것. 리뷰하러 열었던 남의 PR은 세지 않는다. 닫힌(머지 안 된) PR은 목록에 "닫힘"으로만 보이고 층에 들어가지 않는다.
- **GitHub이 답하지 않는 PR**(SSOT_7, 2026-11-19 — 호스트 토큰이 읽지 못하는 비공개 레포): 세션 폴더에 그 레포의 클론이 있으면, 클론의 원격 기본 브랜치에서 그 PR을 머지한 커밋을 찾아 읽는다 — `Merge pull request #N from …`(머지 커밋: 두 번째 부모가 PR head, 파일 = merge-base부터 head까지) 또는 `제목 (#N)`(스쿼시: 그 커밋이 PR). 네트워크도 토큰도 쓰지 않는다. 세션 시작 전에 머지된 것은 세지 않는다(생성 시각 대신 머지 시각). 머지됨 층으로만 들어가고(열린 PR은 그런 커밋이 없다), 행 제목 툴팁이 출처를 말한다. 그래도 못 읽은 PR은 저장본 `unreadPrs`로 남아 탭의 PR 줄에 "읽지 못함"과 이유가 붙는다 — 조용히 "파일 0"이 되지 않는다.
- **한 번에 안 오는 diff**: 범위 전체 패치가 git 출력 한도(16 MiB)를 넘으면(생성된 데이터 파일 하나로도 넘는다) 파일마다 따로 읽는다 — 코드가 데이터(JSON · 표 · lock · 지도 · 축소 파일)보다 먼저, 작은 변경부터, 범위당 2 MiB까지. 5,000줄 넘게 바뀐 파일은 패치 없이 줄 수만. 커밋함 층과 위의 로컬 PR 읽기에 같이 쓴다.
- 같은 파일이 두 층에 있을 수 있다(PR로 올린 뒤 또 고침). 트리의 그 파일 줄은 층 표시를 모두 달고, 뷰어는 층마다 패치를 따로 보여 준다.
- "전체" 범위 = 네 층의 합집합. 숫자(+/−)는 층마다 따로 세고 전체는 그 합이다.

## 4. 화면

### 4.1 변경점 탭

- 섹션 탭: 대화 · 작업 로그 · **변경점** · (오른쪽 끝) 에이전트 트리. 작업 로그 탭이 보이는 레이아웃(어드밴스드의 섹션 줄, 미니멀의 대화 · 작업 로그 탭)이면 변경점도 보인다.
- 위에서부터:
  1. 요약 줄 — `레포 2 · 파일 14 · +820 −61 · 11:42 기준` + 새로 고침. 스냅샷이 아직 없으면 "아직 변경 기록이 없습니다".
  2. 범위 칩 — `전체 14` `커밋 안 함 3` `커밋함 2` `PR 6` `머지됨 5`(0인 층은 흐리게, 눌러지지 않음).
  3. PR 목록 — 세션이 만든 PR마다 한 줄: `#1293 제목 · 머지됨 · +500 −20 · 파일 9` + GitHub 링크. 줄을 누르면 범위가 그 PR 하나가 되고, 다시 누르면 전체로 돌아간다.
  4. 파일 트리 — 루트 아래 레포(`owner/repo`, GitHub 원격이 없으면 폴더 이름), 그 아래 디렉터리, 그 아래 파일. 자식이 하나뿐인 디렉터리 사슬은 한 줄로 접는다(`src/conversation`). 파일 줄: 상태 글자(A · M · D · R) · 이름 · `+n −m` · 층 표시. 디렉터리와 레포 줄은 접고 펼 수 있고 합계를 단다.
- 읽기 권한은 카드와 같다(SSOT_6, 2026-11-17 "다른 사람의 작업도 변경점 읽을수 있게 해줘"): 카드가 보이는 사람이면 변경점도 읽는다. 공개 채널의 작업은 로그인한 누구나, 비공개 작업(DM · 비공개 채널, #1315)은 소유자와 어드민만 — 그 밖의 사람에게는 작업이 없는 것처럼 404. (처음엔 작업 로그처럼 소유자 · 어드민만이었다. 작업 로그는 그대로다.)

### 4.2 뷰어 — 패널 · 전체 화면

- 파일 줄을 누르면 뷰어가 그 파일에서 열린다. 범위는 탭의 범위를 따른다. 모드는 둘이다([`28`](28-detail-card-user-tasks-and-viewer-panel-spec.md) §4).
  - **패널**: 상세 카드가 옆에 붙은 데스크톱에서 카드 왼쪽이 640px 이상이면 보드 자리(상단 바 아래, 왼쪽 끝 ~ 카드 왼쪽 가장자리)에 파일만 띄운다. modal이 아니다. 트리 패널 대신 상세 카드의 탭 트리가 지금 파일을 강조하고 다른 파일을 고른다. Esc는 패널만 닫는다. 카드가 닫히거나 다른 세션으로 바뀌면 같이 닫힌다.
  - **전체 화면**: 그 밖의 경우. 아래 머리 · 왼쪽 패널 · 오른쪽 설명이 이 모드다.
  - 머리의 **전체 화면** · **패널로**(패널이 들어갈 때만)로 연 파일 그대로 모드를 바꾼다. 기기에 "전체 화면" 선택을 기억한다. 창 · 카드 폭이 바뀌면 모드가 따라간다.
- 머리: 범위 이름 · 레포 › 경로 · 이전/다음 파일 · 닫기(Esc 포함).
- 왼쪽 패널: 같은 트리(현재 파일 강조). 다른 파일을 누르면 오른쪽이 바뀐다. 좁은 화면(< 720px)에서는 "파일" 버튼으로 패널을 열고 닫는다.
- 오른쪽: 파일 머리(경로 · 상태 · `+n −m`), 그 아래 층마다 블록 — `커밋 안 함 · <체크아웃 폴더>` / `PR #1293 · 머지됨` — 블록 안은 hunk 머리(`@@ -10,6 +10,8 @@`)와 줄: 왼쪽 줄 번호 · 오른쪽 줄 번호 · 부호 · 코드. 추가는 초록, 삭제는 빨강 배경. 바이너리 · 너무 큰 패치는 그렇다고 쓰고 GitHub 링크(PR이면)를 준다.

## 5. 통계

- 머지 줄(`merge_lines_added`): 세션이 만든 PR이 머지된 것을 수집기가 처음 볼 때 한 번. 값 = GitHub의 additions · deletions, 시각 = GitHub의 머지 시각, id = PR URL로 정한 값 — 몇 번 다시 보더라도 지표 저장소의 id upsert로 한 줄이다. 세션 카드의 `mergeStats`도 같은 PR을 두 번 더하지 않는다.
- 커밋 줄(`commit_created` · `code_lines_added`): 세션 시작 뒤 그 체크아웃에서 만든 커밋(HEAD reflog의 `commit` 계열 항목). 값 = 그 커밋의 numstat, 시각 = reflog 시각, id = 커밋 sha로 정한 값.
- 명령 출력 파싱(`gh pr view` JSON, `git commit` 출력)은 지표를 더 이상 만들지 않는다 — 출처는 수집기 하나.
- 고정 id 이벤트는 먼저 쓴 것이 남는다(first writer wins): 같은 PR을 다른 세션이 링크해도 지표의 주인이 옮겨 가지 않는다.
- 옛 파서가 이미 센 것은 다시 세지 않고, 옛 파서가 쓴 것이 진짜 머지를 대신하지도 않는다. 경계는 이 호스트가 수집기로 세기 시작한 시각(`DATA_DIR/code-changes/.counting-since.json`, 첫 실행 때 고정)이다: 커밋은 그 뒤의 것만 센다. 세션 `mergeStats`에 번호로만 있는 옛 기록(옛 파서는 기록과 지표 행을 함께 썼다)은 그 PR이 경계 전에 머지됐으면 건너뛰고, 경계 뒤에 머지됐으면 열린 PR을 본 기록이었으니 머지를 센다 — 어느 쪽이든 카드의 기록은 GitHub 값으로 바꾼다. 번호만 있는 옛 기록은 세션에 그 번호의 PR이 하나뿐일 때만 같은 PR로 본다.
- 지표 행이 써진 뒤에만 카드의 머지 기록을 쓰고, 행 하나라도 못 쓰면(데이터베이스와 일별 파일 모두 실패) 그 결과 전체를 다시 넘긴다 — 행은 고정 id · 먼저 쓴 쪽 우선이라 두 번 써도 늘지 않는다. 데이터베이스 대신 일별 파일로 넘친 행도 그 규칙을 지닌다(가져올 때 먼저 있던 행을 바꾸지 않는다).
- 세션이 쉬는 동안 머지된 PR: 세션 PR 감시(#928, 60초마다 살아 있는 세션의 현재 PR)가 머지를 보면 그 세션을 다시 모은다 — 같은 머지는 고정 id라 한 줄이다. 닫힌(terminated) 세션의 PR이 그 뒤 머지되면 세지 않는다(loop G3).

## 6. 모델

- GET_SESSION의 `session.codeChanges`: 갱신 시각, 층마다 파일 수 · +/− · 레포별 경로 몇 개, PR 목록(번호 · 상태 · +/−). 패치는 넣지 않는다.
- 턴 컨텍스트: 직전 스냅샷에 커밋 안 함 또는 커밋함(PR 없음) 변경이 있으면 `<context>`에 한 줄 — 레포 · 폴더 · 파일 수 · 경로 앞 몇 개. 없으면 아무것도 붙지 않는다.
