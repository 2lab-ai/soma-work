## 0. 한 줄 정의

크론이 만든 세션은 잡 이름으로 시작해 일이 이름을 얻으면 그 이름으로 바뀌고, 카드 머리에 CRON 뱃지를 달고 보드 위
CRON 레인에 잡별로 모인다. 통계 줄과 inbox 사이에는 llmux 프로바이더 그룹별 잔여율과, 지금부터 7일까지 각 계정이
언제 다시 채워지는지를 보여 주는 쿨타임 타임라인이 있다.

## 1. 요건 → 계약 (SSOT 2026-10-23, T1–T10)

| T | 요건 | 계약 |
|---|---|---|
| T1 | `Direct (skipDispatch)` 대신 잡 이름으로 시작 | 크론 발동 이벤트가 `cron:{jobId, jobName}`을 싣는다(`cronOrigin`, 주입·대기열·새 스레드 3경로). 디스패치 우회 분기에서 `resolveCronOrigin`(구조화 필드만, `[cron:…]` 텍스트 파싱 없음)이 있으면 제목 = 잡 이름, 세션에 `cronJob` 스탬프. 그 밖의 우회(오토 리줌·goal·인시던트)는 `Direct (skipDispatch)` 유지. 기존 세션에 주입된 크론은 그 세션을 스탬프하지 않는다. |
| T2 | 이름이 명확해지면 자연스럽게 교체 | 잡 이름 제목은 `titleProvisional`. 턴 요약 콜백(`canApplySummaryTitle`)과 링크 파생 제목(`setSessionTitle`)이 임시 제목을 교체하고 표식을 지운다. 명시적 제목 변경(`updateSessionTitle`: UPDATE_SESSION·PR·이슈)도 표식을 지운다. 교체 후 대시보드 카드를 즉시 푸시(`scheduleLiveSessionUpdate`)하고, 카드는 새 제목을 페이드인(`is-renamed`, reduced motion은 불투명도만). `cronJob`·`titleProvisional`은 재시작 후에도 남고 `cronJob`은 아카이브에도 남는다. |
| T3 | 좌측에 항상 CRON 뱃지 | `KanbanSession.cronJob`이 있는 카드는 머리 맨 앞이 ✦ 대신 시계 + `CRON` 뱃지(상태색, 툴팁 = 잡 이름). 제목이 바뀌어도 뱃지는 남는다. |
| T4 | 크론은 별도 상태 라인 | inbox 안, 칸 위 `#cron-lane`. 크론 카드는 NEEDS YOU / RUNNING / DONE에서 빠진다(`planCronLane`). 응답을 기다리는 잡이 레인 맨 앞이고 레인 머리에 `▲ 응답 필요 n` · `● 실행 중 n`. |
| T5 | 같은 잡을 묶고 클릭하면 지난 잡 | 잡 1개 = 타일 1개: 스케줄 문장(UTC cron, 시각은 보는 사람 시간대), 다음 실행, 최근 12회 막대(오래된→최신), 현재 상태, 그리고 잡의 최신 실행 카드(응답 대기 > 실행 중 > 최신). `지난 실행 N`·막대 클릭 = 오른쪽 서랍: 스케줄·다음 실행·실행 방식, 실행별 행(기호·시각·예약/▶수동·소요·토큰·비용·오류, 작업 로그/대화 기록/Slack). Esc·바깥 클릭으로 닫힘. 데이터 `GET /api/dashboard/cron?userId=`(프롬프트 비노출, 실행은 `executedAt` 최신순으로 다시 정렬, 세션은 라이브 레지스트리·14일 아카이브에서 연결, 토큰·비용은 그 잡이 만든 세션일 때만). 새 스레드 실행도 이제 `sessionKey`를 기록한다. |
| T6 | 크론 UI 리서치 | §3. |
| T7 | 서머리와 inbox 사이에 프로바이더 그룹별 가용량 + 다음 공급 | `#capacity` 섹션. `GET /api/dashboard/capacity` → `buildCapacityView`. llmux 조회 30초 캐시·single-flight, 실패는 고정 사유(`llmux unreachable` · `llmux admin credential required` · `llmux error (HTTP n)`)의 `available:false`, 500 없음. llmux를 쓰지 않는 배포(`ccp`)는 섹션 숨김. |
| T8 | 타임라인 UI 리서치 | §3. |
| T9 | 소진·부족 시 다음 공급 시각을 한눈에 | 그룹 상태 `empty`(가용 계정 0) · `low`(20% 미만) · `ok` · `unknown`. empty = `다음 복귀 <계정> · 2h 14m 후 (16:03) · 5h 창`을 앞세우고 지금→복귀 구간 빨간 음영, low = 다음 공급(복귀·리필 중 이른 것) + 호박색 음영. `nextRefill`(쓸 수 있는 계정의 창 리셋)과 `nextReturn`(차단 계정 복귀)은 따로 계산한다. 카운트다운은 분 단위 버림(3h59m은 `3h 59m`). |
| T10 | 구독 티어별 색 | llmux는 플랜을 주지 않는다(내부 tier = "max"뿐). 우선순위: `SOMA_LLMUX_ACCOUNT_TIERS`(`group:name=tier`) → llmux가 정확한 문자열(`default_claude_max_20x` 등)을 줄 때 그것 → 기본값(codex `ai1`·`ai2` = Pro $200, `ai5`·`ai6` = Pro $500) → 미지정. bare `max`로 추측하지 않는다. 색 = 프로바이더 안의 상위/하위(Okabe-Ito 주황 #E69F00 / 파랑 #0072B2), 미지정 = 회색 테두리, 마커에 티어 문자(`x20` · `$500`) 병기. |

## 2. 숫자의 정직성 (trinity 범위 합의 D5/D6)

> **v2(2026-10-25)가 이 절의 가용량 규칙을 대체한다** — 단순 평균 잔여율·마커 타임라인 대신 계정분과 재생 예측. §6 참고. 크론 관련 내용은 그대로다.

- llmux `/llmux/status`는 창별 **사용률(0..1)과 리셋 시각**만 준다. 화면의 모든 수는 잔여율 %이고 "토큰량"이라 부르지 않는다.
- 계정 가용 = 묶이는 창(5h·7d) 중 작은 잔여. 모델별 주간 창(Fable 등)은 그 모델만 묶으므로 마커로만 보인다.
- 그룹 % = 측정된 계정의 **단순 평균**. 플랜 가격은 토큰 비율이 아니므로 티어는 색·문자일 뿐 가중치가 아니다.
- 리셋이 지난 창(오래된 스냅샷)과 측정값이 없는 계정은 **미확인** — 평균에서 빼고 `미확인 n`으로 센다.
- 차단 계정의 복귀 = 걸린 차단이 모두 풀리는 시각(소진 창 리셋들과 쿨다운 중 가장 늦은 것). 스케줄러 한도 차단은 가장 찬 창의 리셋. 인증 실패는 복귀 시각을 만들지 않는다(`복귀 미정`).
- 2분 이하의 쿨다운(llmux가 버스트 뒤 물러서는 `cooldown 6s` 류)은 공급 문제가 아니라 스로틀이다. 계정을 0으로 만들지 않고 복귀 마커도 만들지 않는다(`TRANSIENT_COOLDOWN_SECS`).
- llmux 계정 이름은 실제로 `group:local@domain`이다(`claude:ai7@…`). 타임라인 라벨은 `local`(`ai7`)이고, 같은 그룹에 `local`이 겹치면 도메인을 붙인다. 티어 키는 전체 이름·`group:local`·`local` 어느 형태로 써도 맞는다.

## 4. 범위 밖 (기록)

- 형제 인스턴스의 크론 잡·실행 기록은 읽지 않는다. 형제의 크론 카드는 보드 병합으로 들어와 `다른 인스턴스` 타일로 묶인다(스케줄 없음).
- 이 변경 전에 만들어진 크론 세션에는 `cronJob`이 없다(일반 칸에 남고, 다음 실행부터 레인으로 간다).
- Slack 스레드 헤더 제목은 같은 `title`을 쓰므로 잡 이름 → 실제 이름으로 함께 바뀐다. Slack 쪽 CRON 뱃지는 없다.
- (2026-10-26 갱신) llmux 0.2.26부터 계정별 플랜을 보고한다(Claude `rate_limit_tier`, Codex `plan_type`: `pro` = $200, `promax` = $500; llmux `.prd/25`). 우선순위: `SOMA_LLMUX_ACCOUNT_TIERS` → llmux 보고값 → 기본값. 이전 llmux에서는 아래가 그대로다.
- Claude 계정의 x5/x20 매핑은 운영자가 `SOMA_LLMUX_ACCOUNT_TIERS`로 지정해야 색이 붙는다(llmux가 플랜을 주지 않음).

## 6. v2 — 두 기준과 재생 예측 (2026-10-25)

**요건(사용자)**: 1차 화면은 의도는 맞았지만 실사용에서 답을 주지 못했다. 보는 사람이 알아야 할 것은 ① 지금 몇 계정분이
남았는가, 그리고 그것을 전체 대비 %와 최대 계정 몇 개 분량으로 한 번에 보는 것이다. 이 양은 두 기준으로 보여야 한다. 하나는
지금 당장 쓸 수 있는 양으로 Claude는 5h 기준이고, 다른 하나는 주간 기준이다. Codex는 주간 하나만 있다. ② 앞으로 들어올 양에서
5h 리필과 주간 리필이 한눈에 구분되어야 한다. 이 요건으로 목업을 만들고 trinity 리뷰를 통과한 뒤 구현한다.

**리서치 [REF]**: Codex CLI `/status`는 "5h limit 95% left / Weekly limit 36% left"처럼 두 창을 같은 형식의 두 줄로 보여 준다.
CodexBar의 메뉴바 미터는 위가 세션(5h), 아래가 주간인 2단 구성이다. Stephen Few의 불릿 그래프는 주 측정값(진한 막대)과 비교값(옅은 띠)을
한 막대에 겹친다. 지금 ≤ 이번 주이므로 한 막대 안에 포갤 수 있다.

**계약**
- 단위는 **계정분**이다. 계정별 티어 `weight`(x20 = 1, x5 = ¼, $500 = 1, $200 = 0.4)에 잔여율을 곱해 더한다. 토큰 수가 아니라 정규화 추정이다.
  티어 미지정 계정: Claude는 Max x20(가중치 1)으로 세고 `tierAssumed`로 밝힌다(카드 흐린 줄 `티어 미지정 N(x20 가정)`, 접힌 칩 `⚠ x20 가정 N`). Codex는 합계에서 빼고 따로 센다.
  근거: 2026-10-26 한 dev 호스트에 `SOMA_LLMUX_ACCOUNT_TIERS`가 없어 Claude 15계정이 모두 빠지고 "계산 불가"가 됐다. 운영자 결정: Claude 미지정 = x20 가정, 가정이라고 표시(`추정 N`과는 따로 센다).
- 계정의 **지금** = min(5h 잔여, 주간 잔여)이고, 차단 중이면 0이다. 계정의 **이번 주** = 주간 잔여이고, 보류 계정은 합계 밖이다.
  Claude는 항상 지금 줄을 둔다. 다른 프로바이더는 llmux가 five_hour를 줄 때만 둔다.
- **차단은 원인별로 따로 추적한다.**
  - 주간 한도(`7d …`)는 주간 리셋 때 풀린다.
  - 5h 한도(`5h …`)는 5h 리셋 때 풀린다.
  - 120초를 넘는 쿨다운은 `cooldown_until`에 풀린다.
  - 모델별 한도(`fable …`)는 그 창의 리셋 때 풀린다.
  - 풀리는 시각을 모르는 차단(일시정지, `status: paused`, 인증 실패, 끝 시각 없는 쿨다운, 리셋 시각 없는 한도, 알 수 없는 사유)은 **보류**다. 합계에서 빼고 복귀를 그리지 않는다.
  - 이미 지난 리셋은 차단을 푼다.
- **추정과 미측정**
  - 지난 리셋은 그 창을 가득으로 친다. 이 추정이 실제로 숫자를 결정할 때만 `추정 n`으로 표시한다.
  - 차단되지 않았는데 5h 측정이 없는 계정은 지금에서 뺀다(`5h 미측정 n`).
  - 차단 중이고 5h 측정이 없는 계정은, 풀릴 때까지 5시간 이상 쉬게 될 때만 가득으로 친다. 그보다 빨리 풀리면 미측정으로 둔다.
  - 가장 오래된 llmux 측정 시각(`last_refresh_ms`)을 표시한다. 셀 수 있는 계정이 없으면 `계산 불가`로 표시한다.
- **재생**
  - 계정별 이벤트(5h 리셋, 주간 리셋, 차단 해제)를 시간순으로 적용한다. 같은 시각이면 해제 → 5h → 주간 순서다. 병합하지 않는다.
  - 각 이벤트는 가중된 전후 차이 `dNow`·`dWeek`를 갖는다. 아무것도 바꾸지 않는 리셋(이미 가득한 창)은 빠진다. 범위는 7일이다.
- **화면**(카드 = 구독 프로바이더. API 키 풀은 제외)
  - 두 줄 헤더 `x / 합계 계정분 · %`와 다음 증가(원인 리셋 포함)
  - 상한 설명 줄(쓸 수 있는 n계정 중 5h가 상한 a · 주간이 상한 b, 5시간 안에 5h 리셋으로 풀릴 양)
  - 칸 막대, 계정별 막대, 차단·제외·추정·측정 시각 칩
  - 5h 레인(0–5h, ● 청록)과 주간 레인(0–7d, ◆ 보라). 계단선과 원인별 분해 줄이 붙고, ■는 차단 해제다.
  - 5시간 안에 지금을 올릴 이벤트가 없으면 5h 레인을 한 줄로 접는다.
  - 600px 미만에서는 레인 대신 다음 리필 상위 6건 목록을 보여 주고, 지금 증가분과 주간 증가분을 따로 적는다.

## 7. 단순화 카드 (2026-10-25, 사용자 피드백 "알아볼 수 없다")

§6의 v2 카드는 정확했지만 프로바이더마다 요소가 10종을 넘어 읽히지 않았다. 두 줄 헤더, 설명 줄, 칸 막대, 칩, 계정별 막대 17개, 레인 두 개(9px 라벨 칩 20여 개), 분해 문장, 전문 용어가 한 카드에 다 들어가 있었다.
사용자가 고른 안은 **막대 두 줄** + **v1식 타임라인 하나**다.
- 막대: `5시간 · 지금 쓸 수 있음`, `일주일 · 이번 주 남음`. 각각 `x / 합계 계정 · %`와 "다음 …" 한 줄로 보여 준다.
- 공개 줄: 0이 아닌 것만 흐리게 한 줄로 보여 준다(반영·차단·제외·추정·5시간 미측정·측정 시각).
- 타임라인: ●는 5시간 막대가 늘어나는 것으로 라벨을 위에, ◆는 일주일 막대가 늘어나는 것으로 라벨을 아래에 둔다. 라벨이 겹치면 합친다. 5시간 쪽으로 늘어날 양이 없으면 범례에 그렇게 적는다.
- 반올림: %는 실제 비율로 계산하고 가득일 때만 100%로 표시한다. 합계로 반올림되는 수는 소수 둘째 자리까지 보인다.
- 뺀 것: 레인, 칸 막대, 계정별 막대, 설명 줄, 칩, 분해 문장, 전문 용어, 범례, 2열 분기.
- 서버 모델(§6)은 그대로다.

목업 v5 → v5b (2026-10-25, 리서치 [`docs/misc/research/2026-10-25-capacity-dual-window.md`](../docs/misc/research/2026-10-25-capacity-dual-window.md)):
- 근거: claude.ai 사용량 화면, Codex `/status`, CodexBar는 모두 같은 모양 막대 두 줄을 쓴다(위 5시간, 아래 일주일). 풀 단위라 "계정분"을 덧붙인다.
- 폰: 라벨과 값은 첫 줄, 막대는 카드 폭 전체의 둘째 줄, "다음 …"은 셋째 줄에 둔다(이전에는 막대가 약 70px).
- 접힌 칩: 두 값 모두 `x/합계 %`(`Claude 지금 5.2/16.0 33% · 주 5.6/16.0 35%`). 840px 미만에서는 칩 줄이 감기고, 칩은 두 값 사이에서만 끊긴다.
- 접힌 칩 경고: 가장 오래된 측정이 하루를 넘었거나 계정의 80% 미만만 반영되면 `⚠ 5일 전 · 3/5 반영`을 붙인다. 툴팁과 스크린리더 이름에도 넣는다.
- "다음 …": `다음 +1.0계정 · 1시간 23분 후`. 막대 자기 리셋이 아닐 때만 원인을 붙이고, 계정 이름은 툴팁으로 옮긴다. 일주일 한도에 묶인 5시간 막대는 `일주일 한도에 묶임 · 다음 …`으로 쓴다.
- 공개 줄: `16/17 반영(차단 6 포함) · …`. 차단 수가 반영 수 안에 포함된다는 것을 밝힌다.
- ● 범례: 7일 안의 5시간 증가가 모두 0.05 미만이지만 합이 0보다 크면 그 합을 `— 7일 안 +0.1계정 미만`(합 0.05 미만)이나 `— 7일 안 +0.1계정`처럼 쓰고, 정말 0일 때만 `— 7일 안에 늘어날 양 없음`으로 쓴다. 막대의 "다음" 줄과 칩 툴팁도 같은 `capGain` 문구를 쓴다(목업 v5 r5 fable, r6 grok).
