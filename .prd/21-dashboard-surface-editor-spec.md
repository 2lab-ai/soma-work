## 3. 모델 (`src/view-layout.ts`)

- 저장: `UserSettings.dashboardLayout`(유저마다). 고친 화면만 저장한다. 나머지는 기본 프리셋이라서, 나중에 기본 프리셋이 바뀌면 고치지 않은 화면은 그대로 따라온다.

```
DashboardLayoutDoc {
  v: 1
  presets?: { '1'|'2'|'3': { minimal?|advanced?: { card?, open?, detail? } } }   ← 고친 화면만
  active?:  { card?: '1'|'2'|'3', detail?: '1'|'2'|'3' }                         ← 화면마다 기본 안
  thread?:  { mode: 'follow' | 'theme' | 'custom', custom?: ThreadLayout }      ← 스레드 카드
}
```

- 기본 안을 정하는 순서: 화면마다 고른 안(`active`), 없으면 빠른 전환(`dashboardPlan`, `.prd/20`), 그것도 없으면 1안. 태스크 카드의 안이 접힌 면(`card`)과 펼친 카드(`open`)를 함께 정하고, 디테일 카드(`detail`)는 자기 안을 쓴다.
- 레이아웃은 모두 `{ id, on, opt? }`의 순서 있는 목록이다. 목록에는 카탈로그의 모든 항목이 한 번씩 들어 있다. 모르는 id는 버리고, 빠진 id는 끈 채로 끝에 붙인다. 그래서 나중에 항목이 늘어도 숨긴 채로 나타날 뿐, 화면을 흐트러뜨리지 않는다.
- 펼친 카드 기본 프리셋에는 칸마다 다른 순서(`byCol`, 어드밴스드의 옛 본문)가 있다. 편집하면 그 순서는 없어지고, 모든 칸이 같은 순서를 쓴다(편집기가 그렇게 알린다).

항목 카탈로그(`LAYOUT_CATALOG` — 편집기의 이름과 설명):

| 화면 | 구역 | 항목 |
|---|---|---|
| 카드 (접힘) | 머리 | 제목(항상), 상태와 시간(항상), 종류 아이콘, 별, 소유자 |
| | 본문 줄 | 요약 줄(옵션: 물을 때만 · 항상), 현재 작업, 서브에이전트, 토큰 · 비용 줄, 산출물 줄(옵션: 1–4개) |
| | 맨 아래 오른쪽 | 진행 n/m, 컨텍스트 %, 지시 첨부 수, PR, 산출물 수, 비용, 토큰, 모델 |
| 카드 (펼침) | 항상 맨 위 | 액션 · 입력 필요(항상), ☆ 즐겨찾기 버튼 |
| | 그 아래 | 작업 창, 에이전트 트리, 최근 지시와 답변, 산출물, 목표 줄, 이슈 · PR 링크, 모델 · 추론 강도 |
| 디테일 카드 | 머리 | 머리 · 상태 바(항상), 부제 |
| | 위쪽 | 세션 정보, 목표, 입력 필요(옮길 수 있지만 항상 보임), 산출물 |
| | 본문 | 작업 목록(실행 표 · 체크리스트 · 한 줄 · 숨김), 작업 목록 높이(⅓ · ½ · ⅔), 에이전트 탭(항상 · 서브에이전트 있을 때 · 숨김), 채팅(항상), 에이전트 머리 · 경로, 작업 로그 · 트리 탭, 처음부터 펼침 |
| | 아래 | 입력창(항상), 모델 · 추론 강도 |
| 스레드 카드 | 머리 줄 | 제목(항상) |
| | 정보 줄 | 소유자, 워크플로, 모델, 컨텍스트, 비용, 토큰, 현재 작업, 진행 n/m |
| | 링크 · 상태 | 대시보드 링크, 링크 기록, 현재 링크, 종료 표시 |

- 카드 면의 줄 순서는 `@2lab.ai/ui` 0.17.0의 `card.rows`가 그린다. 맨 아래 칩은 전부 호스트 칩(진행 · 컨텍스트도)이라 순서를 자유롭게 바꿀 수 있다.
- 디테일 카드의 위쪽 순서는 CSS `order`(`--o-<id>`, `applyViewMode`)로 정한다. 작업 목록과 채팅의 상하 순서는 바꾸지 않는다. 채팅 높이 계산(`sizePanelSections`)이 작업 목록 아래를 전제로 한다.

## 4. 편집기 화면 (`src/conversation/settings-layout-tab.ts`)

```
[기본 안]  태스크 카드 [1안 ▾]  디테일 카드 [1안 ▾]  스레드 카드 [태스크 카드 따라감 ▾]  한 번에 [1안][2안][3안]
[편집할 안: 1안 | 2안 | 3안]  [미니멀 | 어드밴스드]  (수정됨)        저장됨  [되돌리기] [이 화면 기본값으로]
[카드 (접힘) | 카드 (펼침) | 디테일 카드 | 스레드 카드 (슬랙)]
┌ 항목 ─────────────────────────────┐ ┌ 미리보기 [실행 중 | 질문 대기 | 완료] ┐
│ 머리          제목 (항상) …        │ │  <ui-agent-inbox> — 보드의 카드 그대로 │
│ 본문 줄  ⋮⋮ 현재 작업  [●] ↑ ↓    │ │  펼침: 액션 · 질문 · 고른 부분       │
│ 맨 아래  ⋮⋮ 모델      [●] ↑ ↓    │ │  디테일: 패널 배치도 · 슬랙: 블록 모양 │
└───────────────────────────────────┘ └──────────────────────────────────────┘
```

- 휴대폰(900px 미만)에서는 미리보기가 위, 항목이 아래로 온다.
- "따로 설정"은 지금 스레드 카드가 보여 주는 것(태스크 카드에서 옮긴 것)에서 시작한다. "서버 슬랙 테마"는 `config.json`의 `ui.threadheader`와 테마 명령을 그대로 쓴다.
- 저장: 바꿀 때마다 문서 전체를 `PUT /api/settings/dashboard-layout`(350ms 디바운스, 한 번에 하나, 도중에 바뀌면 끝난 뒤 다시). 편집마다 번호(`_layRev`)를 올리고, 응답은 그 PUT 뒤에 편집이 없을 때만 받아 쓴다. 저장되지 않은 편집은 탭을 다시 열어도 서버 사본으로 덮지 않는다. 서버가 검사한 문서를 다시 받아 쓰고, 대시보드의 기기 사본 `soma-view-layout`도 같이 고친다. 대시보드는 로드할 때, 탭으로 돌아올 때, bfcache에서 돌아올 때 다시 읽는다.

## 5. 스레드 태스크 카드 — 판단

**판단: 표준 하나로 묶는다.** 스레드 카드는 태스크 카드와 같은 항목 이름을 쓰고, 기본값은 "태스크 카드 따라감"이다. 슬랙에서만 의미 있는 항목(대시보드 링크 · 링크 기록 · 워크플로 · 종료 표시)은 스레드 카드에만 있다. 따로 두고 싶은 유저는 "따로 설정"을 고른다. 이유: 둘을 따로 두면 같은 항목(모델, 비용, 현재 작업)을 두 번 고쳐야 한다. 그렇다고 하나로만 묶으면 슬랙의 링크 줄을 설정할 길이 없다.

변환(태스크 카드 → 스레드 카드, `followThreadLayout`. 클라이언트 미리보기와 서버가 같은 결과를 내는지 테스트로 고정):

| 태스크 카드 | 스레드 카드 |
|---|---|
| 제목 | 머리 줄 |
| 소유자 (머리) | 정보 줄: 소유자(@멘션) |
| 현재 작업 (본문 줄) | 정보 줄: `▶ 작업` |
| 토큰 · 비용 줄 | 정보 줄: 토큰, 비용 |
| 진행 n/m · 컨텍스트 % · 비용 · 토큰 · 모델 (칩) | 정보 줄: 같은 항목, 칩 순서대로 |
| PR (칩) | 링크 줄: 링크 기록 |
| 요약 줄 · 서브에이전트 · 산출물 · 지시 첨부 · 별 · 종류 | 슬랙에는 없음(편집기에 "슬랙 X") |
| (항상) | 링크 줄: 대시보드 링크 · 상태 줄: 종료 표시 |

- 슬랙 쪽(`@soma/slack`): 스레드 헤더 필드에 `cost` · `tokens` · `task` · `steps`를 더했다. `ThreadHeaderBuilder`가 받는 provider는 둘이다. `getThreadCardLines(ownerId)`는 소유자의 줄을, `getThreadCardData(session)`는 세션의 합계와 작업 장부를 준다. src/index.ts가 `ownerThreadCardLines` · `threadCardDataOf`(`src/slack/thread-card-data.ts`)로 이 둘을 꽂는다. 줄이 없으면(`theme`) 예전처럼 `ui.threadheader`를 쓴다.
- 세션 테마(`/z theme`, 설정의 "스레드 헤더 테마")는 스레드 카드가 "서버 슬랙 테마"일 때만 헤더에 쓰인다. 그 밖에는 턴 종료 카드에만 쓰이고, `/z theme`의 답과 설정 설명이 그렇게 알린다. "따로 설정"으로 만든 카드는 "태스크 카드 따라감"이나 "서버 슬랙 테마"로 바꿔도 저장된 채 남아, 다시 "따로 설정"을 고르면 돌아온다. 미리보기와 "따로 설정"의 시작점은 편집기의 모드 스위치가 아니라 그 유저 대시보드의 모드(슬랙이 쓰는 것)를 따른다.
- 영향: 아무것도 고치지 않은 유저의 슬랙 헤더도 지시대로 태스크 카드(미니멀 1안)를 따라간다. 정보 줄은 소유자 · 현재 작업 · 비용 · 모델이고, 링크 줄은 대시보드 링크 · 링크 기록, 마지막이 종료 표시다. 예전 헤더로 돌아가려면 "서버 슬랙 테마"를 고른다.
