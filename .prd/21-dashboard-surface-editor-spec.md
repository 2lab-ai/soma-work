## 0. 미니맵

**결론:** 설정에 **대시보드 화면** 탭이 생겼다. 유저마다 태스크 카드(접힘과 펼침 따로), 디테일 카드, 슬랙 스레드 카드("스레드 태스크 카드")에 무엇을 어떤 순서로 보일지 미리보기를 보며 고친다. 1 · 2 · 3안은 고칠 수 있는 프리셋이다. 태스크 카드와 디테일 카드는 각각 기본 안을 고르고, "한 번에"로 둘을 같이 바꾼다. 스레드 카드는 기본으로 태스크 카드를 따라간다.

## 3. 모델 (`src/view-layout.ts`)

- 저장: `UserSettings.dashboardLayout`(유저마다). 고친 화면만 저장한다. 나머지는 기본 프리셋이라서, 나중에 기본 프리셋이 바뀌면 고치지 않은 화면은 그대로 따라온다.

```
DashboardLayoutDoc {
  v: 1
  presets?: { '1'|'2'|'3': { minimal?|advanced?: { card?, open?, detail? } } }   ← 고친 화면만
  active?:  { card?: '1'|'2'|'3', detail?: '1'|'2'|'3' }                         ← 화면마다 기본 안
  thread?:  { mode: 'follow' | 'theme' | 'custom', custom?: ThreadLayout }      ← 스레드 카드
}
```

- 기본 안을 정하는 순서: 화면마다 고른 안(`active`), 없으면 빠른 전환(`dashboardPlan`, `.prd/20`), 그것도 없으면 1안. 태스크 카드의 안이 접힌 면(`card`)과 펼친 카드(`open`)를 함께 정하고, 디테일 카드(`detail`)는 자기 안을 쓴다.
- 레이아웃은 모두 `{ id, on, opt? }`의 순서 있는 목록이다. 목록에는 카탈로그의 모든 항목이 한 번씩 들어 있다. 모르는 id는 버린다. 빠진 id(저장한 뒤에 카탈로그에 더해진 항목)는 기본 프리셋의 상태로, 기본 프리셋에서 바로 앞에 있던 항목 뒤에 들어간다. 그래서 새 항목은 프리셋이 뜻한 대로 나타나고, 저장된 항목의 순서와 켜짐은 그대로다(.prd/22 §5). "따로 설정"한 스레드 카드는 유저가 고른 것만 담으므로, 빠진 id를 끈 채로 끝에 붙인다.
- 펼친 카드 기본 프리셋에는 칸마다 다른 순서(`byCol`, 어드밴스드의 옛 본문)가 있다. 편집하면 그 순서는 없어지고, 모든 칸이 같은 순서를 쓴다(편집기가 그렇게 알린다).

항목 카탈로그(`LAYOUT_CATALOG` — 편집기의 이름과 설명):

| 화면 | 구역 | 항목 |
|---|---|---|
| 카드 (접힘) | 머리 | 제목(항상), 상태와 시간(항상), 종류 아이콘, 별, 소유자 |
| | 본문 줄 | 요약 줄(옵션: 물을 때만 · 항상), 현재 작업, 연결 — 이슈 · PR · 위키(.prd/22), 서브에이전트, 토큰 · 비용 줄, 산출물 줄(옵션: 1–4개) |
| | 맨 아래 오른쪽 | 진행 n/m, 컨텍스트 %, 지시 첨부 수, PR(기본 꺼짐 — 연결 줄이 PR을 보여 준다), 산출물 수, 비용, 토큰, 모델 |
| 카드 (펼침) | 항상 맨 위 | 액션 · 입력 필요(항상), ☆ 즐겨찾기 버튼 |
| | 그 아래 | 작업 창, 에이전트 트리, 최근 지시와 답변, 산출물, 목표 줄, 이슈 · PR 링크, 모델 · 추론 강도 |
| 디테일 카드 (§3.1) | 타이틀 바 | 제목 · 상태 · 시간(항상), 부제, 그 오른쪽 `head`: 모델, 비용, 토큰, 속도 tok/s, 컨텍스트 %, 소유자, 워크플로 |
| | 입력 필요 | 승인 · 질문 · 작업 계획(항상, 타이틀 바 바로 아래 — 탭에 넣지 않음) |
| | 탭 바 | `tabs`: 목표, 작업, 에이전트, 산출물, 세부 — 처음엔 모두 닫힘. 작업 탭 보기(실행 표 · 체크리스트 · 한 줄), 작업 탭 높이(⅓ · ½ · ⅔), 에이전트 머리 · 경로, 처음부터 펼침 |
| | 아래 | 채팅 · 입력창(항상), 대화 · 작업 로그 탭, 대화 · 작업 로그 · 에이전트 트리 탭, 모델 · 추론 강도 |
| 스레드 카드 | 머리 줄 | 제목(항상) |
| | 정보 줄 | 소유자, 워크플로, 모델, 컨텍스트, 비용, 토큰, 현재 작업, 진행 n/m |
| | 링크 · 상태 | 대시보드 링크, 링크 기록, 현재 링크, 종료 표시 |

- 카드 면의 줄 순서는 `@2lab.ai/ui`의 `card.rows`가 그린다(0.17.0부터, 연결 줄 `card.links`는 0.19.0부터). 맨 아래 칩은 전부 호스트 칩(진행 · 컨텍스트도)이라 순서를 자유롭게 바꿀 수 있다.
- 디테일 카드의 순서는 고정이다: 타이틀 바 → 입력 필요 → 탭 바와 열린 탭의 내용 → 대화 · 작업 로그. 고칠 수 있는 순서는 타이틀 바 항목(`head`)과 탭(`tabs`)의 순서다.

### 3.1 디테일 카드 세 구역 (SSOT 2026-11-03)

원문:

> 디테일 작업 카드 개선 — 최상단 타이틀 바 - 설정 지금 좋음. 여기에 실행중 시작 시간 표시 오른편에 모델이랑 사용 토큰, 사용 api 환산 비용도 출력 설정에서 on/off 할 수 있도록 추가 — 중단을 이렇게 해줘 여기에 디폴트로 탭바인데 내용물은 해당 탭을 클릭해야만 나오도록해주고 이 탭바에 뭘 출력할지를 설정하게 해줘. … 세션 정보는 타이틀 화면쪽 설정으로 해주고 이렇게 3개로 디테일 뷰 설정해줘
>
> 아 맞다 입력 필요도 별도임 — 타이틀 / 입력 필요 / 목표 | 작업 | 에이전트 | ... / 대화 | 작업 로그

```
┌ 타이틀 바   [BE] 패스키 간편 로그인
│             [실행 중] 🕐 시작 23:31 · 17분 | ● Opus 5.5 (1M) | $175 | 235.1M 토큰 | 98 tok/s   ☆ 되돌리기 중지
├ 입력 필요    승인 · 질문 · 작업 계획 — 있을 때만, 항상 여기
├ 탭 바       목표 2/5 · 작업 1/7 · 에이전트 5 · 산출물 3 · 세부      ← 누른 탭의 내용만 열림, 다시 누르면 닫힘
│             (목표 탭을 누르면) 목표 진행 중 · 펼치기 · 이어하기 0/1000 · 삭제 · 남은 것 · 다음 목표 …
└ 아래        대화 · 작업 로그 (+ 에이전트 트리) · 모델 · 추론 강도 · 입력창
```

- 타이틀 바(`detail.head`): 상태 바(`<ui-status-bar>`)의 시간 다음 슬롯에 그린다(`panelHeadMetricsOf` → `panelHeadNoteHtml`). 기본은 모든 안에서 모델 · 비용 · 토큰 · 속도. 어드밴스드는 예전 세션 정보 줄의 컨텍스트 · 소유자 · 워크플로도 켠다. 비용과 토큰은 작업 합계(메인 + 서브에이전트)다.
- 속도(tok/s)는 세션의 출력 토큰(`sessionOutputTokens` — `usage` + 실행 중인 턴) ÷ 세션의 활성 시간이다. 둘 다 `/new` · CONTINUE_SESSION(`resetSessionContext`)에서 함께 초기화되므로 같은 구간을 센다(작업 합계 토큰은 초기화되지 않아 분자로 쓰지 않는다). 활성 시간에는 지금 실행 중인 턴도 들어간다. 서브에이전트와 도구 실행 시간도 포함하므로 모델 한 번의 생성 속도가 아니라 작업의 속도다. 일한 시간이 1분이 안 되면 보이지 않는다. 열린 턴은 서버가 한 턴에 두는 상한(`MAX_LEG_MS`, 기본 30분)까지만 센다 — 세션의 활성 시간이 턴을 접을 때와 같은 기준이라, 끝을 놓친 턴이 속도를 0으로 끌어내리지 않는다. 서버는 API 시간을 따로 저장하지 않으므로 이 계산을 쓴다.
- 탭 바(`detail.tabs`): `.slide-panel[data-midtab]`가 열린 탭이고, CSS가 나머지 탭의 내용을 숨긴다. 카드를 열 때마다 모두 닫힌다. 랜딩이 있으면 그 탭이 열린다: 목표 → 목표, 작업 → 작업, 에이전트 → 에이전트, 펼친 카드의 "전체 N개 →" → 산출물. 목록 밖 작업(`tasksOutside`)만 있어도 실행 표에서는 작업 탭이 열린다. 빈 목표 탭은 목표 추가 편집기를 보인다. 같은 카드로 다시 랜딩하면 읽던 탭을 둔다. 내용이 없는 탭은 `disabled`(누를 수 없고 Tab 순서에서도 빠짐)이고, 목표는 추가할 수 있는 사람에게 열린다. 에이전트 탭의 `aria-controls`는 에이전트 스트립(`#panel-tabs`)이다. 기기에 남은 예전 레이아웃 사본도 서버와 같은 규칙으로 읽는다(`detailWithZones`). 숫자: 목표는 지금 목표의 순번 / 전체(지난 + 지금 + 대기), 작업은 완료 / 전체(보고 있는 에이전트의 목록), 에이전트는 서브에이전트 수, 산출물은 파일 + 지시 첨부 수.
- 에이전트 스트립은 에이전트 탭의 것이다. 서브에이전트를 보고 있으면(`data-agent-scoped`) 탭을 닫아도 스트립이 남아 메인으로 돌아갈 길을 보인다. 에이전트 탭이 꺼진 레이아웃은 메인 에이전트만 보인다. 작업 로그의 "열기"는 스트립에 탭이 있는 에이전트(세션의 서브에이전트)로만 옮긴다 — 로그에만 있는 에이전트는 돌아올 탭이 없다.
- 세션 정보 전체 기록(토큰 내역 · 세부 · 컨텍스트 · 링크)은 세부 탭이다. 기본은 어드밴스드에서 켜고 미니멀에서 끈다.
- 예전에 저장한 디테일 카드(`top` · `agents` · `tasks: 'none'`)는 그 안의 기본 타이틀 바와 탭 바를 받고 나머지 선택은 그대로 둔다. 숨긴 작업 목록(`tasks: 'none'`)만 작업 탭 꺼짐으로 옮긴다. 기본 안은 작업 목록을 숨긴 적이 없으므로 유저가 고른 것이다.

- 휴대폰(900px 미만)에서는 미리보기가 위, 항목이 아래로 온다.
- "따로 설정"은 지금 스레드 카드가 보여 주는 것(태스크 카드에서 옮긴 것)에서 시작한다. "서버 슬랙 테마"는 `config.json`의 `ui.threadheader`와 테마 명령을 그대로 쓴다.
- 저장: 바꿀 때마다 문서 전체를 `PUT /api/settings/dashboard-layout`(350ms 디바운스, 한 번에 하나, 도중에 바뀌면 끝난 뒤 다시). 편집마다 번호(`_layRev`)를 올리고, 응답은 그 PUT 뒤에 편집이 없을 때만 받아 쓴다. 저장되지 않은 편집은 탭을 다시 열어도 서버 사본으로 덮지 않는다. 서버가 검사한 문서를 다시 받아 쓰고, 대시보드의 기기 사본 `soma-view-layout`도 같이 고친다. 대시보드는 로드할 때, 탭으로 돌아올 때, bfcache에서 돌아올 때 다시 읽는다.

## 5. 스레드 태스크 카드 — 판단

**판단: 표준 하나로 묶는다.** 스레드 카드는 태스크 카드와 같은 항목 이름을 쓰고, 기본값은 "태스크 카드 따라감"이다. 슬랙에서만 의미 있는 항목(대시보드 링크 · 링크 기록 · 워크플로 · 종료 표시)은 스레드 카드에만 있다. 따로 두고 싶은 유저는 "따로 설정"을 고른다. 이유: 둘을 따로 두면 같은 항목(모델, 비용, 현재 작업)을 두 번 고쳐야 한다. 그렇다고 하나로만 묶으면 슬랙의 링크 줄을 설정할 길이 없다.

변환(태스크 카드 → 스레드 카드, `followThreadLayout`. 클라이언트 미리보기와 서버가 같은 결과를 내는지 테스트로 고정):

| 태스크 카드 | 스레드 카드 |
|---|---|
| 제목 | 머리 줄 |
| 소유자 (머리) | 정보 줄: 소유자(@멘션) |
| 현재 작업 (본문 줄) | 정보 줄: `▶ 작업` |
| 토큰 · 비용 줄 | 정보 줄: 토큰, 비용 |
| 진행 n/m · 컨텍스트 % · 비용 · 토큰 · 모델 (칩) | 정보 줄: 같은 항목, 칩 순서대로 |
| 연결 (본문 줄) 또는 PR (칩) | 링크 줄: 링크 기록 |
| 요약 줄 · 서브에이전트 · 산출물 · 지시 첨부 · 별 · 종류 | 슬랙에는 없음(편집기에 "슬랙 X") |
| (항상) | 링크 줄: 대시보드 링크 · 상태 줄: 종료 표시 |

- 슬랙 쪽(`@soma/slack`): 스레드 헤더 필드에 `cost` · `tokens` · `task` · `steps`를 더했다. `ThreadHeaderBuilder`가 받는 provider는 둘이다. `getThreadCardLines(ownerId)`는 소유자의 줄을, `getThreadCardData(session)`는 세션의 합계와 작업 장부를 준다. src/index.ts가 `ownerThreadCardLines` · `threadCardDataOf`(`src/slack/thread-card-data.ts`)로 이 둘을 꽂는다. 줄이 없으면(`theme`) 예전처럼 `ui.threadheader`를 쓴다.
- 세션 테마(`/z theme`, 설정의 "스레드 헤더 테마")는 스레드 카드가 "서버 슬랙 테마"일 때만 헤더에 쓰인다. 그 밖에는 턴 종료 카드에만 쓰이고, `/z theme`의 답과 설정 설명이 그렇게 알린다. "따로 설정"으로 만든 카드는 "태스크 카드 따라감"이나 "서버 슬랙 테마"로 바꿔도 저장된 채 남아, 다시 "따로 설정"을 고르면 돌아온다. 미리보기와 "따로 설정"의 시작점은 편집기의 모드 스위치가 아니라 그 유저 대시보드의 모드(슬랙이 쓰는 것)를 따른다.
- 영향: 아무것도 고치지 않은 유저의 슬랙 헤더도 지시대로 태스크 카드(미니멀 1안)를 따라간다. 정보 줄은 소유자 · 현재 작업 · 비용 · 모델이고, 링크 줄은 대시보드 링크 · 링크 기록, 마지막이 종료 표시다. 예전 헤더로 돌아가려면 "서버 슬랙 테마"를 고른다.
