## 용어 고정

- **포지키(forge key)** = 다른 토큰을 찍어내는 권한 하나만 가진 Cloudflare API 토큰. 그 자체로는 존(zone)·DNS를 건드릴 수 없다.
  운영 원장에서 2026-07-07부터 이 이름으로 쓰고 있다(그때는 유저 소유 `API Tokens Edit`). 이 기능의 기본형은 계정 소유
  `Account API Tokens Edit` 토큰이다 — 경계가 사람이 아니라 그 환경의 계정이 되도록(16 §6).
- **단기 키(lease token)** = 포지키로 찍어낸 Cloudflare 토큰. 만료 72시간 미만, 환경 하나의 계정·존과 승인된 권한만 갖는다.
- **어드민** = devops-tools에서는 브로커 정책 파일의 `admins`(설치 때 soma-work `ADMIN_USERS`로 채움). server-tools grant 승인은 기존대로 `ADMIN_USERS`.

## 확정 스코프

1. 현재 설정 실측과 환경별 시각화 — 4개 배포의 MCP·server-tools·gh·Cloudflare 상태 (14 §1).
2. `config.json`에 `server-tools`와 같은 모양의 `devops-tools` 섹션을 추가하고, 그 섹션이 있는 배포에서만 devops-tools MCP를 켠다.
3. gh: 환경 축이 아니라 **계정 축**. 계정별로 모델이 원하는 gh 작업을 하게 하되, 읽기도 유저별 grant(서버툴과 같음),
   쓰기는 어드민 grant, org-admin 계정의 조직·레포 권한 작업(유저 추가·삭제, 레포 읽기/쓰기 권한 부여)은 **건마다** 어드민 최종 확인.
4. Cloudflare: **환경 축**(dev2 · stage0 · stage2). 환경마다 포지키 1개. 포지키를 쓰는 모든 일은 어드민 허락 → 72시간 미만
   단기 키 발급 → 그 키로만 작업.
5. 목적 = 모델이 키를 직접 관리하지 않는 것. 키는 모델의 문맥·출력·로그·Slack에 나타나지 않고, 모델이 도구로 읽을 수 있는
   곳에도 두지 않는다.
6. 첫 적용 배포 = `work-m64` dev 봇 (유저 원문의 계정 2개가 거기에 있다).
7. 계획은 Slack DM으로 유저 확인을 받은 뒤 구현한다.
