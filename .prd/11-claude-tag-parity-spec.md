## 1. 문제

- Claude Tag는 채널에 사는 팀메이트다. 멘션하지 않아도 대화를 읽고 끼어들고, 채널 단위로 기억하고, 스스로 후속 작업을 예약하고, 관리자가 채널별 권한·지출을 통제한다 [DOC][ANN].
- soma-work는 멘션받았을 때 일하는 개인 비서에 가깝다. 세션은 스레드 단위, 메모리는 유저 단위, 권한은 유저 단위다. 채널 단위 기억·통제·능동성이 없다 [CODE].
- 그 차이를 기능 단위로 나눠 둔 목록이 없어서, 무엇을 먼저 만들지 고를 수 없다.

## 2. 목표와 비목표

- 유저가 고른 피처마다 GitHub 이슈를 하나씩 만든다.

비목표:
- Claude Tag 소스·브랜드 복제. 목표는 사용자 결과(UX) 재현이다.
- Anthropic 호스팅·요금제 고유 기능 18개 (요금, 좌석, Enterprise Grid, HIPAA, egress IP 대역, legacy 이전 등). 근거 표에 `해당없음`으로 남긴다.

경계: Claude Tag를 직접 조작한 세션은 없다. 판정은 문서·발표·changelog 서술에 근거한다. 이모지 종류·카드 모양 같은 화면 세부는 "미조작 — 추정"이다.

### B. 채널 팀메이트

#### F-03 앰비언트 참여와 채널별 자동 응답 설정 (P1, L)
- 지금: 멘션 없는 top-level 채널 메시지를 처리하는 핸들러가 없다. `message` 핸들러는 파일 공유와 기존 세션 스레드 답글만 받는다 (`packages/slack/src/event-router.ts:812-821`). `ambient` `proactive` 검색 0건 [CODE].
- 목표 (CT-07, CT-08):
  - 채널마다 "자동 응답" 설정을 둔다. 켜진 채널에서는 모든 top-level 메시지와 스레드 답글을 읽고 네 가지 중 하나를 고른다: 아무것도 안 함(기본) · 이미 아는 답이면 짧은 스레드 답 · 채널이 지정한 작업 종류면 세션 시작 · 진행 중 세션과 관련되면 그 세션에 조용히 전달.
  - 다른 봇·워크플로 메시지는 문맥으로만 읽고, 봇 멘션이 있을 때만 답한다 (CT-10).
  - 사람들이 무응답 답글을 무시하면 기록하고 덜 끼어든다. 10일 동안 멘션·게시가 없으면 그 채널 읽기를 멈춘다 (CT-11).
- 진입점: `event-router.ts`의 `message.channels` 처리 분기 + 채널 설정 저장소 (§5 이음매 1).
- 인수:
  - 자동 응답 off 채널: 멘션 없는 질문 → 반응·답 0건.
  - 자동 응답 on 채널: 봇이 이미 아는 사실을 묻는 메시지 → 스레드 답 1건. 잡담 → 0건.
  - 진행 중 세션 주제와 같은 top-level 메시지 → 새 세션 0건, 해당 세션 다음 턴 입력에 포함.
  - 다른 봇의 알림 메시지 → 답 0건. 그 알림에 사람이 "@봇 triage" 답글 → 세션 시작.
- 비목표: 비용 0 읽기 같은 과금 정책 (CT-99, 해당없음).
