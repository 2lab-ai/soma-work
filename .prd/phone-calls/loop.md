## 실측 (2026-11-18, 첫 실통화 — dev, 070 회선 → 소유자 휴대폰)

- 발신 1통, 46 s, `completed`. 첫마디는 신호 중에 만들어 두고 받자마자 시작(받은 뒤 1.2 s). 소유자가 끼어들자 말하기를
  멈춤(통화 보기에 "끊김"). 목적(들리는지·속도) 확인 → 피드백을 한 문장으로 되짚고 인사 → 에이전트가 `hang_up`.
- 소유자 평: "잘 들려", "약간 느리구나".
- 말 끝 → 첫 소리 3.3–4.5 s. 몫: 대화 모델 첫 토큰 1.1–1.6 s · 말 끝 판정 0.7 s · TTS 첫 소리 0.6–1.1 s · STT 0.4–1.1 s.
  받아쓰기는 짧은 말까지 정확(G4 재현 없음).
- 대화 모델을 바꿔도 줄지 않는다(llmux 경유, 같은 대본 3턴): sonnet 첫 토큰 0.87–1.4 s, haiku 1.4–3.2 s(더 느림),
  sonnet 1M 변형은 sonnet과 같음. 남은 수단: 말 끝 판정 0.7 → 0.5 s(말 중간 쉼에서 끊길 위험), 말이 끝나자마자 미리
  만든 짧은 맞장구 재생 — 소유자 결정 대기.
- 수신 1통(소유자 → 070), 78 s, `completed`. SDK가 받아 미리 만든 인사를 바로 재생. 소유자 요구(통화 중):
  "말하는 속도 한 1.5배는 해야", "말을 하고 응답하는 속도가 너무 느려". 드러난 결함:
  - 생각 중간에 쉬면 쉼마다 따로 턴이 되어 답이 쌓였다(약 20 s를 연달아 말함) → 새 말이 옛 답을 대신(W8).
  - "1.5배"의 소수점을 문장 끝으로 보고 "1." / "5배"로 끊어 말함 → 숫자 사이 점은 끝이 아님(W8).
  - 첫 몇 초의 짧은 말이 엉뚱하게 받아써짐("쭈우디아") → 에이전트가 되물음(G4).
- 대시보드(dev, 소유자 계정): 요청한 대화의 답 아래 통화 카드(제목 · 번호 · 0:46 · 통화 끝 · 마지막 말 · 요약) → 클릭하면
  통화 탭(상대/에이전트 말풍선, 끼어든 곳 표시) · 작업 탭(24건: 통화 지시 · 받아쓰기 · 모델 응답 · 음성 합성 · 끼어듦 ·
  `hang_up`). 머리줄: 건 전화 · 0:46 · 대화 모델 · 음성.

## 실측 (2026-11-18, PR #1344 최종 코드 — 서비스 하네스)

- 발신·수신 모두 정상 종료(목적 달성 → 인사 → 에이전트가 `hang_up`). 수신 기록·소유자 알림의 연락처·용건 정확.
- 말 끝 → 첫 소리: 발신 4.58 s · 수신 **8.64 s**. 수신 턴 내역: STT 끝 +2.5 s → 첫 문장 +5.1 s — 대화 모델 첫 토큰이 5 s로
  튐(TTS·예열 문제 아님). 직전 실측(4.13 / 3.54 s)과 같은 코드 경로라 llmux 쪽 편차로 본다.
- 발신 첫마디 "여보세요?"가 "要不可以哦?"로 받아써짐(G4) → 에이전트가 되묻고 이어감.
- 음성 서비스 모델: `drama-3`(기본, 스트리밍) · `s2-pro`(스트리밍 불가). 엔진은 한 번에 하나만 합성하므로 예열은 호스트당
  하나, 진짜 합성·받아쓰기가 시작되면 취소된다.

## 실측 (2026-11-18, 첫 소리 앞당기기 — 음성 호스트 스트리밍 API)

- TTS 스트리밍 첫 바이트(중앙값, 같은 문장 5개): cwon 20 s 참조 1648 ms · 9.3 s 참조 921 ms · **5.9 s 참조 700 ms**.
  합성은 여전히 실시간보다 빠름(3.9 s 음성을 3.0 s에).
- 엔진 유휴 페널티: 연달아 0.6 s, 10 s 쉰 뒤 1.4 s, 3 s 전에 한 글자 예열 0.6–0.8 s.
- 하네스 말 끝 → 첫 소리: 4.13 s / 3.54 s. 내역(발신 턴): 말 끝 판정 0.7 · STT 0.96 · 첫 토큰 1.22 · TTS 0.78.

## 실측 (2026-11-18, 서비스 하네스 — 실제 `2lab-ai-dev` 설정 + 음성 서비스 + llmux, 전화망만 가짜)

- PhoneService를 그대로 돌려 발신 1통 · 수신 1통. 수신 인사는 받는 즉시 나가고, 발신 첫 마디는 신호 중에 만들어 둔다.
  둘 다 상대가 "감사합니다 / 수고하세요"로 끝내자 에이전트가 인사하고 직접 `hang_up`.
- 찾은 결함(고침): 조용한 회선 재촉 타이머가 에이전트가 아직 말하는 중에 터져 같은 확인을 두 번 물었다. 새 턴이 시작되면
  타이머를 끄고, 말하는 중에는 재촉하지 않는다. 상대가 이미 확인 · 마무리했으면 다시 묻지 않는다는 통화 규칙 추가.
- 음성 서비스가 내려가 있던 원인: 음성 호스트의 WSL을 붙잡는 예약 작업이 기본 실행 한도(72시간)에 걸려 종료 → 한도 해제.
- 첫 토큰 0.55–1.25 s, TTS 첫 바이트 1.3–2.3 s (G1 그대로).

## 실측 (2026-11-17, 전화망 제외 하네스 — 실제 음성 서비스 + llmux)

- 3턴 가짜 통화: 첫 인사 → 상대 "여보세요?"(대화 모델로 보내지 않음) → 받아쓰기 정확(문장부호까지) → 확인 질문 → 끼어들기 2회 정지 → 작별 인사 후 `hang_up`.
- 말 끝 → 첫 응답 소리 5.24 s. 내역: VAD 0.7 · STT 0.95 · 첫 토큰 0.73 · 첫 문장 완성 ~0.3 · TTS 첫 바이트 2.2 (G1).
- 대화 모델 첫 턴 첫 토큰 1.6–3.5 s(CLI 기동 포함), 이후 0.59–0.73 s (claude-sonnet-5-5, llmux).
