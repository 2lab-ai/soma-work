## 용어 고정

- **비밀** = 봇 비밀 저장소(`secrets/`)의 파일 하나. 이름(파일 이름)과 값(파일 내용). 설정은 `{"$secret": "<이름>"}`로 이름만 가리킨다.
- **비밀 사용** = 샌드박스 밖의 봇 쪽 코드(server-tools MCP, 전화 데몬)가 모델의 도구 호출을 처리하면서 그 비밀의 값을 쓰는 것.
  모델은 값을 받지 않는다. 이 워크스트림에서 "모델이 키를 요청한다"는 이 뜻이다.
- **비밀 grant** = (유저, 비밀) 한 쌍의 허락. 범위는 "이번 한 번"(그 요청 하나) 또는 "항상".
- **도구 권한** = server-tools 도구 하나를 누가 부를 수 있는가. 도구 × 환경(서버) 칸마다 정한다.
- **어드민** = `ADMIN_USERS`의 사람. **환경 유저** = `env:<이름>` 사용자(env-access, 샌드박스 없는 어드민).

## 확정 결정 (이 문서에서 고정 — 바꾸려면 새 SSOT 항목)

- **D1 — 값은 어떤 화면에도 다시 나오지 않는다.** 대시보드는 이름 · 만든/바꾼 시각 · 쓰는 곳 · 허락된 유저만 보인다. 값은 넣을 때 한 번 받고,
  바꾸려면 새 값으로 덮어쓴다(GitHub secrets와 같은 모델). 근거: SSOT_2 "새로 볼수는 없고 깃허브 시크릿처럼".
- **D2 — 모델은 여전히 값을 받지 않는다.** 승인은 "그 유저의 모델이 부른 도구가 이 비밀을 써도 된다"는 허락이다. env-access 불변식
  (비밀은 봇만 읽는다, 어떤 모델도 어떤 방법으로도 읽지 못한다)은 그대로다. 근거: env-access SSOT D5 · [`../24-env-access-to-be.md`](../24-env-access-to-be.md) §5.
- **D3 — 승인 카드는 어드민에게 간다.** 비밀의 주인은 어드민이고, 대시보드의 권한 편집도 어드민만 한다(SSOT_2 "어드민일 경우").
  카드 버튼은 SSOT_1의 세 가지: 수락(이번 한 번) · 거부 · 앞으로 계속 자동 수락(이 유저에게 이 비밀 항상).
- **D4 — 어드민과 환경 유저는 묻지 않는다.** 둘 다 이미 모든 비밀을 쓰는 주체다(env-access D6).

## 확정 스코프

1. 비밀 grant 저장소: 유저 × 비밀, "항상" 기록. 모델은 쓰지 못한다(샌드박스 denyWrite + 정책 1b).
2. 비밀 사용 시점의 승인: 비어드민 유저의 도구 호출이 grant 없는 비밀을 쓰려 하면 어드민에게 3버튼 카드(Slack DM + 대시보드 관리자 승인).
3. 대시보드 설정 `비밀` 탭(어드민만): 이름 목록, 추가(이름 + 값), 값 덮어쓰기, 삭제, 비밀마다 허락된 유저 보기 · 더하기 · 빼기.
4. 대시보드 설정 `서버 도구` 탭(어드민만): server-tools 도구 전체 목록, 환경(서버) 전체 목록, 도구별 권한 수준, 환경별 허락된 유저, 비밀별 쓰는 곳.

## 비스코프 (근거)

- 비밀 값을 대시보드나 Slack에 다시 보여 주기 — D1.
- 모델이 임의의 명령 · URL에 비밀을 넣어 쓰는 범용 도구 — 모델이 고른 목적지로 값이 나갈 수 있다. 필요해지면 새 이슈(비밀마다 허용 호스트를 묶는 설계부터).
- 유저가 자기 개인 비밀을 넣는 저장소 — SSOT_2는 어드민 관리자만 말한다. 필요해지면 새 SSOT.
- prod 적용 — 첫 적용은 dev 봇. prod는 같은 코드가 배포될 때.
