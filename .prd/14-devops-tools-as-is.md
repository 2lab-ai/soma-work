## 한 줄

환경 접속 도구의 유저별 허락은 설정해야 켜지고, 봇 컴퓨터 계정에 사람 gh 계정이 로그인돼 있으면 그 키가 모델 손이 닿는 곳에 있으며,
Cloudflare 키는 봇 밖에 흩어져 있고, 봇 안의 허락 기록은 모델이 흉내 낼 수 있다.

## 1. 봇과 환경

soma-work 봇은 여러 곳에 배포되고, 배포마다 볼 수 있는 환경(dev2 · stage2 · test2 · stage0 중 일부)이 다르다.
환경을 보는 도구는 server-tools 하나다. 환경마다 DB 조회와 서비스 로그 읽기를 한다. 쓰기는 없다.

## 2. 누가 그 도구를 쓸 수 있나

유저별로 허락을 받게 하는 장치는 코드에 있지만, 배포 설정에 허락 표를 넣어야 켜진다. 표가 없는 배포에서는 채널에 있는 누구나 쓸 수 있다.

## 3. gh

- 봇이 PR을 만들고 고칠 때 쓰는 신원은 봇 전용 GitHub 앱이다. 사람 계정을 쓰지 않는다.
- 그런데 봇 컴퓨터 계정에 사람 gh 계정이 로그인돼 있는 경우가 있다. 그러면 같은 컴퓨터 계정으로 도는 모델이 그 계정 키를 꺼낼 수 있는 구조다
  (실제로 꺼내 보지는 않았다).
- 계정을 골라 쓰는 도구도, 계정별 허락도 없다.
- 조직 유저 추가·삭제에는 조직 멤버 관리 권한이 있는 키가 필요하다.

## 4. Cloudflare

- 봇에는 Cloudflare 도구도 키도 없다.
- 환경마다 Cloudflare 계정이 따로 있고, 키는 봇 밖 여러 곳에 흩어져 있다.
- 짧게 쓰고 버리는 키를 만드는 체계는 없다.

## 5. 어드민 허락

허락 버튼은 있다(server-tools 사용 허락용). 그러나 버튼을 누른 결과가 모델도 쓸 수 있는 곳을 거쳐 전달된다.
그래서 모델이 허락을 흉내 낼 수 있는 구조다(실제로 흉내 내 보지는 않았다).

## 요청과의 거리

| 요청한 것 (TO-BE) | 지금 (AS-IS) |
|---|---|
| 모델이 키를 직접 관리하지 않는다 | 사람 gh 계정 키가 모델 손 닿는 곳에 있을 수 있다 |
| 계정별로 원하는 gh 작업 | 계정을 고르는 도구가 없다 |
| 유저별 허락, 쓰기는 어드민 허락 | 유저별 허락은 설정해야 켜진다, 허락은 흉내 낼 수 있다 |
| org-admin 계정으로 유저·레포 권한 관리 | 조직 멤버 관리 권한이 있는 키가 필요하다 |
| 환경별 포지키 → 매번 허락 → 3일 미만 키 | 봇에 Cloudflare가 없고, 짧은 키 체계가 없다 |
